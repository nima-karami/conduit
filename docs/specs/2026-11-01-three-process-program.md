# Three-process program: Conduit app · Conduit server · hc runtime

This implements ADR 0007. The design is in `2026-11-01-three-process-architecture.md` and the
contracts in `src/contracts/`. This doc covers the **workstreams, their path ownership, their order,
and which harness builds each**. Every workstream gets a short spec or plan when it starts. The
integration branch is `feat/three-process`; nothing merges to `main` before the gate (D6), except
W0b, the topology-neutral host refactor that the branch rebases onto.

## Workstreams

Each path has exactly one owner. Shared entry files (`electron/main.ts`, `package.json`, `esbuild.mjs`)
belong to a single serial lane or to the lead.

**Lane rule for phase 3: import, don't fork.**
- Server lanes **import** the unchanged modules from `server/**`: `src/conduit-mcp/*`,
  `src/session-manager.ts`, `src/session-activity.ts`, `src/scrollback-*`, `src/pty-writer.ts`,
  `src/add-dir-delivery.ts`, and the like. After W0b that includes the MCP host itself
  (`src/conduit-mcp/host.ts`, with the split tool gate) and the topology-neutral install module
  moved out of `electron/mcp-install.ts`, which W5 **imports** over C7 ports. Lanes copy only
  `main.ts` glue. Where hc already provides something, lanes use it rather than rebuild it (D33,
  the architecture's reuse audit).
- Lanes never edit those shared `src/*` modules. A needed change is a contract request to the lead.
- **Every lane that copies code also ports the existing unit tests covering it.** That is a
  deliverable, checked in review.
- W7 still owns every edit to existing `electron/*` and shared files, incl. the argv changes in
  `src/mcp-launch.ts` and `src/conduit-mcp/install-entries.ts`, and every deletion, so every lane's
  SHA stays green on its own.

alongside phase 2, ships in today's topology like any refactor (the host moved to

## Invariants every lane keeps

- The server is each live session's only active viewer and only PTY writer, through one PtyWriter
  (D19). The app observes; it never types or resizes, and PTY size = xterm size because the server
  applies the size the app requests.
- Each typing intent keeps its v0.51 policy: notices gate at the queue slot, timed messages submit
  bare, add-dir keeps its own gate. hc `terminal.send` is never used. The MCP host never writes raw
  input; every byte goes through `TypingPort`.
- The hc flags are always `no_parent`, `no_notify` and `keep:false`. The server's env and specs carry
  no `HC_*`; session specs carry the user's XDG values, never ours. The app's own hc calls strip
  `HC_*`, pass `HC_SESSION=conduit-<h>` and use `hc run --no-parent`.
- The MCP token is the only identity. Agents can never set a token or a role brief. Only token
  hashes are stored. Adopt trusts the recorded address + launch id, never a label, and an unreadable
  token store adopts and kills nothing. W5 alone writes `tokens.json`, through `TokenStorePort`.
- Spawn recovery never decides from absence or a clock (D21): only a core connection lost before
  the reply leaves the launch `unconfirmed`, never retried and never revoked on a negative lookup;
  late registrations are adopted from hc events. Every outcome is recorded as soon as hc reports it; nothing relies on hc keeping a
  record. Only W4 allocates `generation` and `launchId`; only W5 reserves tokens.
- While the server is stopping, nothing starts (D32). Idle exit and `hc server stop` wait while any
  token row is `reserved` or `unconfirmed`.
- Every PTY-output and folder-state concern has exactly one subscriber (architecture §Internal
  subscribers). The supervisor is identified by its unique name, never by a label.
- Nothing long-lived runs from the install dir. Every long-lived process runs with its cwd in its
  runtime dir.
- Git is spawned only via `runGitBin`; directories are watched only via `watchDir`.
- No e2e fan-out: one local e2e at a time, everything else remote.
- Never stop or restart the user's own hc session, and never `hc server stop` ours while any
  non-Conduit terminal is live. Kill only hc terminals, by address, hc name or the `conduit.role=session`
  label (the supervisor only by its unique name): never a process by pid or by process name. Only the supervisor restarts the server; the app never kills a server or supervisor
  without an explicit user action. Tests use their own userData, and through it their own server and
  hc session.

## Decided

Decided 2026-11-01: hc is **bundled, pinned exact**. Conduit uses its **own `HC_SESSION`**.
Electron stays. Process: the lead writes the contracts and architecture, they go through repeated
architecture-critic rounds, and the user approves them with the trade-offs laid out. After that the
build runs unattended across harnesses (skill `multi-agent-build-loop`).

Upstream requests to file with herdr-core (lead, during phase 2): a per-terminal opt-out of env
injection or a configurable injected session (D16; M25 first checks whether config already allows
it), an explicit end-of-paint marker (D20), and keeping the `spawn_pending` claim under
`keep:false` (D21).

Decided in revision 9.1: windowless `close_session` through `DomainPort.closeSession`; the MCP open outcome's launch failures; repo state in the app (D39); `restoreSessions: false` only stops reopening (D40); `--stop-all`'s two bounds; persisted formats over their existing version fields.

Decided in revision 9: cwd and typed-CLI detection from hc `foreground` (D38, gated on M27); hc
`doc.*` and `turn` unused, with reasons (§Reuse audit); C2's same-user exposure is an accepted
residual with `hello.auth` reserved (D16, M28); no confirm timeout on spawns; persisted files are
the fourth cross-version edge (D12).

Decided in revision 8: reuse hc first (D33); the MCP host runs in-process in the server (D35);
agents reach Conduit through MCP, not a CLI (D36); the server is TypeScript on bundled Node (D37).

Deferred to a follow-up program: the agent-lifecycle MCP tools (`spawn_agent`, `wait_for`, child
notes, cascade close), built on hc's parent links, `wait` and notes (D33); remote machines, over
hc's SSH machines and `--via` transports; conversation resume after a reboot. The single-app and
local assumptions to reverse first are listed in the architecture.
