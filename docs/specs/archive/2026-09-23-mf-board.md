# Feature Spec: mf-board — board card ↔ sessions (12f)

**Tier:** FULL   **Feature type:** UI (board card + pure derivations + one optional board-model field;
no new host message)
Autonomous mode. Builds on the locked contract (`.autoloop/locked.md` L1 `home`/`roots`/`projectId`,
L2 dangling project ids, L3 `openRepo {roots, projectId}`, L7 `.conduit/` resolves against
`session.home`) and on mf-new-session (the dialog and its prefill). **Hard dependency order:**
mf-model (the `projectPath`→`home` rename including `BoardView`'s prop and `mgr.create`, plus host
stamping of `roots`/`projectId` on `openRepo`) and mf-new-session land first. Design:
`.autoloop/handoff/README.md` §12f, `screenshots/12f-board-card.png`, Flows file `#12f`.

## 1. Problem frame

Today a board card shows its linked sessions only as one aggregate badge (`Running · 2` / `Exited`)
that jumps to a single session. "Start session for this card" prefills only the active session's
path. With multi-folder sessions, the card is where the ticket ↔ work link lives. From a card, the
user wants to:

- see **every** session working on it,
- jump to any one of them,
- start another with the same folders and project, without picking them again.

**Success:**

- A card lists its linked sessions: dot, name and agent.
- Clicking a row activates that session.
- `+ Start session` opens New session already carrying the project, the folders and the card link.
- When a session closes, it leaves the list and the card stays.
- The sidebar session card shows no ticket.

**Non-goals:**

- Tracker sync (Jira, Linear) of any kind.
- A project-level board folder (the handoff's open question).
- Showing other windows' sessions.
- Persisting a card's folders anywhere.
- Changing stages, proposals, specs, pipeline or WIP.
- The project-header ticket pill (mf-sidebar D8 already defers it).

## 3. Behaviour

### 3.1 Card anatomy, in DOM order

1. **Header row.** It holds three parts, and each renders only when its field is present. The row is
   omitted when there is no `ticket` (true of every card today).
   - `ticket.key` in mono, never truncated below 40 characters (see §3.5).
   - `ticket.source` as a neutral tag.
   - `ticket.status` as an accent-tint pill, flush right; the header row wraps, so a long status
     drops onto its own line rather than ellipsising (revised per conductor, fix1).

   Each part carries `dir="auto"`. A truncated part gets `title` set to its full value.
2. Title row — the title with the hover actions (`bcard__acts`) beside it, reserving their space
   (revised per conductor, fix1) — then notes, meta and the "Agent proposed" flag, unchanged.
3. **Linked sessions list.** It shows only when at least one session is linked, with a hairline divider
   above. Each row has:
   - a status dot;
   - the session name, ellipsised, with `title` set to the full name;
   - the agent label in mono, right-aligned and muted, at most 40% of the width, ellipsised, with
     `title`.
4. **`+ Start session`.** A pill button with an accent tint. It shows on real cards; ghost
   (proposed-addition) cards don't have it.

The old `.bcard__badge` is **removed** (D4). Ghost cards render the header, read-only, but no list and
no button.

### 3.2 Linked sessions (pure)

`linkedSessionsForCard(sessions, cardId, boardHome)` returns the sessions where both of these hold:

- `s.cardId === cardId`;
- `boardHome` equals `s.home` **or** one of `s.roots`, both compared through the existing
  `normalizeRoot`. It folds slashes and drive-letter case and is platform-independent. **Never branch
  on `process.platform`.**

Order is the input order, which is the host list order (D10). There is no dedupe: L1 guarantees that
`home` is never in `roots`.

`linkedRowState(s)`:

| `status` | State | Dot | Name |
|---|---|---|---|
| `running` | `'running'` | filled `--accent` | normal text |
| `exited` or `stale` | `'stopped'` | hollow (1.4px ring) | muted, as in the screenshot |

Busy and needs-you are not shown on the card; the sidebar owns those.

**Agent label:** the same agent label mf-sidebar's card shows on its second line (the registry
agent's label, e.g. `claude`, `shell`). It falls back to `s.agentId` when the agent is no longer
registered (D11).

### 3.3 `+ Start session`

It opens New session (mf-new-session) with this prefill:

```ts
interface NewSessionPrefill {   // what this item needs from mf-new-session (D8)
  projectId: string | null;     // null = the chip is removed (standalone)
  home: string;
  roots: string[];
  cardId: string;
  cardTitle: string;            // dialog subtitle: Start a session for "<title>"
  agentId?: string;
}
```

**"Last session"** is the linked session (§3.2, any status) with the greatest `lastActiveAt`. A tie
goes to the first in order. The fields come from it, or from a fallback:

| Field | Last session exists | No linked session |
|---|---|---|
| `home` / `roots` | its `home` / `roots` | active session's `home` / `roots` (`home === boardHome`, since the board is the active session's) |
| `projectId` | its `projectId`, mapped to `null` when absent or not in `state.projects` | the same rule applied to the active session |
| `agentId` | its `agentId`, only when that agent is still registered; otherwise omitted | omitted (dialog default) |

Missing roots are passed through. The dialog shows and handles them its own way (mf-new-session). The
user may edit anything. On submit the dialog posts
`openRepo {path: home, agentId, roots, projectId, cardId}` (L3).

**Two consequences, both accepted:**

- **The new session may not link back.** If the user makes home a folder that is neither `boardHome`
  nor one of `roots`, the new session is not listed on this card (D3).
- **The board may switch.** With `autoSwitchSession` on, the new session becomes active and the board
  now shows *its* home's board, which is the same board unless home was changed (D9).

The card's context-menu item "Start session for this card" stays and runs the same action. Both are
disabled when there is no board home. Focus returns to the `+ Start session` button when the dialog
is cancelled.

### 3.4 Activating and closing

**Activating:** a click, Enter or Space on a row calls the existing `onActivateSession(id)`. It
activates the session, switches the centre view to the editor and closes the board. Focus then goes
wherever today's session activation puts it; this item doesn't change that.

**Closing:** closing a session by any path removes it from `state.sessions`, and the row disappears on
the next broadcast. The card and `board.json` are never modified.

**Cross-window move:** the row leaves the source window's card. It appears on the target window's card
if that window shows a board that matches.

**Deleting a card:** the sessions keep a dangling `cardId`, as today.

### 3.5 Ticket fields (D1)

`BoardCard` gains `ticket?: { key?: string; source?: string; status?: string }`. **Nothing in the app
writes it.** There is no sync. The field exists so that an external writer (a future sync, a script,
or an agent via the proposal file) can fill it in, and the app round-trips it instead of stripping it.

**Parse** (`restoreBoard`, and therefore `readBoardArtifact`):

- Each sub-field is kept when it is a string that is non-empty after trimming. It is stored trimmed.
- Values are capped by code points (`Array.from`), never by UTF-16 units: key 40, source 24,
  status 32. A longer value is truncated, not dropped: it is cut to one under its cap, trimmed at the
  end, and ends in "…", so it stays within the cap and reloads unchanged.
- A `ticket` with no valid sub-field is omitted.

**Other rules:**

- `duplicateCard` does not copy `ticket`: a duplicate is not the same ticket.
- `diffBoard(...).edited[].fields` reports `ticket` when any sub-field differs. The `CardEdit.fields`
  doc comment gets updated to match.
- The inline editors don't touch it. It is read-only in v1, and display is verbatim.
- An external write to `board.json` follows today's rule (the watcher reload wins; `cancelBoardSave`).
- An older Conduit that rewrites the file strips `ticket` (D12).

### 3.6 Sidebar and preview shell

- The sidebar is unchanged: a session card shows no ticket, key or card title.
- The browser fake shell (`webview/bridge.ts` mock `openRepo`, `webview/mock.ts` seed `cardId`) gets
  `home`/`roots` so the preview shows linked rows.
- `board__sub`'s "overnight agent" copy is out of scope.

## 4. Data / interface contract

| Change | Producer | Consumer |
|---|---|---|
| `linkedSessionsForCard`, `linkedRowState`, `lastLinkedSession`, all in `src/board-linkage.ts`. `sessionsForCard`, `badgeStateForCard` and `CardBadge` are **deleted** (fallow gates dead exports). | `state.sessions` (host `postState`, per window, via `useSnooze`) | `BoardView` → `Card`, and the prefill in `app.tsx` |
| `BoardCard.ticket?` | **external writer only: no in-app producer (D1)** | `restoreBoard`, the artifact serializer, `diffBoard`, the `Card` header |
| `Card` props: `badge` is replaced by `linked: Session[]`, `agentLabel(s)` and `onStartSession()` | `BoardView` | `Card` |
| `onStartSessionForCard(card)`: the app builds a `NewSessionPrefill` (§3.3) | `app.tsx` | the mf-new-session dialog |
| `openRepo`: no fields beyond L3, which are stamped by mf-model | the dialog | host `mgr.create` |

**Invariant:** the committed `board.json` never gains a session id, a path or any other machine-local
datum (ADR 0002; `types.ts:77`). The list is derived and never stored.

## 5. Edge cases

- **No linked sessions:** no list and no divider, only `+ Start session`.
- **Many linked sessions (6 or more):** every row renders and the card grows. There is no cap.
- **An agent session that stopped or is stale:** hollow dot and muted name. The row is still clickable
  and stays until the session is closed.
- **`session:setHome`:** the old home becomes a root, so the session still matches. A session whose
  folders no longer include `boardHome` drops off.
- **Same project, different homes:** each session sees only its own home's board. A card still lists a
  session that has `boardHome` attached as a root (D2).
- **A session in another window:** not listed (D5).
- **The last session's project was deleted, or its agent was removed:** the prefill uses
  `projectId: null` and omits `agentId`.
- **An empty session name:** the accessible name falls back to `Untitled session`.
- **Malformed `ticket`:** omitted, and the card still loads.

## 6. Defaults vs settings

There is no new setting.

- The header is hidden without a `ticket`.
- The prefill comes from the most recent linked session (the handoff's "folders come from the card's
  last session").
- `autoSwitchSession` is respected as it is (D9).

## 7. UI checklists

**States:**

- linked sessions: none, one, many, a mix of running and stopped;
- a ghost card;
- `+ Start session` disabled;
- the header: full, partial, absent, overflowing.

**Styling:**

- A hovered row gets the shared quiet hover (`--state-hover-bg`) with radius 8, not an accent wash:
  the interaction-state vocabulary is the house rule (revised per conductor, 2026-09-24; plan
  Decisions). `+ Start session` carries its 9% accent tint at rest; hover changes its edge.
- Rows and the pill use the existing focus-visible ring.

**Interaction:**

- Clicks on a row or the pill call `stopPropagation`, so they never start a rename or open a menu.
- The card stays `draggable`, and a drag that starts on a row or the pill still moves the card
  (proven by e2e).
- There is no keyboard path to the context menu. `+ Start session` is the keyboard route.

**Accessibility:**

- The list is `<ul aria-label="Linked sessions">`.
- Each row is a `<button>` whose accessible name comes from one template: `{name}, {agent}, running`
  or `{name}, {agent}, not running`. The dot is `aria-hidden`.
- State never relies on colour alone: filled vs hollow and the muted name carry it too.
- Tab order follows the DOM: hover actions → rows → `+ Start session`.
- Rows and the pill are at least 24px tall.
- The status pill uses accent text on an accent tint. Its contrast must meet 4.5:1 in all three
  themes, checked in `npm run shots`.

**i18n:**

- New strings: `Linked sessions`, `+ Start session`, `running`, `not running`, `Untitled session`.
- Keep the existing subtitle template. It contains no plurals.
- User-supplied text (session names, agent labels, ticket parts) renders with `dir="auto"`. Widths
  come from flex and ellipsis, never from fixed LTR assumptions.

**Tokens:**

- Use `--accent`, `--text-muted`/`--muted`, the existing tag and pill classes and the mono font
  variable. No hex.
- Delete the `.bcard__badge*` rules.
- The board isn't over `.topbar`, so no app-region change is needed.

## 8. Scope

- **MVP:** §3 and the acceptance criteria below.
- **v1:**
  - Other windows' linked sessions. This needs a host broadcast of every session's
    `{id,cardId,home,roots,name,agentId,status,windowId}` and focusing across windows.
  - Remembering a card's last folders in userData, so that Start session still works after every
    session has closed.
- **Vision:** tracker sync writes `ticket`; a project-level board folder.

## 9. Acceptance criteria

**Unit tests** (`board-linkage.test.ts`, `board.test.ts`, `conduit-store.test.ts`,
`conduit-proposal.test.ts`)

- **AC1** `linkedSessionsForCard` matches on `cardId` and on `boardHome` being the home or a root. It
  is case- and slash-insensitive for drive paths, tested with explicit `C:\\Src\\A` vs `c:/src/a/`
  strings (CI runs on Linux). A matching `cardId` with neither home nor a root at `boardHome` is
  excluded.
- **AC2** Order is the input order. `lastLinkedSession` picks the greatest `lastActiveAt`; ties go to
  the first. `linkedRowState` maps `running` to `running`, and both `exited` and `stale` to `stopped`.
- **AC3** `ticket` behaviour:
  - It survives `serializeBoardArtifact` → `readBoardArtifact`, both as an envelope and as a bare
    board.
  - Values are trimmed and truncated by code point, with a test that uses a 41-emoji key.
  - Non-strings and empty values are dropped; a `ticket` that ends up empty is omitted.
- **AC4** `duplicateCard` drops `ticket`. `diffBoard` reports `ticket` in `edited[].fields` when a
  sub-field changes.
- **AC5** The prefill builder: last session vs the active-session fallback; a dangling `projectId`
  becomes `null`; an unregistered `agentId` is omitted.
- **AC6** `badgeStateForCard`, `CardBadge` and `sessionsForCard` are gone, and `npm run verify` is
  green.

**EARS**

- WHEN a card has one or more linked sessions, THE card SHALL render one row per session in host list
  order.
- WHEN a row is clicked, or activated with Enter or Space, THE app SHALL activate that session and show
  the editor.
- WHEN `+ Start session` is activated, THE app SHALL open New session prefilled per §3.3.
- WHEN a linked session is closed, THE card SHALL drop its row and SHALL NOT write `board.json`.
- IF a card has no `ticket`, THEN the header row SHALL NOT render.

**Gherkin: e2e `test/e2e/board-sessions.e2e.mjs`** (real app, hidden, shared harness, `closeApp`,
scenarios run in order)
