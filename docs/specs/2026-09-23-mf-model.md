# Feature Spec: mf-model — the multi-folder session model and its host plumbing

**Tier:** FULL   **Feature type:** non-UI (host model, protocol, persistence, launch). No UI module.
**One-line request (conductor, verbatim):** "Host data model: projectPath→home rename, roots[],
projectId, Project store + v1→v2 migration, L3 messages, multi-root repos (tags), --add-dir
adapter, writeRoots + watcher over all folders, missing-folder detection (L9 host side). App
behaves as today for single-folder sessions."

Written in autonomous mode. The frame is `.autoloop/locked.md` (L1–L10), which this spec does not
re-argue. Where this spec extends a lock, the extension is recorded in §13. Design source: handoff
README "Data model changes" and 12j. The UI items (mf-sidebar, mf-new-session, mf-files,
mf-changes, mf-review, mf-live-edits, mf-board) build on the contract in §3 and are not specified
here.

**Revision 2** *(revised per design review)*: the architecture review (`.autoloop/evidence/mf-model-design-review.md`) and
conductor rulings `.autoloop/locked.md` L11/L12 changed the on-disk format (sessions.json stays
`version: 1` with a `projectPath` mirror), missing-folder handling at `openRepo`, the
projects.json read rule, the watcher event shape, the health check's concurrency, the win32
metacharacter trigger, and dropped the launch-record fields, the `session:replaceRoot` /
`keepOldHome` wire messages and `repoRoot` on rangeDiff/resolveRange. Each changed passage is
marked *(revised per design review)*.

## 1. Problem frame

- **Job:** give a session a home folder plus attached folders, and group sessions into named
  projects. The host has to own, persist, validate and publish this so every UI item can read it
  from `state` and change it with one message.
- **Actors:** the Electron main process (source of truth), every renderer window (reads `state`,
  posts L3 messages), the launched agent (claude gets `--add-dir`), and the on-disk files
  `userData/sessions.json` and `userData/projects.json`.
- **Success outcomes (observable):**
  - An existing user's `sessions.json` loads with each session's folder as `home`, `roots: []` and a
    `projectId`; the file stays `version: 1` and loadable by an older build *(revised per design review)*. `projects.json` holds one project per distinct folder.
    The sidebar, Changes, Files, git band and terminal behave exactly as before.
  - A session given attached folders over L3 messages publishes them in `state`. Its repos
    include the attached folders' repos, tagged. Writes, previews and LSP are admitted inside
    those folders. A claude session launched afterwards gets one `--add-dir <root>` per present
    root. The project watcher reports changes in every folder.
  - Deleting an attached folder on disk marks it in `missingRoots`. Recreating it clears the mark
    without user action.
- **Non-goals:** all UI. That covers the sidebar grouping by `projectId` (mf-sidebar; this item
  keeps grouping by `home`, §13 D1), the dialog, the Files and Changes tabs, the banner, the
  missing-folder UI, board links, per-repo branch/dirty data (§13 D9). *(revised per conductor)* Upward detection of an enclosing repo is now in
  scope (§2.4, §13 D8). Also out: any change to preview-protocol confinement rules (L6), and a
  `--add-dir` equivalent for codex, cursor-agent or shells (L5).

## 2. Behavior & states

### 2.1 The rename (L1)
`Session.projectPath` becomes `Session.home` in the type, host, renderer, `webview/mock.ts` and
tests. No alias survives. It is a mechanical rename, and every current meaning carries over:
launch dir, default name, sidebar group key (for now), `.conduit/` root, plan-watch root,
index/quick-open root, `openedRoot` for `resolveActiveRepo`. The helpers `activeCwd`,
`gitRootForSession` and `sessionGitRoot` take `{ cwd?, home }`. The vestigial
`state.groups` / `ProjectGroupDTO` / both `groupByProject` helpers are **deleted**, not renamed
(§13 D2). The renderer reads `state.sessions` (app.tsx:526); `groups` is only a fallback there.

### 2.2 Session and project lifecycle

| Event | Effect on the model |
|---|---|
| `openRepo {path, agentId, cardId?, roots?, projectId?, requestId?}` | *(revised per design review)* `home = path` (stored as given). The home is stat'd: missing → no session, reply `openRepo:result {error:'home-missing'}` (`'invalid-path'` for a non-directory or a non-string path; with a `requestId`, an unknown `agentId` → `'unknown-agent'`, without one today's first-agent substitution stays). `roots` are validated (§3.3): a valid-but-missing root is **kept** and seeded into `missingRoots` at create; an invalid entry is dropped and reported in `droppedRoots: {path, reason}[]`; the session is still created. A `projectId` naming no project, or `null`/absent, gives a standalone session. A health check runs, then a repo scan. |
| `duplicate {id}` | The copy gets the same `agentId`, `home`, `roots`, `missingRoots` and `projectId`. It does **not** get `cardId` (unchanged today). Health is re-checked rather than copied. |
| `session:addRoot` | Validated `path` is appended to `roots`. Rescan. The watcher is re-armed if the session is active. Health check. |
| `session:removeRoot` | Matching root removed (folder-key compare, §3.3). A missing root can be removed. `home` can't be removed this way (rejected; use `setHome`). Side effects: the rescan drops its repos, so a pin or active repo inside it falls back through `resolveActiveRepo`. Open editor tabs stay open. Saves still succeed for files the host served, through read-grants (`src/read-grants.ts`); other writes there are refused. LSP servers rooted there stop by their normal idle stop; they are not killed. |
| replace a root (host API, no wire message) *(revised per design review)* | For "Locate…" on a missing folder, called by mf-files' `session:locateFolder` (L11). `new` is validated like `addRoot`, excluding `old` from the overlap check, and replaces `old` **at the same index**. |
| `session:setHome {path}` | If `path` is in `roots`, it leaves `roots`. The old home is appended to `roots`, which is a swap. If `path` is new, it must pass validation (and be present), and the old home is still appended. *(revised per design review)* The "don't keep the old home" variant is a host-only parameter used by the Locate handler for a missing home; it is not on the wire. `cwd`, `name` and the live PTY are untouched. Only terminals started afterwards see the new home (`term:start` passes `s.cwd ?? s.home`). Because `.conduit/` follows the home (L7), `planWatcher.reconcile` re-runs over every session's home. The board, architecture and review-notes watchers are re-armed by the renderer's next request for `active.home`, as today. |
| `session:setProject {projectId}` | `projectId` is set, or cleared with `null`. An unknown id is rejected. |
| `project:create {name, requestId}` | New project `{id: random, name, order: max+1}`. Reply `project:created {requestId, id}`. |
| `project:rename {id, name}` / `project:reorder {ids}` | Name is validated and set. Reorder puts the listed ids first, appends the missing ones and renumbers `order` 0..n-1. Unknown ids are ignored. |
| `project:delete {id}` | The project is removed. Every session with that `projectId` has the field deleted and becomes standalone. PTYs, folders and `.conduit/` are untouched (L2). |
| `session:move` / `dragEnd` (cross-window) | No change. Session objects are process-global, so `home/roots/projectId` travel. Projects are global and every window's `state` carries the same list. |
| Restore | Parse (§2.3), then health-check every session (§2.6), then scan repos. |

Every mutation emits through `SessionManager` or the new project store. That triggers
`postState` and the existing persist path (§2.3).

### 2.3 Persistence and migration *(revised per design review)*

- **sessions.json stays `{version: 1, sessions}`** (L12 S13). Each session is persisted with `home`,
  `roots`, `projectId?` **and a `projectPath` mirror equal to `home`**, written only by the
  serializer; the `Session` type has no `projectPath` (L1). An older build (which accepts only
  version 1 and spreads unknown fields) therefore loads every session and round-trips the new
  fields. The strip list is extended with `missingRoots` and `homeMissing`.
- **projects.json v1:** `{version: 1, projects: Project[]}`, written with the same async atomic
  `persistFile` on every change and by `flushStateSync` in `before-quit` (only when changed this
  run). Projects are always persisted, **not** gated on `restoreSessions`.
- **Parse (sessions):** a version other than 1, non-JSON, or a non-array `sessions` → empty (today's
  behaviour). Per entry: `home` = a non-empty string `home`, else a non-empty string `projectPath`
  (the entry is then **legacy**), else the entry is dropped and logged. `roots` must be an array
  of non-empty strings; entries are de-duped by folder key and home's key is dropped; not an array →
  `[]`. A non-string `projectId` is deleted.
- **Folder key:** `folderKey(p)` = `normalizeRoot` from `src/review-marks.ts` (slashes normalised,
  trailing slash stripped, drive-letter paths lower-cased), with UNC (`//server/share…`) paths also
  lower-cased. String-only, never `process.platform`. The deterministic project id of a folder is
  `p-` + the first 12 hex digits of sha1(folder key).
- **Migration (pure; runs at startup when `restoreSessions` is on). Trigger = any legacy entry**
  (lacking `home` — pre-multi-folder, or added by an older build after a downgrade). Each legacy
  session gets `projectId` = its folder's deterministic id; if projects.json lacks it and is
  writable, `{id, name: basename(home) || home, order: max+1}` is appended in first-seen order. A
  legacy session thus joins its folder's existing project. If anything migrated, `sessions.json` is
  copied once (atomically; skipped if present) to `sessions.pre-mf.bak.json`, then projects.json is
  written, then sessions.json — both synchronous and atomic, before the first `postState`; **the
  sessions write is skipped if the projects write failed** (the next launch re-migrates).
- **projects.json read:** `absent` **only on ENOENT**. Any other read error (EBUSY, EPERM, …) is
  `unreadable`. Text that fails to parse or has the wrong shape is `corrupt`; `version > 1` is
  `future`. An entry needs a non-empty string `id` (duplicates: first wins); `name` is trimmed,
  empty/non-string → `"Untitled project"`; a non-finite `order` sorts last; orders are renumbered
  0..n-1.
  - `absent`/`ok`: a session `projectId` naming no project is deleted — **unless it equals its
    home's deterministic id, in which case that project is recreated** (recovers a crash between the
    two writes or a run whose projects write was blocked).
  - `corrupt`: the file is copied (atomically, overwriting) to `projects.corrupt.json`, loading
    continues with `[]`, session ids are kept (they read standalone), writes are allowed.
  - `unreadable`/`future`: `[]`, session ids kept, and **projects.json is not written for the
    run**. A project mutation first retries the read; if it now succeeds the store is loaded and
    writes resume, otherwise the mutation is refused (`project:opResult {reason:'store-unavailable'}`
    for create; others are logged no-ops).
- Idempotence: ids are deterministic, so re-running the migration after any crash lands on the same
  projects and never duplicates one.

### 2.4 Repos (L4)
`scheduleRepoScan` runs `detectRepos` for `home`, unless the home is missing, and then for each
present root in `roots` order. *(revised per conductor)* When a folder's downward scan finds no repo rooted at the
folder itself, the host asks git for its **enclosing** repo (`git rev-parse --show-toplevel` through
`runGit` — `GIT_OPTIONAL_LOCKS=0` — async, `GIT_TIMEOUT.metadata`, memoised 30 s) and lists it
before that folder's downward results, tagged by the folder it encloses (`'home'` for home,
`'attached'` for an attached folder), `folder` = that folder, `name` = the toplevel's last segment.
A home at `repo/packages/foo` therefore keeps showing `repo`'s changes, as it does today through the
cwd fallback. The results are merged in that order and de-duped by folder key of
`root`, so the first occurrence wins. Each `RepoInfo` gets `folder` (the session folder it was
found under, as stored) and `tag`: `root` equal to home → `'home'`; found under home → `'nested'`;
found under an attached root → `'attached'`. `name` stays relative to `folder` (`'.'` when the
folder is the repo). The merged list is capped at 200, with home's repos first. `setRepos`'s
unchanged-list check compares `root`, `tag` and `folder`, because a `setHome` swap changes tags
without changing roots. `resolveActiveRepo` uses `openedRoot = home`, so a single-folder session
resolves exactly as today. `settings.multiRepoPicker === false` still yields `repos = []`
(§13 D10).

### 2.5 Launch (L5)
On a cold start, `term:start` looks up `mgr.get(sessionId)`, which it already does for the
kill-race guard. It passes the session's **present** roots (`roots` minus `missingRoots`) into
spawn resolution. There is a pure adapter, `launchArgsFor(def, roots, platform)`. It is also
importable by the renderer, so mf-new-session's "Launches as" preview uses the same logic. It
works like this:
- **Match:** a definition is claude when the command's last segment, lower-cased, with a trailing
  `.exe`/`.cmd`/`.bat` stripped, equals `claude`. The segment is split on **both** `/` and `\`
  on every platform, never with `path.basename`, which is wrong on ubuntu CI for `C:\x\claude.cmd`. The user-chosen `id` is ignored. Any other
  definition, and `'shell'` or the default-shell fallback, gets no extra args.
- **Args:** `[...def.args, '--add-dir', r1, '--add-dir', r2, …]`, appended after the definition's
  args and before `cwdReportingAugmentation`, which only applies to shells anyway. The flag is
  repeated per root rather than given one variadic list. Measured: `claude --help` prints
  `--add-dir <directories...>`, so a single variadic list would swallow any positional argument
  after it.
- **win32 metacharacter guard** *(revised per design review)* (L12 S10, one policy): on win32, when the **resolved** command
  (PATH lookup trying `.exe`, `.cmd`, `.bat`) ends in `.cmd` or `.bat` — or cannot be resolved —
  a root containing any of `" % & | < > ^ !` is skipped for `--add-dir`, logged, and returned in
  the launch plan's `skippedAddDirRoots` (the dialog's preview disables Start on it). `.exe` and
  posix are unaffected (§13 D6).
- **Race with the first health check:** a cold `term:start` awaits that session's in-flight
  health check, if one is pending, before building args. A restored session can therefore never
  pass a missing root.
- **No launch record on the session** *(revised per design review)* (L12 S7). `buildLaunchSpec` returns
  `{ok: true, spec, addDir, launchedRoots, skippedAddDirRoots}` or `{ok: false, reason: 'home-missing'}`;
  mf-live-edits captures its own scope from the final spawn args.
- **Missing home** *(revised per design review)* (supersedes D5): a `homeMissing` session never spawns. The cwd is the live
  cwd if it exists, else home if it exists, else the launch is refused; `os.homedir()` is no longer a
  session fallback. `term:start` writes one dim line and spawns nothing; the UI is mf-live-edits'.
- The cwd rule is unchanged. So is the attach path: a live PTY keeps its original args, and the
  banner for that case belongs to mf-live-edits. Relaunch goes through the same cold path, so it
  picks up the current roots.

### 2.6 Folders everywhere (L6) and missing folders (L9)
- **`writeRoots()`** = every session's `home` + every `roots` entry + recent `repos.json` paths.
  Missing folders are included, per the lock's literal wording. They hold no files, and they
  reconnect in place. Path guards, preview tokens (`rootTokenFor` gives one opaque token per
  root, so one origin per folder) and LSP workspace roots consume `writeRoots` unchanged. **No
  edit to `electron/preview-protocol.ts`** is made.
- **`resolveOwningSession`** (`src/owning-session.ts`, used by the host's OS-open at main.ts
  ~3941 and by the renderer) matches the longest ancestor among each session's `home` **and
  roots**. A file under an attached folder then reuses that session instead of opening a new one.
  The input shape becomes `{id, home, roots?}`. If two folders tie on length (one session's
  home is another's root), the session whose **home** it is wins.
- **Project watcher:** `ProjectWatcher` becomes a watched **set**. `requestProject` gains an
  optional `sessionId`, and the renderer's three `requestProject` posts (app.tsx ~1240, ~1257,
  ~1308) pass `active.id` (§13 D4). The registered folders are `{p}` ∪ (session ? `{home}` (unless
  `homeMissing`) ∪ present roots : ∅). `fs.watch` on an absent path throws, so missing folders are
  never registered. Registered folders nested in another share the ancestor's single recursive
  `fs.watch`. *(revised per design review)* Each event is mapped on arrival to the registered folders containing it; the ignore filter
  is evaluated relative to the **deepest** containing folder; only a bounded set of folder indexes is
  kept per debounce window. **One** `fsChanged {root, folders}` is emitted per fire: `folders` = the
  touched registered folders in registration order, `root = folders[0]` (today's value whenever the
  requested path is touched). The renderer does one Changes refresh per message; per-folder consumers
  read `folders`. A single-folder session gets one watch and one event per window, identical to
  today, including when cd'd into a subfolder. Host side effects per fire: `dropResolutionsForRoot`
  per folder and one `scheduleRepoScan` per session owning any of them. Unregistered watches are
  closed. The whole folder lifecycle (watch set, health, rescans, plan reconcile) lives in one host
  module with a single `onFoldersChanged(sessionId)` hook (L12 S1). The watcher still follows the latest `requestProject` from any
  window, as today.
- **Health check** (`checkFolders(sessionId)`, async `fs.promises.stat`, so an offline UNC share
  never blocks the main thread). There is **at most one stat in flight per folder key**, and *(revised per design review)* **at most 2 outstanding across
  all keys**; the 3 s timeout starts at issue; a folder that could not be issued within its window is
  `unknown` and keeps its previous state; a key still unsettled past its timeout is not re-issued. A timeout marks the folder missing, and a later tick retries it. This
  keeps a hung share from piling stats onto libuv's 4-thread pool, which `persistFile` shares.
  Results are intersected with the session's **current** `roots` before they are applied, which
  keeps I3 when a `removeRoot` lands mid-check; *(revised per design review)* a result carries the home key it measured and
  `homeMissing` is applied only if that is still the home (a `setHome` mid-check can't mark the new home). A folder is present iff stat succeeds and it is a directory. The
  result sets runtime `missingRoots` (a subset of `roots`, in `roots` order, absent when empty)
  and `homeMissing` (absent when false). The manager emits only when they change. The check runs
  on: restore; `openRepo`, `duplicate`, `addRoot`, `setHome`; `requestProject` for its
  `sessionId` only when that session is not already the watched one (a session switch — every
  `fsChanged` provokes a refresh `requestProject`, so checking on each would be a check per fire);
  host window focus, for the watched session; and *(revised per design review)* a watcher `error` or a null-filename event (only the folders of that watch are checked —
  never every folder on every fire). A **reconnect poll** runs every 5 s, but only while at least one
  folder of any session — **home included** *(revised per design review)* — is missing. It checks only the missing folders, and it stops when none are
  missing. A folder that returns *(revised per design review)* is re-run through the full validator (§3.3: realpath key,
  filesystem-root, duplicate/overlap against the current folders) before its mark clears; if it now
  fails it stays in `missingRoots` and the reason is logged once. A cleared mark triggers a rescan. The watcher is re-armed if
  its session is the active one.
- **Missing attached folders are excluded from:** `detectRepos`, the watcher set and `--add-dir`.
  Search exclusion is renderer-side (mf-files), fed by `missingRoots`. **A missing home** *(revised per design review)*: never spawns (§2.5); the "Can't start" UI belongs to mf-live-edits and is
  fed by `homeMissing` (§13 D5).

## 3. Data / interface contract

### 3.1 Types (`src/types.ts`, `src/repo-scan.ts`, `src/protocol.ts`)
```ts
interface Project { id: string; name: string; order: number }            // new, shared
interface Session {                                                      // changed fields only
  home: string;              // was projectPath
  roots: string[];           // attached only; never contains home; folder-key-unique; add order
  projectId?: string;        // absent = standalone
  missingRoots?: string[];   // runtime-only, host-derived, stripped on save
  homeMissing?: boolean;     // runtime-only, host-derived, stripped on save
}
type RepoTag = 'home' | 'nested' | 'attached';
interface RepoInfo { root: string; name: string; folder: string; tag: RepoTag }
// state: + projects: Project[] (sorted by order); − groups
```
*(revised per design review)* `launchedRoots` / `skippedAddDirRoots` are not session fields (L12 S7).

### 3.2 Messages (renderer → host), new or changed
```ts
| { type: 'openRepo'; path: string; agentId: string; cardId?: string;
    roots?: string[]; projectId?: string | null; requestId?: number }
| { type: 'requestProject'; path: string; changesRoot?: string; sessionId?: string }
| { type: 'session:addRoot';    sessionId: string; path: string; requestId?: number }
| { type: 'session:removeRoot'; sessionId: string; path: string; requestId?: number }
| { type: 'session:setHome';    sessionId: string; path: string; requestId?: number }
| { type: 'session:setProject'; sessionId: string; projectId: string | null; requestId?: number }
| { type: 'project:create';  name: string; requestId: number }
| { type: 'project:rename';  id: string; name: string }
| { type: 'project:delete';  id: string }
| { type: 'project:reorder'; ids: string[] }
// + optional repoRoot?: string on: git:history, git:refs, git:switch
//   (rangeDiff / resolveRange belong to mf-review) *(revised per design review)*
```
Host → renderer:
```ts
| { type: 'session:opResult'; requestId: number; ok: boolean;
    reason?: 'unknown-session' | 'invalid-path' | 'not-found' | 'not-a-directory'
           | 'filesystem-root' | 'duplicate' | 'overlaps' | 'is-home' | 'not-attached'
           | 'unknown-project' | 'too-many' }
| { type: 'project:created'; requestId: number; id: string }
| { type: 'openRepo:result'; requestId: number; sessionId?: string;
    droppedRoots: { path: string; reason: SessionOpReason }[];
    error?: 'home-missing' | 'invalid-path' | 'unknown-agent' }          // revised per design review
| { type: 'project:opResult'; requestId: number; ok: false;
    reason: 'invalid-name' | 'store-unavailable' }                        // create only
| { type: 'fsChanged'; root: string; folders: string[] }                  // revised per design review: one per fire
// every git:*Result above echoes repoRoot when the request carried one
```
The `session:opResult` reply is sent only when `requestId` was given. State changes always arrive
on `state`. Project mutations with no `requestId` fail silently (logged). There is no reason to
reply, because the next `state` is authoritative.

### 3.3 Validation (host, trust boundary: every renderer payload is untrusted)
- **A folder path** (`openRepo.roots[]`, `addRoot`, `setHome`) is a string of 1–4096 characters
  with no NUL. It is `path.isAbsolute`, and it is stored as `path.resolve(p)`. It must `stat` as
  a directory (async) — *(revised per design review)* except in `openRepo.roots`, where a missing path is kept after the
  lexical checks only and marked missing. For a present path its realpath is taken with the **async**
  `fs.promises.realpath` (never the sync `realPathLeaf`, never for a missing path). Neither `p` nor its realpath may be a filesystem root
  (`path.parse(x).root === x`), so a junction to `C:\` is refused too (§13 D12). A session holds
  at most **32** roots (`too-many`). Identity is the **folder key** of `p` plus that of its realpath. *(revised per design review)* Existing folders contribute
  their lexical key **and** a runtime-cached realpath key (taken when the folder was added or first
  seen present), so the check works in both directions. The candidate must differ from every existing
  key (`duplicate`). It must neither contain nor be contained by home or any other root,
  using segment-aware `isAncestorOf` on keys (`overlaps`) (§13 D13). `setHome`'s check excludes
  the path itself when it is being swapped out of `roots`. After every await, the handler
  re-checks that the session exists and re-runs the key and overlap checks against the
  **current** `roots`/home before mutating, because two messages can interleave across the stat.
  Stored paths stay lexical (`path.resolve`), so a symlinked folder inherits today's limit: writes
  inside it fail `validateWrite` stage 2, because the realpath is outside the lexical root.
  Recorded as §13 D15. `openRepo.path` *(revised per design review)* must be a directory that exists (else `openRepo:result.error`); otherwise
  unvalidated as today (a filesystem root stays allowed, D12).
- **`removeRoot`** compares by folder key against `roots`: `not-attached` if absent, `is-home` if
  it names home.
- **`projectId`** must name an existing project (`unknown-project`).
- **Project `name`:** trimmed, internal whitespace collapsed, 1–80 characters (`invalid-name`).
  Duplicate names are allowed.
- **`repoRoot`** (history, refs, switch *(revised per design review)*): accepted only if `session.repos` contains it by folder
  key. Otherwise the host replies with that result's failure shape: `git:historyResult` gets
  `state:'error'`, empty commits; `refs` gets empty lists + `error:'unknown repo'`; `switch` gets
  `ok:false, reason:'failed', message:'unknown repo'`. Git is never run against the raw path. When the request carries no `repoRoot`, the host
  uses `gitRoot(session)` as today. The existing `git:commitDiff.root` is left as it is today
  (§13 D14).
- **Payload types:** a field of the wrong type (`ids` not an array of strings, `name` not a
  string, `projectId` neither string nor null) makes the message a logged no-op.
- Session ownership by the sending window is not checked. That is consistent with
  `rename`/`kill`/`repo:pin` today.

### 3.4 Invariants
I1: `roots` never contains home's key, and has no two entries with one key. I2: roots never
overlap each other or home, lexically or by realpath, checked at add time **or, for a root added
missing, at its first presence** *(revised per design review)*. I3:
`missingRoots ⊆ roots`. I4: after a clean projects.json load (absent on ENOENT, or ok), a persisted `projectId` names an
existing project (recreated if it is its home's deterministic id), or is deleted on load or on
project delete. After a failed load it is kept
and reads as standalone. I5: `missingRoots` and `homeMissing` never reach disk. I6: for a
session with `roots = []` and no `projectId` change, every consumer receives the same values it
did before this item. The only difference is the `projectPath` → `home` spelling.

## 4. Edge cases & failure modes

| Condition | Expected behaviour |
|---|---|
| v1 has `C:\a\x` and `c:/A/x/` | `normalizeRoot` lower-cases the whole key for a drive-letter path, so both map to key `c:/a/x` and **one** project. Each session keeps its own stored `home` string. |
| v1 on linux with `/Work/x` and `/work/x` | two projects (case-sensitive, not a drive-letter path) |
| projects.json present + sessions.json v1 | migrates onto deterministic ids; nothing duplicated (§2.3) |
| projects.json absent (ENOENT) + migrated sessions *(revised per design review)* | deterministic ids recreate their projects; other dangling ids deleted |
| projects.json corrupt | backed up to `projects.corrupt.json`; `[]`; ids kept (standalone); writes allowed |
| projects.json unreadable (EBUSY/EPERM) or future version *(revised per design review)* | `[]`; ids kept; projects.json not written this run; mutations retry the read, else `store-unavailable` |
| sessions.json corrupt / other version | as today: empty. No backup (unchanged). |
| Downgrade to an older build and back *(revised per design review)* | older build loads every session via the `projectPath` mirror; sessions it adds lack `home` and join their folder's project on the next upgrade |
| Hung UNC stat | one in flight per folder, 3 s timeout → missing; persistence keeps its threads |
| `removeRoot` during a health check | result intersected with current roots; I3 holds |
| UNC `\\Srv\Share` vs `\\srv\share` | one folder key |
| `restoreSessions` off | no parse, no migration, no sessions write. projects.json still loads and persists. The later restore-on launch migrates. |
| Crash between the two migration writes | re-migrates idempotently, or recovers via deterministic ids |
| Two `addRoot` for one path in a burst | handled serially on the one host loop. The second gets `duplicate`, since validation stats asynchronously and then re-checks the key against the current `roots` right before inserting. |
| `addRoot` of a symlink to home, or to a sibling root | `duplicate` or `overlaps` via the realpath key |
| `setHome` to a subfolder of the old home | `overlaps` (the old home would become a root containing the new home) |
| `project:delete` while sessions are running | they keep running and are standalone on the next `state` |
| `project:reorder` with duplicates / unknown ids | first occurrence wins; unknown ignored; missing appended |
| Root deleted while its session is inactive | noticed on the next `requestProject` for it, `term:start`'s scan, or restore |
| Root on an offline network share | stat rejects or times out on the libuv pool, and the root is marked missing. The main thread never blocks. |
| Many missing folders | poll is O(missing) every 5 s; zero cost when none (idle-fs-quiet holds) |
| Root with `&` on win32, command resolving to `.cmd` | skipped for `--add-dir`, warning logged, reported; still attached everywhere else |
| Root with `&` on win32, command resolving to `claude.exe` *(revised per design review)* | passed |
| Relaunch after `addRoot` | new PTY gets the new `--add-dir`; attach path (window move) keeps old args |
| `repoRoot` (history/refs/switch) for a repo removed by a rescan | rejected with the failure shape; renderer re-requests on `state` |
| `openRepo.roots` includes home or a dup | dropped (logged, reported in `droppedRoots`). The session is still created. |
| `openRepo.roots` includes a missing folder *(revised per design review)* | kept, in `missingRoots` from the first `state` |
| `openRepo` on a missing home *(revised per design review)* | no session; `openRepo:result {error:'home-missing'}` |
| Four hung shares *(revised per design review)* | ≤ 2 stats outstanding; queued folders read `unknown` (unchanged) |

## 5. Defaults vs. settings

| Decision | Default | Configurable? | Rationale |
|---|---|---|---|
| New session's project | standalone (L3) | per call (`projectId`) | lock |
| Reconnect poll interval | 5 s, only while something is missing | no | same order as PlanWatcher's 2 s existsSync poll; zero idle cost |
| Merged repo cap | 200, home first | no | today's per-scan cap; bounds `state` size |
| `--add-dir` for non-claude | none | no | L5 |
| Project name max | 80 chars | no | fits a group header; reversible |
| Migration backup *(revised per design review)* | `sessions.pre-mf.bak.json`, once, atomic | no | insurance for the one rewrite that adds `home`/`projectId` |
| Outstanding health stats *(revised per design review)* | 2 | no | keeps libuv's 4-thread pool free for persistence |
