# Feature Spec: mf-model — the multi-folder session model and its host plumbing

**Tier:** FULL   **Feature type:** non-UI (host model, protocol, persistence, launch). No UI module.
**One-line request (conductor, verbatim):** "Host data model: projectPath→home rename, roots[],
projectId, Project store + v1→v2 migration, L3 messages, multi-root repos (tags), --add-dir
adapter, writeRoots + watcher over all folders, missing-folder detection (L9 host side). App
behaves as today for single-folder sessions."

Written in autonomous mode. The frame is `.autoloop/locked.md` (L1–L10), which this spec does not
re-argue. Where this spec extends a lock, the extension is recorded in §13. Design source: handoff
README "Data model changes" and 12j. The UI items (mf-sidebar, mf-new-session, mf-files,
mf-changes, mf-review, mf-live-edits, mf-board) build on the contract in §3 and are not specified
here.

## 1. Problem frame

- **Job:** give a session a home folder plus attached folders, and group sessions into named
  projects. The host has to own, persist, validate and publish this so every UI item can read it
  from `state` and change it with one message.
- **Actors:** the Electron main process (source of truth), every renderer window (reads `state`,
  posts L3 messages), the launched agent (claude gets `--add-dir`), and the on-disk files
  `userData/sessions.json` and `userData/projects.json`.
- **Success outcomes (observable):**
  - An existing user's `sessions.json` v1 loads as v2. Each session keeps its folder as `home`,
    gets `roots: []`, and gets a `projectId`. `projects.json` holds one project per distinct folder.
    The sidebar, Changes, Files, git band and terminal behave exactly as before.
  - A session given attached folders over L3 messages publishes them in `state`. Its repos
    include the attached folders' repos, tagged. Writes, previews and LSP are admitted inside
    those folders. A claude session launched afterwards gets one `--add-dir <root>` per present
    root. The project watcher reports changes in every folder.
  - Deleting an attached folder on disk marks it in `missingRoots`. Recreating it clears the mark
    without user action.
- **Non-goals:** all UI. That covers the sidebar grouping by `projectId` (mf-sidebar; this item
  keeps grouping by `home`, §13 D1), the dialog, the Files and Changes tabs, the banner, the
  missing-folder UI, board links, per-repo branch/dirty data (§13 D9) and upward detection of an
  enclosing repo (§13 D8). Also out: any change to preview-protocol confinement rules (L6), and a
  `--add-dir` equivalent for codex, cursor-agent or shells (L5).

## 2. Behavior & states

### 2.1 The rename (L1)
`Session.projectPath` becomes `Session.home` in the type, host, renderer, `webview/mock.ts` and
tests. No alias survives. It is a mechanical rename, and every current meaning carries over:
launch dir, default name, sidebar group key (for now), `.conduit/` root, plan-watch root,
index/quick-open root, `openedRoot` for `resolveActiveRepo`. The helpers `activeCwd`,
`gitRootForSession` and `sessionGitRoot` take `{ cwd?, home }`. The vestigial
`state.groups` / `ProjectGroupDTO` / both `groupByProject` helpers are **deleted**, not renamed
(§13 D2). The renderer reads `state.sessions` (app.tsx:526); `groups` is only a fallback there.

### 2.2 Session and project lifecycle

| Event | Effect on the model |
|---|---|
| `openRepo {path, agentId, cardId?, roots?, projectId?, requestId?}` | `home = path` (stored as given today). `roots` are validated (§3.3). An invalid entry is dropped and the session is still created. With a `requestId`, the host replies `openRepo:result {requestId, sessionId?, droppedRoots: {path, reason}[]}`, so the dialog can say which folder was refused. A `projectId` naming no project, or `null`/absent, gives a standalone session. A health check runs, then a repo scan. |
| `duplicate {id}` | The copy gets the same `agentId`, `home`, `roots` and `projectId`. It does **not** get `cardId` (unchanged today). Health is re-checked rather than copied. |
| `session:addRoot` | Validated `path` is appended to `roots`. Rescan. The watcher is re-armed if the session is active. Health check. |
| `session:removeRoot` | Matching root removed (folder-key compare, §3.3). A missing root can be removed. `home` can't be removed this way (rejected; use `setHome`). Side effects: the rescan drops its repos, so a pin or active repo inside it falls back through `resolveActiveRepo`. Open editor tabs stay open. Saves still succeed for files the host served, through read-grants (`src/read-grants.ts`); other writes there are refused. LSP servers rooted there stop by their normal idle stop; they are not killed. |
| `session:replaceRoot {old, new}` | For "Locate…" on a missing attached root. `new` is validated like `addRoot`, excluding `old` from the overlap check, and replaces `old` **at the same index**. |
| `session:setHome {path, keepOldHome?}` | If `path` is in `roots`, it leaves `roots`. The old home is appended to `roots`, which is a swap. If `path` is new, it must pass validation, and the old home is still appended. With `keepOldHome: false`, the old home is not appended; that is for "Locate…" on a missing home. `cwd`, `name` and the live PTY are untouched. Only terminals started afterwards see the new home (`term:start` passes `s.cwd ?? s.home`). Because `.conduit/` follows the home (L7), `planWatcher.reconcile` re-runs over every session's home. The board, architecture and review-notes watchers are re-armed by the renderer's next request for `active.home`, as today. |
| `session:setProject {projectId}` | `projectId` is set, or cleared with `null`. An unknown id is rejected. |
| `project:create {name, requestId}` | New project `{id: random, name, order: max+1}`. Reply `project:created {requestId, id}`. |
| `project:rename {id, name}` / `project:reorder {ids}` | Name is validated and set. Reorder puts the listed ids first, appends the missing ones and renumbers `order` 0..n-1. Unknown ids are ignored. |
| `project:delete {id}` | The project is removed. Every session with that `projectId` has the field deleted and becomes standalone. PTYs, folders and `.conduit/` are untouched (L2). |
| `session:move` / `dragEnd` (cross-window) | No change. Session objects are process-global, so `home/roots/projectId` travel. Projects are global and every window's `state` carries the same list. |
| Restore | Parse (§2.3), then health-check every session (§2.6), then scan repos. |

Every mutation emits through `SessionManager` or the new project store. That triggers
`postState` and the existing persist path (§2.3).

### 2.3 Persistence and migration

- **sessions.json v2:** `{version: 2, sessions}`. Each session is persisted with `home`, `roots` and
  `projectId?`, and the existing strip list is extended with `missingRoots` and `homeMissing`.
- **projects.json v1:** `{version: 1, projects: Project[]}`. It uses the same
  `persistFile` (async atomic) on every change, and `flushStateSync` writes it in `before-quit`.
  Projects are always persisted (they are user-made entities, like `repos.json`). **They are not**
  gated on `restoreSessions`.
- **Migration (pure function, host calls it at startup when `restoreSessions` is on):**
  1. The sessions blob is parsed. If `version === 1`, each session's `projectPath` becomes `home`
     (a legacy `home` wins if both are present), `roots = []`, and the project mapping below
     applies. A v1 session with no string `projectPath` is dropped and logged. Today it would
     restore with an undefined folder.
  2. Project mapping. Take each distinct **folder key** in first-seen order. The key is
     `folderKey(p)`: `normalizeRoot` from `src/review-marks.ts` (slashes normalised, trailing
     slash stripped, drive-letter paths lower-cased), with UNC (`//server/share…`) paths also
     lower-cased. It is string-only and never calls `process.platform`. The id is **deterministic**, `p-` + the first 12 hex digits
     of sha1(folder key). If projects.json already holds that id, that project is reused as-is
     (name/order kept). Otherwise `{id, name: basename(home) || home, order: max+1}` is appended.
     Every session in that key gets the id.
  3. If anything migrated, `sessions.json` is **copied once** to `sessions.v1.bak.json` (skipped
     if the backup exists). Then projects.json is written, then sessions.json v2, both
     synchronously and atomically, before the first `postState`.
- The deterministic id makes the migration **idempotent**. Consider a crash after projects.json and
  before sessions.json v2. On relaunch the v1 file migrates again onto the same ids, and no
  duplicate projects appear. That is also why migration keys on "sessions blob is v1" and not on
  "projects.json absent" (§13 D3). A v1 blob with projects.json present still migrates, and
  existing projects are reused or new ones appended.
- **v2 parse:** a session needs a non-empty string `home`, or the legacy `projectPath` (L1). If it
  has neither, it is dropped. `roots` must be an array of non-empty strings. Entries are de-duped
  by folder key, and an entry equal to `home`'s key is dropped. If `roots` is not an array, it
  becomes `[]`. A `projectId` that isn't a string, or that names no project, is deleted (L2: reads
  as standalone). The id is deleted on load, which is the persisted fix.
- **projects.json parse:** an entry needs a non-empty string `id`, and duplicate ids resolve to the
  first. `name` is trimmed, and an empty or non-string name becomes `"Untitled project"`.
  A non-finite `order` sorts last. After the sort, orders are renumbered 0..n-1.
- **Corrupt vs absent:** `readBlob` returns `undefined` for an absent file. Suppose a string then
  fails to parse, or has the wrong version or shape. For **projects.json**, the file is copied to
  `projects.corrupt.json` (overwriting the previous copy), a warning is logged, and loading
  continues with `[]`. Sessions' ids then dangle and read standalone. For **sessions.json**,
  today's behaviour is unchanged: it is treated as empty.
- **An unknown future version** (`version > 2` in sessions.json, or `> 1` in projects.json)
  loads as empty. Before the first write, the file is copied to `sessions.v<N>.bak.json` /
  `projects.v<N>.bak.json` (once, never overwritten), so running an older build never destroys a
  newer file.
- **Dangling `projectId` when projects.json failed to parse:** the id is **kept** on the session
  and reads as standalone at runtime. It is not deleted, so restoring `projects.corrupt.json`
  recovers the grouping. Deletion on load happens only when projects.json parsed cleanly.

### 2.4 Repos (L4)
`scheduleRepoScan` runs `detectRepos` for `home`, unless the home is missing, and then for each
present root in `roots` order. The results are merged in that order and de-duped by folder key of
`root`, so the first occurrence wins. Each `RepoInfo` gets `folder` (the session folder it was
found under, as stored) and `tag`: `root` equal to home → `'home'`; found under home → `'nested'`;
found under an attached root → `'attached'`. `name` stays relative to `folder` (`'.'` when the
folder is the repo). The merged list is capped at 200, with home's repos first. `setRepos`'s
unchanged-list check compares `root`, `tag` and `folder`, because a `setHome` swap changes tags
without changing roots. `resolveActiveRepo` uses `openedRoot = home`, so a single-folder session
resolves exactly as today. `settings.multiRepoPicker === false` still yields `repos = []`
(§13 D10).

### 2.5 Launch (L5)
On a cold start, `term:start` looks up `mgr.get(sessionId)`, which it already does for the
kill-race guard. It passes the session's **present** roots (`roots` minus `missingRoots`) into
spawn resolution. There is a pure adapter, `launchArgsFor(def, roots, platform)`. It is also
importable by the renderer, so mf-new-session's "Launches as" preview uses the same logic. It
works like this:
- **Match:** a definition is claude when the command's last segment, lower-cased, with a trailing
  `.exe`/`.cmd`/`.bat` stripped, equals `claude`. The segment is split on **both** `/` and `\`
  on every platform, never with `path.basename`, which is wrong on ubuntu CI for `C:\x\claude.cmd`. The user-chosen `id` is ignored. Any other
  definition, and `'shell'` or the default-shell fallback, gets no extra args.
- **Args:** `[...def.args, '--add-dir', r1, '--add-dir', r2, …]`, appended after the definition's
  args and before `cwdReportingAugmentation`, which only applies to shells anyway. The flag is
  repeated per root rather than given one variadic list. Measured: `claude --help` prints
  `--add-dir <directories...>`, so a single variadic list would swallow any positional argument
  after it.
- **win32 metacharacter guard:** when the definition's command string does not end in `.exe`
  (a bare `claude` counts as non-`.exe`), a root containing any of `" % & | < > ^ !` is skipped
  and a warning is logged. A `claude.cmd` shim is run through
  `cmd.exe`, which would interpret those characters (§13 D6).
- **Race with the first health check:** a cold `term:start` awaits that session's in-flight
  health check, if one is pending, before building args. A restored session can therefore never
  pass a missing root.
- **Launch record (feeds the mf-live-edits banner):** the cold start stores two runtime-only
  fields on the session, `launchedRoots` (the roots actually passed) and `skippedAddDirRoots`
  (roots the guard skipped). Both are cleared on `term:exit` and stripped on save. They are only
  set for claude-matched launches. The banner shows when the present roots ≠ `launchedRoots`.
- The cwd rule is unchanged. So is the attach path: a live PTY keeps its original args, and the
  banner for that case belongs to mf-live-edits. Relaunch goes through the same cold path, so it
  picks up the current roots.

### 2.6 Folders everywhere (L6) and missing folders (L9)
- **`writeRoots()`** = every session's `home` + every `roots` entry + recent `repos.json` paths.
  Missing folders are included, per the lock's literal wording. They hold no files, and they
  reconnect in place. Path guards, preview tokens (`rootTokenFor` gives one opaque token per
  root, so one origin per folder) and LSP workspace roots consume `writeRoots` unchanged. **No
  edit to `electron/preview-protocol.ts`** is made.
- **`resolveOwningSession`** (`src/owning-session.ts`, used by the host's OS-open at main.ts
  ~3941 and by the renderer) matches the longest ancestor among each session's `home` **and
  roots**. A file under an attached folder then reuses that session instead of opening a new one.
  The input shape becomes `{id, home, roots?}`. If two folders tie on length (one session's
  home is another's root), the session whose **home** it is wins.
- **Project watcher:** `ProjectWatcher` becomes a watched **set**. `requestProject` gains an
  optional `sessionId`, and the renderer's three `requestProject` posts (app.tsx ~1240, ~1257,
  ~1308) pass `active.id` (§13 D4). The registered folders are `{p}` ∪ (session ? `{home}` (unless
  `homeMissing`) ∪ present roots : ∅). `fs.watch` on an absent path throws, so missing folders are
  never registered. Registered folders nested in another share the ancestor's single recursive
  `fs.watch`. A debounced change emits `fsChanged {root: F}` once for **each registered folder F
  that contains the changed path**. `F` is exactly as registered, and an unknown filename counts
  as all of them. So a single-folder session whose cwd is home still gets one watch and one event,
  identical to today. The watcher's side effects run per emitted root: `dropResolutionsForRoot`,
  plus `scheduleRepoScan` for every session whose `home` or a root has that folder key.
  Unregistered watches are closed. The watcher still follows the latest `requestProject` from any
  window, as today.
- **Health check** (`checkFolders(sessionId)`, async `fs.promises.stat`, so an offline UNC share
  never blocks the main thread). There is **at most one stat in flight per folder key**, raced
  against a 3 s timeout. A timeout marks the folder missing, and a later tick retries it. This
  keeps a hung share from piling stats onto libuv's 4-thread pool, which `persistFile` shares.
  Results are intersected with the session's **current** `roots` before they are applied, which
  keeps I3 when a `removeRoot` lands mid-check. A folder is present iff stat succeeds and it is a directory. The
  result sets runtime `missingRoots` (a subset of `roots`, in `roots` order, absent when empty)
  and `homeMissing` (absent when false). The manager emits only when they change. The check runs
  on: restore; `openRepo`, `duplicate`, `addRoot`, `setHome`; `requestProject` for its
  `sessionId` (focus and session switch); and a watcher `error`, or an event after which the
  watched folder no longer exists. A **reconnect poll** runs every 5 s, but only while at least one
  folder of any session is missing. It checks only the missing folders, and it stops when none are
  missing. A folder that returns clears its mark and triggers a rescan. The watcher is re-armed if
  its session is the active one.
- **Missing attached folders are excluded from:** `detectRepos`, the watcher set and `--add-dir`.
  Search exclusion is renderer-side (mf-files), fed by `missingRoots`. **A missing home:**
  `term:start` keeps today's fallback (`resolveLaunchSpec` → `os.homedir()`). The "Can't start"
  gate, which is renderer-side, belongs to mf-live-edits and is fed by `homeMissing` (§13 D5).

## 3. Data / interface contract

### 3.1 Types (`src/types.ts`, `src/repo-scan.ts`, `src/protocol.ts`)
```ts
interface Project { id: string; name: string; order: number }            // new, shared
interface Session {                                                      // changed fields only
  home: string;              // was projectPath
  roots: string[];           // attached only; never contains home; folder-key-unique; add order
  projectId?: string;        // absent = standalone
  missingRoots?: string[];   // runtime-only, host-derived, stripped on save
  homeMissing?: boolean;     // runtime-only, host-derived, stripped on save
  launchedRoots?: string[];      // runtime-only: roots passed as --add-dir at the last cold start
  skippedAddDirRoots?: string[]; // runtime-only: roots the win32 guard skipped at that start
}
type RepoTag = 'home' | 'nested' | 'attached';
interface RepoInfo { root: string; name: string; folder: string; tag: RepoTag }
// state: + projects: Project[] (sorted by order); − groups
```

### 3.2 Messages (renderer → host), new or changed
```ts
| { type: 'openRepo'; path: string; agentId: string; cardId?: string;
    roots?: string[]; projectId?: string | null; requestId?: number }
| { type: 'requestProject'; path: string; changesRoot?: string; sessionId?: string }
| { type: 'session:addRoot';    sessionId: string; path: string; requestId?: number }
| { type: 'session:removeRoot'; sessionId: string; path: string; requestId?: number }
| { type: 'session:replaceRoot'; sessionId: string; old: string; new: string; requestId?: number }
| { type: 'session:setHome';    sessionId: string; path: string; keepOldHome?: boolean;
    requestId?: number }
| { type: 'session:setProject'; sessionId: string; projectId: string | null; requestId?: number }
| { type: 'project:create';  name: string; requestId: number }
| { type: 'project:rename';  id: string; name: string }
| { type: 'project:delete';  id: string }
| { type: 'project:reorder'; ids: string[] }
// + optional repoRoot?: string on: git:history, git:refs, git:switch, git:rangeDiff, git:resolveRange
```
Host → renderer:
```ts
| { type: 'session:opResult'; requestId: number; ok: boolean;
    reason?: 'unknown-session' | 'invalid-path' | 'not-found' | 'not-a-directory'
           | 'filesystem-root' | 'duplicate' | 'overlaps' | 'is-home' | 'not-attached'
           | 'unknown-project' | 'too-many' }
| { type: 'project:created'; requestId: number; id: string }
| { type: 'openRepo:result'; requestId: number; sessionId?: string;
    droppedRoots: { path: string; reason: string }[] }
| { type: 'project:opResult'; requestId: number; ok: false; reason: 'invalid-name' } // create only
// every git:*Result above echoes repoRoot when the request carried one
```
The `session:opResult` reply is sent only when `requestId` was given. State changes always arrive
on `state`. Project mutations with no `requestId` fail silently (logged). There is no reason to
reply, because the next `state` is authoritative.

### 3.3 Validation (host, trust boundary: every renderer payload is untrusted)
- **A folder path** (`openRepo.roots[]`, `addRoot`, `setHome`) is a string of 1–4096 characters
  with no NUL. It is `path.isAbsolute`, and it is stored as `path.resolve(p)`. It must `stat` as
  a directory (async). Only after that, `realPathLeaf(p)` runs; it is sync, but it is then cheap
  and on a known-present path. Neither `p` nor its realpath may be a filesystem root
  (`path.parse(x).root === x`), so a junction to `C:\` is refused too (§13 D12). A session holds
  at most **32** roots (`too-many`). Identity is the **folder key** of `realPathLeaf(p)`. It must differ from home's key and every
  root's key (`duplicate`). It must neither contain nor be contained by home or any other root,
  using segment-aware `isAncestorOf` on keys (`overlaps`) (§13 D13). `setHome`'s check excludes
  the path itself when it is being swapped out of `roots`. After every await, the handler
  re-checks that the session exists and re-runs the key and overlap checks against the
  **current** `roots`/home before mutating, because two messages can interleave across the stat.
  Stored paths stay lexical (`path.resolve`), so a symlinked folder inherits today's limit: writes
  inside it fail `validateWrite` stage 2, because the realpath is outside the lexical root.
  Recorded as §13 D15. `openRepo.path` keeps today's
  (absent) validation, because that is unchanged behaviour.
- **`removeRoot`** compares by folder key against `roots`: `not-attached` if absent, `is-home` if
  it names home.
- **`projectId`** must name an existing project (`unknown-project`).
- **Project `name`:** trimmed, internal whitespace collapsed, 1–80 characters (`invalid-name`).
  Duplicate names are allowed.
- **`repoRoot`:** accepted only if `session.repos` contains it by folder key. Otherwise the host
  replies with that result's failure shape: `git:historyResult` gets `state:'error'`, empty
  commits; `refs`/`switch`/`rangeDiff`/`resolveRange` get their empty shape + `error:'unknown
  repo'`. Git is never run against the raw path. When the request carries no `repoRoot`, the host
  uses `gitRoot(session)` as today. The existing `git:commitDiff.root` is left as it is today
  (§13 D14).
- **Payload types:** a field of the wrong type (`ids` not an array of strings, `name` not a
  string, `projectId` neither string nor null) makes the message a logged no-op.
- Session ownership by the sending window is not checked. That is consistent with
  `rename`/`kill`/`repo:pin` today.

### 3.4 Invariants
I1: `roots` never contains home's key, and has no two entries with one key. I2: roots never
overlap each other or home, lexically or by realpath at the time they were added. I3:
`missingRoots ⊆ roots`. I4: after a clean projects.json load, a persisted `projectId` names an
existing project, or is deleted on load or on project delete. After a failed load it is kept
and reads as standalone. I5: `missingRoots` and `homeMissing` never reach disk. I6: for a
session with `roots = []` and no `projectId` change, every consumer receives the same values it
did before this item. The only difference is the `projectPath` → `home` spelling.

## 4. Edge cases & failure modes

| Condition | Expected behaviour |
|---|---|
| v1 has `C:\a\x` and `c:/A/x/` | `normalizeRoot` lower-cases the whole key for a drive-letter path, so both map to key `c:/a/x` and **one** project. Each session keeps its own stored `home` string. |
| v1 on linux with `/Work/x` and `/work/x` | two projects (case-sensitive, not a drive-letter path) |
| projects.json present + sessions.json v1 | migrates onto deterministic ids; nothing duplicated (§2.3) |
| projects.json absent + sessions.json v2 | ids dangle → deleted on load → all standalone; projects `[]` |
| projects.json corrupt / future version | backed up to `projects.corrupt.json`; `[]`; logged |
| sessions.json corrupt | as today: empty. No backup (unchanged). |
| sessions.json with a future version (downgrade) | loads empty; copied to `sessions.v<N>.bak.json` before the first write |
| projects.json corrupt + sessions v2 with ids | ids kept (standalone at runtime), so restoring the corrupt copy recovers the grouping |
| Hung UNC stat | one in flight per folder, 3 s timeout → missing; persistence keeps its threads |
| `removeRoot` during a health check | result intersected with current roots; I3 holds |
| UNC `\\Srv\Share` vs `\\srv\share` | one folder key |
| `restoreSessions` off | no parse, no migration, no sessions write. projects.json still loads and persists. The later restore-on launch migrates. |
| Crash between the two migration writes | re-migrates idempotently on relaunch |
| Two `addRoot` for one path in a burst | handled serially on the one host loop. The second gets `duplicate`, since validation stats asynchronously and then re-checks the key against the current `roots` right before inserting. |
| `addRoot` of a symlink to home, or to a sibling root | `duplicate` or `overlaps` via the realpath key |
| `setHome` to a subfolder of the old home | `overlaps` (the old home would become a root containing the new home) |
| `project:delete` while sessions are running | they keep running and are standalone on the next `state` |
| `project:reorder` with duplicates / unknown ids | first occurrence wins; unknown ignored; missing appended |
| Root deleted while its session is inactive | noticed on the next `requestProject` for it, `term:start`'s scan, or restore |
| Root on an offline network share | stat rejects or times out on the libuv pool, and the root is marked missing. The main thread never blocks. |
| Many missing folders | poll is O(missing) every 5 s; zero cost when none (idle-fs-quiet holds) |
| Root with `&` on win32, command `claude` resolving to `.cmd` | skipped for `--add-dir`, warning logged; still attached everywhere else |
| Relaunch after `addRoot` | new PTY gets the new `--add-dir`; attach path (window move) keeps old args |
| `repoRoot` for a repo removed by a rescan | rejected with the failure shape; renderer re-requests on `state` |
| `openRepo.roots` includes home or a dup | dropped silently (logged). The session is still created. |

## 5. Defaults vs. settings

| Decision | Default | Configurable? | Rationale |
|---|---|---|---|
| New session's project | standalone (L3) | per call (`projectId`) | lock |
| Reconnect poll interval | 5 s, only while something is missing | no | same order as PlanWatcher's 2 s existsSync poll; zero idle cost |
| Merged repo cap | 200, home first | no | today's per-scan cap; bounds `state` size |
| `--add-dir` for non-claude | none | no | L5 |
| Project name max | 80 chars | no | fits a group header; reversible |
| Migration backup | `sessions.v1.bak.json`, once | no | cheap downgrade escape (D11) |

## 7. Acceptance criteria

### 7.1 EARS
- **E1** When the host starts with `restoreSessions` on and a v1 sessions.json, it shall write
  `sessions.v1.bak.json`, projects.json and sessions.json v2 before the first `state`. It shall
  also publish one project per distinct folder key, in first-seen order.
- **E2** While a session has `roots = []`, the host shall produce the same launch spec, repos
  (plus `folder`/`tag`), git root, watcher events and write-root decisions as before this item.
- **E3** When `session:addRoot` names a valid folder, the host shall append it, publish it, admit
  writes inside it, rescan repos with `tag:'attached'`, and emit `fsChanged {root}` for changes
  in it while its session is active.
- **E4** If an L3 message fails §3.3, then the host shall leave the model unchanged and, when
  `requestId` is present, reply `session:opResult {ok:false, reason}`.
- **E5** When a claude-matched session cold-starts, the host shall append `--add-dir <r>` for each
  present root, in `roots` order.
- **E6** When an attached folder disappears, the host shall publish it in `missingRoots` and drop
  it from scan, watcher and `--add-dir`. When the folder returns, the host shall clear it within
  one poll interval (≤ 5 s + debounce).
- **E7** When `project:delete` runs, the host shall make its sessions standalone without touching
  any PTY or folder.

## 13. Decisions Needed
- **D1 [normal]** Sidebar grouping during this item. Pick: keep grouping by `home` (renamed).
  `collapsedProjects` stays a path list, and mf-sidebar switches both to `projectId` per L10.
  Migrated sessions group identically either way. New sessions are standalone, so projectId
  grouping now would change today's UI.
- **D2 [normal]** Delete the vestigial `state.groups` / `ProjectGroupDTO` / both `groupByProject`
  instead of renaming them. Measured as unread except for a fallback.
- **D3 [high, extends L2]** Migration triggers on "sessions blob is v1", and uses deterministic
  `p-<sha1(folderKey)[:12]>` ids. The lock's trigger, "once when projects.json is absent", would
  make every session standalone after a crash between the two writes, or after a restore-off run
  wrote projects.json. The lock's own case behaves identically. Pick: extended trigger.
- **D4 [normal]** `requestProject` gains `sessionId`, and mf-model edits the 3 app.tsx posts. The
  watcher cannot know the active session's roots otherwise.
- **D5 [normal]** Missing home: `term:start` keeps today's `os.homedir()` fallback. The refusal
  and "Can't start" belong to mf-live-edits (renderer gate on `homeMissing`).
- **D6 [normal]** win32 metacharacter guard on `--add-dir` for non-`.exe` commands (a root is
  skipped and logged). Pick: skip, because it is safe against `cmd.exe` injection. The trade-off
  is that a folder named `R&D` isn't visible to claude. mf-live-edits may surface it.
- **D7 [normal]** Repeated `--add-dir` accumulates: ASSUMED from commander semantics and not
  measured against real claude. The e2e proves the argv only. Recommend a one-off manual check.
- **D8 [normal]** No upward detection of an enclosing repo. A folder inside a repo, but not at its
  root, shows no git for attached folders. For home, today's cwd fallback still applies.
- **D9 [normal]** Per-repo branch/dirty is **not** in the model. mf-changes owns its
  producer and consumer, for the branch chip on every repo header.
- **D10 [normal]** `multiRepoPicker=false` still yields `repos=[]`, so attached repos are hidden
  too. mf-changes decides whether the setting survives the picker's removal.
- **D11 [normal]** Current-behaviour claims marked ASSUMED in §2.7 were source-inspected, not
  run. The builder's red tests confirm them first. Downgrade loses sessions (backup mitigates).
- **D12 [normal]** Roots may not be a filesystem root (`C:\`, `/`). `openRepo.path` keeps
  allowing it (unchanged). An attached drive root would make the whole drive writable and one
  preview origin.
- **D13 [normal]** Overlapping folders are rejected (`overlaps`) rather than merged, which keeps
  invariant I2 simple. The trade-off: attaching a parent of an attached folder needs a remove
  first.
- **D15 [normal]** Roots are stored lexically. A symlinked or junctioned folder inherits today's
  home limit: writes inside it fail `validateWrite`'s realpath stage. Storing realpaths, or
  adding them to `writeRoots`, would change confinement. That is left alone (L6).
- **D16 [normal]** Added beyond L3 so the UI items don't reopen the model: `session:replaceRoot`,
  `setHome.keepOldHome`, `openRepo.requestId` → `openRepo:result`, the runtime `launchedRoots` /
  `skippedAddDirRoots`, and a 32-root cap. All are additive and optional.
- **D14 [normal]** `git:commitDiff.root`, the terminal-originated path, is left unvalidated as
  today. Validating it against `repos ∪ sessionGitRoot` is a separate hardening item. The new
  `repoRoot` fields are validated.
