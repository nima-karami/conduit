# Feature Spec: What's new for updates

**Tier:** LITE   **Feature type:** UI + update metadata + persisted first-launch notice

## 1. Problem and scope

The ready update card offers a relaunch action but does not explain what the update contains. Once
installed, the user also has no in-app way to see the release notes. This adds a single local source
of notes, a dialog reachable before and after installation, and a one-time post-update toast.

The `CHANGELOG.md` section for a version is the sole source of release notes. Notes are bundled
with the application and never fetched from the network.

## 2. Behavior

- The release workflow extracts the tagged version's changelog section and fails when it is absent
  or empty. GitHub releases and electron-updater metadata use those same notes; the GitHub release
  also links to the full compare changelog.
- The packaged application includes `CHANGELOG.md`. The host answers `getReleaseNotes` with the
  requested/current version's section. The renderer uses the existing safe Markdown renderer and
  external-link path. Remote images use the Markdown viewer's existing opt-in placeholder behavior;
  release notes do not load remote images automatically.
- When an update is ready and has notes, the update card adds a **What's new** button before
  **Relaunch to update**. The dialog is titled **What's new in v{incoming}**, shows **you have
  v{current}**, renders the notes, links to the GitHub release, and offers **Later** and
  **Relaunch to update**. Relaunch is available only while the update is ready. Escape and Later
  close the dialog. It uses the same opaque raised surface as other modal dialogs. While notes
  are open, the redundant update card is hidden and returns on close unless already dismissed;
  the shared toast/approval layer order remains as specified by overlay-layers.
- On the first launch after an upgrade, a **Updated to v{current}** toast offers **What's new** and
  dismiss. When a saved `lastSeenVersion` exists, show it only for a newer version with a bundled
  changelog section. An existing `settings.json` without this field is a legacy upgrade with an
  unknown previous version: show the toast when notes exist. A truly fresh install with no settings
  file records its version without showing a toast. Same-version launches, downgrades, prerelease
  versions, and missing notes show none. The installed dialog has no installed-version sub-line or
  relaunch action. `lastSeenVersion` is an optional migration-safe field in `settings.json`; persist
  it after the renderer acknowledges that the toast mounted, so a reload or early exit before
  display does not consume the notice. Opening **What's new** from the toast dismisses the toast.
- The status bar has a `data-status-item="update"` button while downloading or ready: **Updating ·
  {pct}%** with the existing percent formatter, or **Update ready**. It reveals the card while
  downloading and opens What's new when notes exist (otherwise it reveals the relaunch card) when
  ready. It is hidden for all other update states. Its label keeps its full width; machine,
  branch, worktree and command labels may ellipsize first, without hiding their items.
- The floating stack remains the shared notification outlet. Dialog links open externally; notes
  are sanitized; the dialog is labelled by its title; toast text uses a polite live region.

## 3. Acceptance

- Changelog parser handles missing versions, the last section, `[Unreleased]`, and CRLF.
- Release-note generation fails for a missing section, and packaged updater metadata carries the
  same Markdown section as the GitHub release.
- Ready card exposes What's new only when notes exist. Incoming and installed dialogs show their
  correct title/body/actions; Escape and Later close; GitHub links open externally.
- Post-update toast decision covers fresh install, legacy settings with no marker, same version,
  newer version, downgrade, prerelease, and no notes; a mounted-toast acknowledgement persists
  `lastSeenVersion`.
- Status item covers downloading, ready, hidden states, reveal/open actions, and narrow widths.
- Markdown containing executable HTML renders inert.
- E2E covers ready → What's new → dialog → Later and legacy settings without a marker → toast →
  acknowledgement persisted → What's new dismisses toast and opens installed dialog with bundled
  notes → renderer reload does not repeat the toast.
