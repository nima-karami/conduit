# Feature Spec: Auto-save (VS Code `files.autoSave` parity)

**Tier:** FULL   **Feature type:** UI
**Mode:** autonomous: no human in the loop. Would-be questions are assumptions (§12) or
flagged decisions (§13).
**One-line request:** "We also need the option to auto-save after modifying a file. Let's mirror
what VS Code already has."

## 1. Problem frame

- **Job:** stop losing edits and stop pressing Ctrl+S. Conduit sits next to agents that write
  files in the same tree, so an unsaved buffer is both a loss risk and a staleness risk: the agent
  reads the old disk file. Auto-save keeps disk ≈ buffer without the user thinking about it.
- **Actors:** the user editing in a code editor tab. A second actor: **an agent or external tool
  writing the same file**. That one is the reason auto-save must never overwrite silently.
- **Success outcomes (observable):**
  - With `afterDelay`, an edited file is on disk within `delay + one write` of the last keystroke,
    and the tab's unsaved dot clears.
  - With `onFocusChange` / `onWindowChange`, leaving the editor (or the window) writes it.
  - A file changed on disk underneath a dirty buffer is **never overwritten by auto-save**. The
    user gets a conflict banner and chooses.
  - `off` (the default) behaves exactly like today.
- **Non-goals:**
  - Hot exit / backup of unsaved buffers across restarts.
  - `files.autoSaveWhenNoErrors`, `files.autoSaveWorkspaceFilesOnly`, per-language overrides.
  - A diff/compare view for conflicts.
  - Proactive conflict detection before a save is attempted.
  - Format-on-save. It doesn't exist in Conduit (`grep formatOnSave` → none), so there's nothing to
    interact with.
  - Changing the plan editor, board, or architecture canvas. They already write through on their
    own debounce (`plan-store.ts`, `board-view.tsx:114`, `architecture-view.tsx:1478`), never enter
    the dirty store, and are **not governed by this setting**.

## 2. Behavior & states

### 2.1 Participating surfaces

Every surface that calls `registerSave`. Measured: `grep -rn "registerSave(" webview` hits
exactly one call site, `components/code-viewer.tsx:271`. `CodeViewer` is mounted by:

| Host | Where |
|---|---|
| Code file tab | `doc-view.tsx:257` |
| Markdown **source** view | `markdown-viewer.tsx:984` |
| HTML **source** view | `html-viewer.tsx:423` |

So auto-save lives **in `CodeViewer`** (plus a pure policy module) and covers all three for free.
Excluded even when dirty: `doc.binary` (never editable), and **`doc.truncated`** (> 2 MB; the
buffer holds only the first 2 MB, so writing it would truncate the file on disk — see D7).

### 2.2 Modes

Setting `autoSave: 'off' | 'afterDelay' | 'onFocusChange' | 'onWindowChange'`, plus
`autoSaveDelay` (ms, used only by `afterDelay`).

| Trigger | off | afterDelay | onFocusChange | onWindowChange |
|---|---|---|---|---|
| Edit (buffer becomes/stays dirty) | — | (re)arm timer for `delay` | — | — |
| Timer fires | — | save | — | — |
| Editor widget blurs (focus leaves Monaco, incl. to terminal, sidebar, palette) | — | — | save | — |
| Active tab switches away, or a markdown/HTML tab toggles from source to rendered view (both unmount `CodeViewer`) | — | **flush** pending timer → save | save | — |
| Window `blur` (app loses OS focus) | — | flush → save | save (D5) | save |
| Close tab while dirty | prompt (today) | save, then close (D2) | save, then close | save, then close |
| `beforeunload` / `pagehide` | best-effort save-all (today) | same, flush first | same | same |
| Manual Ctrl+S / Save All | save | save | save | save |

Notes:
- **Auto-save state lives in a per-path controller, NOT in `CodeViewer`'s editor effect.** That
  effect is keyed on `doc.content` (`code-viewer.tsx:549`), and `notifySaved` rewrites
  `doc.content` (`app.tsx:552`), so every save disposes and recreates the editor (C8). Timers,
  in-flight flag, conflict/failure state and the baseline the dirty flag was computed against
  are held in a **module-level store keyed by path** that outlives the editor. It is backed by the
  Monaco model (`monaco.editor.getModel(fileUri(path))`, never disposed). It is dropped when the
  doc is force-closed / `clearDirty`'d.
- **That controller is the path's save entry, and it stays registered while the tab is open, not
  only while it's mounted.** Only the active doc is mounted (`center-pane.tsx:430`,
  `key={activeDoc.id}`). Today a dirty background tab has no entry, so `closeDoc`'s Save
  force-closes it and loses the edits (`app.tsx:1677-1681`), and Save All skips it (C9). A
  model-backed entry fixes both for every mode, including `off`.
- **The flush trigger is the tab/view leaving, not an effect cleanup.** It fires from a cleanup
  keyed on `doc.path` only (or the tab switch itself), never from the `doc.content`-keyed
  effect. At that effect's cleanup `baselineRef` has already advanced to the new disk content
  (`code-viewer.tsx:137`, assigned during render). A flush there would see the old buffer as
  "dirty" and write stale text over an agent's change, and the precondition would pass.
- **Eligibility requires a user edit.** A path is auto-saved only after a content change since
  mount/last save, never on the seed dirty computation. If Monaco normalizes mixed EOLs on
  load (C10), a freshly opened file reads as dirty, and auto-save would otherwise rewrite files
  the user never touched.
- "Editor blur" means Monaco's `onDidBlurEditorWidget`, not `onDidBlurEditorText`. Focus moving
  into Monaco's own find/rename widget is not a focus change. Overflow widgets live in
  `monacoOverflowHost()` outside the editor DOM; the builder must confirm that focusing one
  (e.g. the rename input) doesn't fire a widget blur (C6).
- In `afterDelay`, the dirty dot shows during the delay window and clears on save (D4).

### 2.3 Per-file auto-save state machine (the pure policy module)

```
clean ──edit──▶ dirty ──trigger──▶ saving ──ok, buffer==written──▶ clean
                  ▲                  │  └─ok, buffer changed during write──▶ dirty (re-arm / trailing save)
                  │                  ├─fail (io/permission)──▶ failed ──edit / next trigger──▶ saving
                  │                  └─precondition mismatch──▶ conflict (auto-save PAUSED)
                  └────────── user: "Overwrite" (save w/o precondition) | "Reload" (adopt disk) ──┘
```

- **Single-flight + trailing.** At most one write per file in flight. A trigger while `saving`
  sets `resaveRequested`. When the write completes, if the buffer ≠ the new baseline, exactly one
  more save runs, still subject to the mode (in `afterDelay` the edit already re-armed the timer;
  the timer firing mid-flight becomes the trailing request). Edits during a write are never
  dropped: today's save already re-computes dirty against `model.getValue()` after the write
  (`code-viewer.tsx:245`).
- **`failed`:** no retry loop. Retry only on the next edit (afterDelay) or the next trigger
  (focus modes), or on manual save.
- **`conflict`:** auto-save for that path is **suspended** until the user resolves it. Edits keep
  the buffer dirty and don't write. **Every** non-forced save respects the pause: Ctrl+S, Save
  All, `beforeunload`, and save-on-close. None of them writes; they return `false` and surface
  the banner. Only the banner's **Overwrite** (forced save, no precondition) writes.
- **Reload from disk:** clear the path's dirty flag and controller state, then post a fresh
  `readFile`. The originally withheld `fileContent` is gone, and a dirty model is never re-seeded
  (`code-viewer.tsx:175`), so the order matters: clear first, then read.
- **Conflict/failure state survives unmount.** It's in the controller store, not component state
  (today `saveError` is `useState` and vanishes on tab switch). The banner re-renders when the
  tab is shown again, and the tab itself shows a conflict marker (§8).
- **Coalescing:** a burst of triggers in one tick (blur + tab switch + window blur) produces one
  save. The single-flight rule covers this.

## 3. Data / interface contract

**Settings (`src/settings.ts`, `AppSettings`):**
- `autoSave: AutoSaveMode`. Parse: any value outside the 4 literals → `'off'`.
- `autoSaveDelay: number`. Parse with `clampNum(…, 100, 60000, 1000)`, rounded to an integer.
  Persists through the existing settings pipeline (`settings.json` in userData, `settings-sync`).
  No migration: absent keys take defaults.

**Host write precondition (`writeFile` IPC, `electron/main.ts:4316` → `src/file-service.ts`):**
- New optional 3rd argument `opts?: { expected?: string }`. `expected` is the content the
  renderer last knew to be on disk (its baseline).
- With `expected`, the host does an **uncapped** read of the target and decodes it as utf8 (a
  BOM survives as `﻿`, matching `readFile`'s decode). It skips `readFile`'s 2 MB cap and its
  binary sniff; truncated/binary docs never reach this path. It then compares the result to
  `expected`:
  - equal → the existing atomic temp+rename write.
  - different → `{ ok:false, conflict:'changed', error }`, and nothing is written.
  - file missing → `{ ok:false, conflict:'deleted', error }`. Auto-save never recreates a
    deleted file (VS Code parity: orphaned editors aren't auto-saved).
- Without `expected`: today's behavior, byte for byte. Manual save and **Overwrite** go this way.
- The trust boundary is unchanged: `validateWrite` and read-grants run first, exactly as now.
- Race window between compare and rename: accepted. It's the same order as VS Code's mtime
  check.
- `WriteResult` gains `conflict?: 'changed' | 'deleted'`.

**`SaveEntry` (`save-registry.ts`):**
- `save(opts?: { kind?: 'auto' | 'manual' | 'force' }): Promise<boolean>`. `auto` sends the
  precondition and follows §2.3. `manual` (default) keeps today's unconditional write (D1) but
  refuses while the path is in `conflict`. `force` is Overwrite only.
- The entry is registered by the per-path controller (model-backed) for as long as the tab is
  open, not just while `CodeViewer` is mounted (§2.2 notes).
- A call while in flight **awaits the in-flight write and then re-saves if still dirty**, instead
  of returning `false` (fixes C4 for every caller).

**Pure module (new, unit-tested):** `webview/auto-save-policy.ts`. It holds the §2.3 machine as a
reducer, `(state, event, mode) → { state, effects: ('save'|'arm'|'clear'|'showConflict')[] }`, plus
`parseAutoSave` / `clampAutoSaveDelay`. No React, no Monaco, no timers (the timer is an effect the
caller runs, as with `makeDebouncedFlush`).

**Producers / consumers:**

| Data / state | Produced by | Consumed by | Both in scope? |
|---|---|---|---|
| `autoSave`, `autoSaveDelay` | Settings modal → `update()` → host persist | `CodeViewer` (reads live via ref), `closeDoc` (`app.tsx:1662`) | Yes |
| Write precondition / `conflict` result | Renderer `CodeViewer.save` | Host `writeFile` IPC + `file-service.writeFile` | Yes |
| Save entry (`save-registry`) | Per-path controller (was `CodeViewer`) | `closeDoc`, Save All, Ctrl+S, `beforeunload` | Yes |
| Auto-save/conflict state per path (new store) | Controller | `CodeViewer` banner, `doc-tabs` conflict marker | Yes |
| `notifySaved(path, content)` | Controller save (also for unmounted tabs) | `app.tsx:552` files map (which recreates a mounted editor, C8), `refreshIndexedFile` | Yes. Module stores only, safe after unmount. |
| `fileChanged` self-echo after our write | Host watcher | `app.tsx:485` → `readFile` → `fileContent` | Yes. The echo carries the same content as `notifySaved`, so `doc.content` is unchanged and no editor re-seed happens. If the user typed meanwhile, the path is dirty and the echo is withheld. |
| Save-error banner / toast | `CodeViewer.fail` | User | Yes (§4 throttle) |

## 4. Edge cases & failure modes

| Condition | Expected behavior |
|---|---|
| Edit during an in-flight write | Stays dirty. One trailing save after the write completes. Nothing dropped, no parallel writes. |
| Blur + tab switch + window blur in one tick | One write (single-flight). |
| Rapid typing in `afterDelay` | Timer resets on every edit. One write per pause, not per keystroke. |
| Type, then undo back to baseline | Buffer == baseline → clean → timer cleared, no write. |
| Agent/external tool rewrites the file while buffer is dirty | Auto-save hits the precondition → **conflict banner**; disk untouched; auto-save paused for that path. |
| File deleted on disk while dirty | `conflict:'deleted'` → banner "deleted on disk"; **Overwrite** recreates the file, **Close** discards. |
| External change while buffer is **clean** | Today's reload path (`fileContent` replaces content); no conflict. |
| Write fails (EACCES, read-only FS, path outside roots, disk full) | Stays dirty. The existing banner shows. Toast **only on the first failure of a streak** per path (D10). No retry until the next edit/trigger. |
| Browser preview (no `window.agentDeck`) | `canSave` is false. Auto-save is a **no-op** there: no toast storm. The mode is still selectable. |
| `truncated` / `binary` doc | Never auto-saved. The dirty dot and manual save stay as today (D7). |
| Close tab while dirty, auto-save on | Save with precondition → close on success. On failure or conflict → today's Save/Discard/Cancel prompt, with the conflict/failure reason in the message. |
| Close others/all (loops `closeDoc`, `app.tsx:2340-2368`) with dirty tabs, auto-save on | Each `closeDoc` saves silently and closes. Only failures prompt. Today each `setConfirm` replaces the previous one, so only the last prompt shows; that's pre-existing, and auto-save makes it rarer. Not fixed here. |
| Same file open in two windows | Each window has its own model; the watcher broadcasts to both. A clean window reloads; a dirty one hits the precondition → conflict. No clobber either way. |
| External change while a clean tab is mounted | `doc.content` changes → the editor re-seeds; no flush fires (flush is keyed on `doc.path`, eligibility needs a user edit), so the agent's change is never reverted. |
| Mode switched from `off` with buffers already dirty | Nothing is written retroactively. The next edit (afterDelay) or trigger (focus modes) saves them. |
| Mixed-EOL file opened, no edit | Not auto-saved (eligibility requires an edit; C10). |
| Quit / window close within `delay` of an edit | Window `blur` usually fires first and flushes. Otherwise best-effort `beforeunload`/`pagehide`. **A guaranteed flush is out of scope** (D3). |
| Delay input: empty, non-numeric, < 100, > 60000, decimal | The field shows an inline error and keeps the last valid value. The parser clamps anything persisted. |
| Mode changed while timers are armed | → `off`: clear timers, leave buffers dirty. → another mode: clear timers, and the next trigger of the new mode applies. |
| Delay changed while a timer is armed | The new delay applies from the next edit; the armed timer keeps its deadline. |
| Rename/move of an open dirty file | Today this discards unsaved edits (C11). With auto-save ≠ off, the controller for the old path is **flushed (auto kind) before `dropDocsFor`**. On failure/conflict, the existing rename proceeds and the edits are lost, same as today (D11). |
| Many dirty files flushed on window blur | One write per path, in parallel. Failures are aggregated into one toast ("Could not save N files"), as in Save All. |

## 5. Defaults vs. settings

| Decision | Default | Configurable? | Rationale |
|---|---|---|---|
| Mode | `off` | Yes (4 modes) | VS Code default. No behavior change on upgrade. |
| Delay | 1000 ms | Yes, 100–60000 | VS Code default. The floor stops a 0 ms write-per-keystroke storm. |
| Show dirty dot during delay | Shown | No | Honest state; it clears within ~1 s (D4). |
| Conflict policy | Pause + banner | No | Never clobber; agents write the same files. |
| Scope | All `CodeViewer` hosts | No | One code path. Per-language scoping is out of scope. |
| Close-dirty with auto-save on | Save silently | No | VS Code parity (D2). |

## 6. Scope slicing

- **MVP:** settings + UI; `afterDelay`, `onFocusChange`, `onWindowChange`; unmount flush; policy
  module; write precondition + conflict banner (Overwrite / Reload from disk); single-flight save
  (C4 fix); save-on-close; failure toast throttle; truncated/binary exclusion.
- **v1:** a guaranteed pre-quit flush (the host asks the renderer to flush dirty docs before
  `before-quit` teardown, reusing the `confirmQuit` round-trip shape). Command-palette
  "Toggle Auto Save" (VS Code has **File → Auto Save**).
- **Vision:** the precondition for manual save too, with a compare view; hot exit.
- **Out of scope:** the §1 non-goals, and Save All skipping unmounted dirty tabs (pre-existing,
  ASSUMED; with auto-save on it only arises after a failed save).

## 7. Acceptance criteria

The e2e runs on `test/e2e/harness.mjs` (hidden window). Suggested scenario: `auto-save.e2e.mjs`.
The disk is asserted with `fs.readFileSync` in the test process. Keystrokes are real `keyboard`
input into Monaco.

**Unit (pure):** `auto-save-policy` reducer (every §2.3 transition, the §2.2 matrix per mode,
single-flight + trailing, conflict suspends, failure doesn't re-arm); settings parse/clamp;
`file-service.writeFile` precondition (equal / changed / missing / BOM file / absent `expected` ⇒
unchanged behavior).

**EARS**
- **E1 (Ubiquitous):** The editor shall never have more than one write in flight per file.
- **E2 (State):** While `autoSave = off`, the editor shall behave exactly as before this change
  (no automatic writes; close-dirty prompts).
- **E3 (Event):** When `afterDelay` is set and the user stops editing a dirty file for
  `autoSaveDelay` ms, the editor shall write the buffer and clear the unsaved dot.
- **E4 (Event):** When `onFocusChange` is set and focus leaves the editor, or its tab is switched
  away, the editor shall write the dirty buffer.
- **E5 (Event):** When `onWindowChange` (or `onFocusChange`/`afterDelay`) is set and the window
  loses focus, all dirty participating buffers shall be written.
- **E6 (Unwanted):** If the file's disk content differs from the buffer's baseline when an
  auto-save runs, then the editor shall not write, shall show the conflict banner, and shall
  suspend auto-save for that file until the user resolves it.
- **E7 (Unwanted):** If an auto-save fails, then the buffer shall stay dirty, the banner shall
  show the reason, and no automatic retry shall occur until the next edit or trigger.
- **E8 (Event):** When a dirty tab is closed with auto-save on, the editor shall save and close
  without a prompt. If that save fails or conflicts, it shall fall back to the Save/Discard/Cancel
  prompt.
- **E9 (Ubiquitous):** A `truncated` or `binary` document shall never be auto-saved.

## 10. Accessibility & i18n (UI)

- Keyboard: every control above is operable without a pointer. Focus isn't moved by an auto-save.
  The conflict banner doesn't steal focus from the editor; it's announced instead.
- Announcements: the conflict banner is `role="alert"`, and so is the save failure (existing
  banner + toast). A **successful** auto-save announces nothing. It happens constantly and would
  flood a screen reader; the dot clearing is the visual signal, as with manual save today.
- Colour: the conflict banner carries text plus a warning icon, not colour alone. The dot's
  existing `aria-label="Unsaved"` stays.
- Visible focus on the new field uses the existing focus ring token; forced-colors is inherited.
- i18n: Conduit has no string externalization layer (all copy is inline today). New strings go in
  one `AUTO_SAVE_COPY` const, next to the existing pattern (`html-viewer.tsx:43`), not scattered
  through JSX. The file count in the aggregate toast uses the existing `file${n===1?'':'s'}`
  pattern. Mode labels: "Off", "After delay", "On focus change", "On window change". The delay is
  shown as a plain integer, not locale-formatted, because it's an input value. The layout must
  tolerate the longest label, "On window change", at +30%.
- RTL: not supported app-wide; nothing new.

## 11. Design tokens (UI)

No new tokens. The conflict banner reuses the `.plan__conflict` / `.viewer__banner` warning roles.
The field reuses the settings input surface, border and focus-ring tokens. It must render in all
three themes (`npm run shots` covers the settings modal).

## 12. Assumptions

- A1: VS Code semantics taken as: default `off`, `afterDelay` 1000 ms, focus-change saves on
  editor/tab switch, window-change saves on window blur. Stated from memory; not checked against
  the VS Code source.
- A2: VS Code doesn't auto-save orphaned (deleted-on-disk) editors, and it surfaces "file is
  newer" as an error rather than overwriting. Mirrored here as the precondition.
- A3: VS Code closes a dirty editor without prompting when auto-save ≠ off (it saves). ASSUMED
  (D2).
- A4: Untitled buffers don't exist in Conduit, so VS Code's "untitled isn't auto-saved" rule is
  moot.
- A5: The setting is global (per user), not per project, like every other editor setting.
- A6: Placement is Settings → Appearance section "Editor & code" (`appearance-sections.ts:62`),
  the only editor-settings section (D9).

## 13. Decisions Needed

- **[high] D1 — Write precondition scope.** Auto-save carries an `expected` baseline and the host
  refuses on mismatch. This changes the `writeFile` IPC at a trust boundary. Manual Ctrl+S is
  **left unconditional** (today's behavior) so the change stays additive. VS Code checks manual
  saves too. *Default taken:* precondition on auto-save and save-on-close only. Manual save
  unchanged.
- **[normal] D2 — Close-dirty with auto-save on** saves silently in all three non-off modes, and
  falls back to the prompt on failure/conflict. *Default:* as stated.
- **[normal] D3 — Quit/window-close flush.** No host→renderer flush exists for dirty files (C5).
  An edit made < `delay` before quit, with no window blur in between, can be lost; that's
  strictly better than today, where every unsaved edit is lost. *Default:* MVP relies on window
  blur plus best-effort `beforeunload`/`pagehide`; a guaranteed pre-quit flush is v1.
- **[normal] D4 — Dirty dot during the `afterDelay` window.** VS Code hides it for short delays.
  *Default:* keep showing it (honest, zero extra logic).
- **[normal] D5 — `onFocusChange` also saves on window blur.** Believed to match VS Code;
  unverified. *Default:* yes (superset, safer).
- **[normal] D6 — Delay bounds 100–60000 ms.** VS Code has no documented minimum. *Default:* clamp
  as stated.
- **[normal] D7 — Truncated (> 2 MB) buffers are excluded from auto-save.** The underlying hazard
  (a manual save truncates the file on disk, C7) is pre-existing and **not fixed here**; it
  deserves its own item. *Default:* exclude, don't fix. **Since fixed (branch
  `fix/file-integrity`):** a truncated doc opens read-only and the store refuses every save of it,
  manual included (E9 tightened accordingly).
- **[high] D11 — Save-entry ownership moves from `CodeViewer` to a model-backed per-path
  controller** that stays registered while the tab is open. This is forced by C8 (the editor is
  recreated on every save) and C9 (background dirty tabs are unsaveable). It also changes
  behavior in `off` mode: Save All and close→Save now work for background tabs. A rename with a
  failed flush still loses edits (pre-existing C11). *Default:* do the move; the rename-loss fix
  is out of scope. **Since fixed (branch `fix/file-integrity`):** a rename or move retargets the
  open tab and moves its store entry (`FileSaves.rename`), so no flush is needed and no edit is
  lost. C11 was also never reached: the explorer spells paths with `/`, tabs with `\`, so the
  rename handler never matched an open tab at all.
- **[normal] D8 — Current-behavior claims C2–C11 are ASSUMED** from source reading. The builder
  measures them before building on them. If C4, C5, C8, C9 or C10 measures false, drop the part that
  depends on it.
  *Default:* build as specified.
- **[normal] D9 — Settings placement:** the "Editor & code" appearance section, even though
  auto-save isn't an appearance setting. *Default:* put it there; moving it is cheap.
- **[normal] D10 — Failure toast throttling:** a toast only on the first failure of a streak per
  path (reset on a successful save); the banner is always shown. *Default:* as stated.
