# Feature Spec: mf-files — Files tab, search and quick open across a session's folders (9b, 12c-left, 12d-left, 12g, 12h, 12j)

**Tier:** FULL   **Feature type:** UI (right-pane Files tab, Search pane, quick open, explorer
drop/context menus) plus a renderer index change. No new host message: pickers use mf-new-session's
`folder:pick`, Locate uses mf-live-edits' `folder:locate`.
Autonomous mode. Builds on `.autoloop/locked.md`: L1 (`home`, `roots`, `missingRoots`, `homeMissing`),
L3 (`session:addRoot/removeRoot/setHome`), L6 (watcher over home + every present root, `fsChanged {root}`),
L9 (missing folders excluded from search). Design: `.autoloop/handoff/README.md` §9b, §12c, §12d, §12g,
§12h, §12j; screenshots `9b-files-tab`, `12c-edit-folders`, `12d-missing-folder`, `12g-attach-explorer`,
`12h-search`; copy taken verbatim from both `.dc.html` files.

**Owned elsewhere:** the Changes tab content and its count (mf-changes); the New session dialog and its
own `+ Add folder…` (mf-new-session); the terminal banner after a folder change and the missing-HOME
centre state (mf-live-edits); the host data model, validation, watcher and missing detection (mf-model).

## 1. Problem frame

- **Job:** in a running session with a home folder and attached folders, browse, create, search and
  quick-open files in **every** folder from one pane, and add, remove, re-home or re-locate folders
  without starting a new session.
- **Actors:** the user; the running agent (writes files → watcher → tree refresh); the host (source of
  truth for `home`/`roots`/`missingRoots`).
- **Success outcomes (observable):** one `files__bar` + tree per folder, home first; a dashed
  `+ Add folder…` ends the list; `···` menu acts on that folder; a missing attached folder shows the warn
  box and returns by itself; an OS folder dropped from outside the session's folders offers
  `Attach to session` by default; Search in files groups by folder then file; quick-open rows carry a
  folder tag only when the session has >1 folder; go-to-definition resolves inside attached folders.
- **Non-goals:** Changes/Review/History (mf-changes, mf-review); the new-session dialog; the terminal
  banner; the missing-home centre pane; per-folder `.conduit/` (L7: ignored); preview-protocol
  confinement changes (L6); multi-select across folders; sticky folder bars; reordering attached folders.

### 2.2 Folder list

- Order: `home`, then `roots` in stored order (L1). Each folder renders a **section**: `files__bar`, then
  either its tree, its collapsed state (bar only), or — when missing — the warn box (§2.5).
- **Layout (D2):** sections stack in one vertical scroller (`right__scroll--files`); bars scroll with the
  content (not sticky). Each section's tree is its own `role="tree"`, windowed against the shared
  scroller's viewport: a section's window uses `scrollTop − section.offsetTop` (measured in a layout
  effect on scroll and on a ResizeObserver per section, so warn boxes, collapsed sections and drafts of
  any height feed in). Rows stay direct keyed children (`flatMap`, CLAUDE.md). The pane sums every
  section's counts into `window.__conduitFilesPerf`. Selection, roving focus and inline drafts are
  **per section**; clicking a row in another section starts a new selection there. Drag set, in-app
  cut/copy clipboard, conflict prompt, `committing` lock and undo are **pane-wide**, so moving or pasting
  between folders works (both are write roots, L6).
- **Keys:** every per-folder map (sections, `treeCache`, search replies, quick-open results,
  `indexedRoots`) is keyed by mf-model's folder key (the pure normaliser behind L1's win32
  case-insensitive dedupe), never by the raw string.
- The list ends with a dashed full-width button `+ Add folder…` (accent text). Shown in single-folder
  sessions too. It is not a drop target.
- A single-folder session shows exactly one bar tagged `Home` plus `+ Add folder…`.
- **Home missing:** its section is the warn box (§2.5); attached sections render and work normally;
  search, quick open and indexing run over the present attached folders; compiler options stay as last
  applied.

### 2.3 `files__bar`

Left: `IconFolder`, folder display name (title = full path), tag `Home` (`--accent` text on
`--accent-soft`, as mf-changes' repo head) or `Attached` (neutral). Right, in order: **collapse**
(chevron), **refresh**, **new file** (`IconPlus`), **new folder** (`IconFolder`), **`···`** (`IconMore`).
Right-click on the bar opens the same `···` menu.

- **Collapse (D3):** toggles the section. Collapsing also collapses every subfolder (subsumes today's
  "Collapse all"); expanding shows the top level. Chevron rotates; `aria-expanded` reflects it.
- **Refresh:** re-reads that folder's root + expanded dirs (today's `refreshAll`, scoped).
- **New file / New folder:** as today, targeting the section's create target (the anchored dir in that
  section, else the folder root). Titles/labels as today (`New file at root` / `New file in <dir>`).
- **Display name:** basename; when two session folders share a basename, both show
  `name` + faint ` — <parent segment>` (D15, same rule as mf-changes). The same display name is used in
  search groups and quick-open tags.
- **Git dots (D13):** the row change map is keyed by normalised **absolute** path. Source: mf-changes'
  `repoChanges[]` when present (abs = `root` + change path), else today's `changes` resolved against the
  git root they belong to. A row under no repo in that data gets **no** dot, never a lookup relative to
  another folder's root.

### 2.4 `···` menu (ContextMenu primitive, portal-to-body)

| Item | Shown | Action |
|---|---|---|
| Make home | attached folders; disabled with title `Folder not found` while missing | `session:setHome {sessionId, path}`. On the next `state` that folder is first, tagged `Home`; the old home is **appended** to `roots` (mf-model §2 `setHome`), so it shows last, tagged `Attached`. Running terminals keep their cwd (L3). |
| Reveal in Explorer | all | existing `revealInExplorer {path}` |
| Copy path | all | existing clipboard path; announce `Copied path` |
| Remove from session (danger, separator before) | attached only; **never on home** | See below. Disk untouched. No confirm (D9). |

**Remove:** if any dirty editor tab lives under the folder, Remove is refused with a toast
`Save or close <n> unsaved file(s) in <name> first.` (D16). Otherwise it posts
`session:removeRoot {sessionId, path, requestId}` and shows an info toast `Removed <name> from session`
(default toast lifetime) with action `Undo`. Undo posts `session:addRoot` for the **captured** sessionId
and path (re-added at the end). There is no `Undo` when the removed folder was missing, because addRoot
would reject a path that doesn't exist.

No optimistic UI: sections follow `state.sessions[active].home/roots/missingRoots`. The folder change is
all this item emits; mf-live-edits reacts to the resulting roots delta.

### 2.5 Missing folder (12d left): consumes `missingRoots` / `homeMissing` (L1, L9)

In place of the bar + tree: a dashed warn box (§11 tokens): folder name (warn text) + tag `Not found`;
the full path in mono; buttons `Locate…` (primary, warn fill) and `Remove` (neutral).
- `Remove` = §2.4 Remove (no Undo).
- `Locate…`: `folder:locate {sessionId, path, requestId}` (mf-live-edits §2.7, the one host handler both
  surfaces share; it opens the picker at the nearest existing ancestor). It replaces the folder **in place**. `folder:locateResult` failures toast per mf-live-edits §3.3; `cancelled` is silent.
- When the folder returns (mf-model's 5 s reconnect poll drops it from `missingRoots`), the box turns
  back into bar + tree, restored from `treeCache` and re-read. No user action.
- **Missing home (D10):** same box, tag `Home`, `Locate…` only (no Remove). The centre-pane state is
  mf-live-edits'; both call the same `folder:locate`.
- Missing folders are excluded from search, quick open, indexing and readDir (L9).

### 2.6 Add folder… (running session)

Click → `folder:pick {requestId}` → on a path: `session:addRoot {sessionId, path, requestId}`. The new
section appears at the end when `state` arrives, expanded, and focus moves to its collapse button;
announce `Attached <name>`. A `session:opResult {ok:false, reason}` shows an error toast (D4):

| reason (mf-model §3.3) | Copy |
|---|---|
| `duplicate` | `<name> is already in this session.` |
| `overlaps` | `<name> overlaps a folder already in this session.` |
| any other | `Couldn't add <name>.` |

Picker cancel: nothing.

### 2.7 Dropping from outside (12g)

On an OS drop onto any section (row, bar, empty space):
1. **Synchronously inside the `drop` event** (DataTransfer items go dead after it): capture each path
   (`getPathForFile`) and `webkitGetAsEntry()?.isDirectory`. Entries where that is `null` are resolved
   afterwards with mf-new-session's `folder:probe` (exists/isDir). A pure mapper
   `(item-like[]) → {path, isDir | null}[]` is unit-tested.
2. **Eligible folders** = `topLevelPaths` of the dropped dirs that are not equal to, inside, or
   containing any of **this session's** folders (D5, D4).
3. No eligible folder → today's import (copy into target), unchanged.
4. ≥1 eligible folder → a drop-intent menu at the drop point (ContextMenu primitive): `Attach to session`
   (default, focused and highlighted), `Copy into <target>/`, `Cancel`. `<target>` = the drop target
   folder's name (row folder or section root). While it is open a separate `dropMenuOpen` guard refuses
   another OS drop; rename, paste and internal drags are unaffected.
   - `Attach to session`: each eligible folder → `session:addRoot {requestId}`, serially; dropped files
     and ineligible folders copy into the target (D17). Failed attaches are **not** copied; one error
     toast lists them (`Couldn't attach <a>, <b>`). Announce `Attached <n> folder(s)` for the successes.
   - `Copy into <target>/`: today's import of everything.
   - `Cancel` / Esc / click-away / session switch: nothing.
5. The existing `committing` lock blocks a drop while a copy batch runs.

### 2.8 Open as new session (12g right)

Explorer folder-row menu item unchanged in position. When `projectForNewSession(active, projects)`
(mf-sidebar) yields a project, the item gets `hint: in <project name>`. It opens New session with the
mf-new-session prefill `{home: dir}`; the dialog derives the same project, so hint and chip agree.

### 2.9 Search in files (12h left)

- Scope = every **present** folder of the active session (not the live cwd, D1). Placeholder, the
  `Aa W .*` toggles, include/exclude and debounce unchanged; include/exclude apply inside each folder.
- One `contentSearch {requestId, root, query}` per folder, all sharing one `requestId` (D11). The pane
  keeps a per-root result map (replacing today's single `results`); `searching` stays true until every
  folder has replied. Replies with a stale id or a root no longer in the session are dropped. Results
  render as they arrive.
- With >1 folder: summary `N results in M files · K folders` (K = folders with ≥1 result); groups per
  folder in folder order (heading: display name + result count), then today's file groups inside
  (path relative to that folder). With one folder: today's rendering exactly.
- Per-folder `truncated` / `error` show as a one-line note under that folder's heading; on the watchdog,
  folders that haven't replied get today's `Search timed out. Try again.` note while arrived results stay.

### 2.10 Quick open (12h right)

- Corpus = `searchFiles` per present folder, cached per folder key (replacing today's single `search`
  state). On palette open, request every present folder not yet cached; `addRoot`/locate make the new
  folder uncached; entries of folders that left the session are dropped. Ranking unchanged
  (`src/omni-search.ts`, path relative to its folder).
- **Tag:** only when the active session has >1 folder, each file row shows a trailing pill with its
  folder display name (home: accent tint; attached: neutral); title = full path. One folder → rows
  identical to today.

### 2.11 TS index and language servers (12j)

- On activation (after today's 1.5 s delay): `indexProjectOnce(home)`, then each present root, in folder
  order. On `addRoot`/locate for the active session: index the new folder. On file open: index the session
  folder that contains the file (longest prefix), else home.
- **Compiler options come from home (D8):** `ts-project.ts` caches each root's `tsconfig` from its seq-0
  chunk and holds an *options root*. The renderer sets it to the active session's home on activation and
  on a home change; setting it applies that root's cached tsconfig (if any, compared before
  `setCompilerOptions`, as today); a seq-0 chunk applies options only when its root is the options root.
  This fixes the once-guard staleness on session switch and after Make home. extraLibs keep going
  through batched `addExtraLib`; not purged on remove.
- Incremental re-index on `fsChanged {root}` works per folder as today.
- Language servers and per-folder trust follow L6 (`writeRoots` feeds `lsp-root` and trust); no work
  here beyond one e2e check in §7.3.

### 2.12 cwd-following (D1)

The Files tree, Search in files and quick open show the session's folders only. `cd` in the terminal no
longer re-roots the tree. `session.cwd` / `trackCwd` keep driving what they drive today outside this item
(launch cwd L5, git-root fallback). No auto-attach of a cwd outside every folder.

### 2.13 Pane-level empty state (D12)

`No project open` and `No active project` are removed (every session has a home). With **no active
session**, the pane shows `No session` / `Start a session to see its folders here.`.

## 3. Data / interface contract

### 3.1 Renderer inputs
`Session.home`, `roots`, `missingRoots?`, `homeMissing?`, `projectId?` (L1); `state.projects` (L2);
`fsChanged {root}` (L6); `session:opResult {requestId, ok, reason?}` (mf-model §3.2); `repoChanges?`
(mf-changes); `dirEntries`, `contentSearchResults {requestId, root, …}`, `searchResults {root, …}`
(unchanged shapes).

### 3.2 Messages (D6): none new
- **From mf-new-session:** `folder:pick {requestId}` → `folder:picked {requestId, path | null}`, with its
  e2e seam `global.__pickDirHook.queue(paths: (string|null)[])` under `CONDUIT_E2E=1` (`null` = cancel).
- **From mf-model:** `session:addRoot`, `session:removeRoot`, `session:setHome`, each sent with
  `requestId` so failures come back as `session:opResult`.
- **From mf-live-edits:** `folder:locate {sessionId, path, requestId}` → `folder:locateResult
  {requestId, ok, path?, reason?}`. The host owns the picker, the in-place replacement and validation.
  Its test seam is mf-live-edits' (a `dialog.showOpenDialog` stub via `app.evaluate`); this item's e2e
  uses that for Locate and `__pickDirHook` for Add folder (D6).

### 3.3 Renderer seam for OS drops (D7)
`window.__conduitOsDrop({ items: {path, isDir}[], targetDir, x, y })` enters §2.7 at step 2, the same
function the real `onDrop` calls after step 1. Installed only when the host reports e2e mode (`about.e2e`,
set from `CONDUIT_E2E=1`), because unlike the read-only `__conduit*` probes it can widen `writeRoots`.

### 3.4 Invariants
- Sections always equal `[home, ...roots]` from the latest `state`; the renderer holds no list of its own.
- No search, quick-open, index or readDir request targets a missing folder. Proven by unit tests on the
  pure request builders (inputs: session with `missingRoots`), not by an e2e negative.
- `treeCache` is keyed by folder key, so a folder shared by two sessions shares expansion.

### 3.5 Producers / consumers

| Data / state | Produced by | Consumed by | Both in scope? |
|---|---|---|---|
| `home`/`roots` changes (add/remove/setHome/locate) | this item (UI) → mf-model host; locate → mf-live-edits host | Files sections, search, quick open, index (here); terminal banner (mf-live-edits); Changes (mf-changes) | Producer UI yes; host sides are mf-model (locked) and mf-live-edits (`folder:locate`). Consumers read the roots delta; nothing new is required of them |
| `missingRoots` / `homeMissing` | mf-model (L9, 5 s poll) | warn box (here), centre state (mf-live-edits) | No: producer locked in L9; read-only here |
| `fsChanged {root}` per folder | mf-model watcher (L6) | per-section refresh + incremental index (here) | No: locked, today's shape |
| Git dots | mf-changes `repoChanges[]` / today's `changes` | tree rows (here) | No: pinned shape in mf-changes §3; D13 rule keeps wrong dots impossible if it's absent |
| `NewSessionPrefill {home}` | explorer menu (here) | New session dialog (mf-new-session) | No: shape pinned by mf-new-session §3.1 |
| contentSearch replies per root | host (unchanged) | grouped search (here) | Yes |
| extraLibs + tsconfig per folder | host `indexProject` (unchanged) | TS worker via `ts-project.ts` (here) | Yes |

## 4. Edge cases & failure modes

| Condition | Expected behavior |
|---|---|
| Double-click `+ Add folder…` | Host dialog is modal to the window; a second `folder:pick` while one is open is ignored host-side (mf-new-session). |
| Second OS drop while the drop menu is open | Refused by `dropMenuOpen`. |
| Folder already in session / overlapping | Picker: `opResult` toast (§2.6). Drop: not eligible, so today's copy. |
| Dropping `A` and `A/sub` together | `topLevelPaths` keeps `A` only. |
| Partial attach failure | §2.7: one toast naming the failures; they aren't copied. |
| 0 attached folders | One `Home` bar + `+ Add folder…`; search/quick open identical to today. |
| Many folders (10+) | No cap; each section windowed; mounted rows stay bounded. |
| Folder removed while a search or index is in flight | Reply for that root dropped; group disappears; `searching` stops waiting for it. |
| Folder deleted from disk while expanded | Host marks missing → warn box; cache kept; returns → tree restored. |
| Two folders with the same basename | Disambiguated display names (§2.3). |
| Reveal a file in a collapsed or other section | That section expands and reveal walks its ancestors; file outside every folder → no reveal (as today). |
| Session switch while the drop menu or a toast is up | Menu closes (Cancel); Undo still targets the captured session. |
| Dirty tabs under a folder being removed | Remove refused with toast (D16). |
| Locate picks a folder already in the session | `opResult` toast; box stays. |
| Undo after the folder was re-added some other way | `duplicate`; no toast (silent on Undo). |
| Home missing | §2.2 "Home missing". |

## 5. Defaults vs. settings

| Decision | Default | Configurable? | Rationale |
|---|---|---|---|
| Section expanded on first show | expanded | no | matches 9b |
| Section collapse persisted | renderer memory (treeCache), per folder key | no | today's expansion isn't persisted either |
| Drop menu default | `Attach to session` | no | 12g |
| Remove confirm | none; Undo toast | no | reversible, disk untouched |
| Quick-open tag | only when >1 folder | no | 12h |
| Compiler options source | active session's home | no | one global options set per Monaco |

## 6. Scope slicing

- **MVP:** §2.2–2.6, §2.9, §2.11, §2.12, §2.13 (Locate needs mf-live-edits' `folder:locate`; until it lands the button is hidden).
- **v1:** §2.7 drop intent, §2.8 hint, §2.10 tags, basename disambiguation.
- **Vision:** sticky folder bars; reorder folders by drag; cross-folder multi-select; reveal the live cwd

- **Out of scope:** everything in §1 non-goals.

## 7. Acceptance criteria

### 7.1 EARS
1. The Files tab shall render one `files__bar` per session folder in the order `home, ...roots`, each
   followed by its tree, and end with a `+ Add folder…` button.
2. The home bar shall carry the tag `Home`; attached bars `Attached`.
3. When the user chooses `Remove from session` on an attached bar with no dirty tabs under it, the system
   shall post `session:removeRoot`, remove the section when `state` arrives, and show a toast with `Undo`
   that re-attaches the folder to the same session.
4. The home bar's `···` menu shall not contain `Remove from session`.
5. When the user chooses `Make home` on an attached folder, the system shall post `session:setHome`, and
   the next `state` shall show that folder first tagged `Home` and the old home last tagged `Attached`.
6. While a folder is in `missingRoots`, its section shall show the warn box (name, `Not found`, path,
   `Locate…`, `Remove`), and the request builders shall exclude it.
7. When a missing folder reappears on disk, the section shall return to bar + tree within 10 s with no
   user action.
8. When the terminal `cd`s to another directory, the Files sections shall not change.
9. When an OS drop contains an eligible folder, the system shall show the drop-intent menu with
   `Attach to session` focused, then `Copy into <target>/`, then `Cancel`.
10. If a drop contains no eligible folder, then the system shall import it exactly as today (no menu).
11. While the session has >1 folder, Search in files shall group results by folder then file and the
    summary shall end `· K folders`; with one folder it shall render as today.
12. While the session has >1 folder, every quick-open file row shall carry its folder tag; with one folder
    no row shall carry a tag.
13. When a session becomes active or its home changes, compiler options shall come from its home's
    tsconfig, and a chunk from an attached folder shall not change them.
14. Where `projectForNewSession` yields a project, the explorer `Open as new session` item shall show
    `in <project name>`.
15. If `session:addRoot` or `folder:locate` fails, then the system shall show the §2.6 / mf-live-edits toast and
    leave the sections unchanged.
16. If a folder's search reply errors, is truncated or times out, then the system shall show that note
    under that folder's heading and keep the other folders' results.
17. If the user removes a folder that has dirty tabs under it, then the system shall refuse with the
    D16 toast and post nothing.
18. `__pickDirHook` and `window.__conduitOsDrop` shall exist only under `CONDUIT_E2E=1`.

### 7.2 Gherkin (key flows)

```gherkin
  Scenario: Cancel the picker

  Scenario: Remove and undo

    Then only the "rmb" bar remains and a toast offers "Undo"
    When I click "Undo"
    Then "ci-image" is back, tagged "Attached"

  Scenario: Make home
    When I choose "Make home" on "ci-image"
    Then "ci-image" is first, tagged "Home", and "rmb" is last, tagged "Attached"

  Scenario: An attached folder goes missing and comes back
    When "ci-image" is deleted on disk
    Then within 10 s its section shows "Not found", its path, "Locate…" and "Remove"
    When it is recreated
    Then within 10 s its bar and tree return

  Scenario: Locate a missing folder
    Given "ci-image" is missing and the picker will return "ci-image-moved"
    When I click "Locate…"
    Then the second section is "ci-image-moved" tagged "Attached"

  Scenario: Attach by dropping
    When a folder "api-contracts" from outside the session is dropped on the tree
    Then the menu shows "Attach to session" focused
    When I press Enter
    Then "api-contracts" is attached and nothing is copied

  Scenario: Dropping a file only
    When a file from outside is dropped on the "rmb" bar
    Then no menu appears and the file is copied into "rmb"

    Given a session with only home "rmb"
    Then no quick-open file row carries a tag
```

### 7.3 Tests
- **Unit (pure, platform-neutral: normalise separators and case explicitly, since CI is Linux):** section

## 10. Accessibility & i18n

- Live region announcements (the existing `liveRef`): `Attached <name>`, `Removed <name> from session`,
  `<name> not found`, `<name> reconnected`, search summary.
- Status is never colour-only: `Home`/`Attached`/`Not found` are text tags, and the warn box has a text
  tag and a dashed border.
- Focus: after Remove → the next section's collapse button (or `+ Add folder…`); after Attach/Add → the
  new bar's collapse button; after Locate → the relocated bar's collapse button; a menu closing returns
  focus to its invoker.
- Visible focus on all new buttons survives forced-colors (existing `.iconbtn` focus ring).
- Reduced motion: chevron rotation only; no animated reorder.
- Overlays: the drop menu and the `···` menu use the portal primitives and carry
  `-webkit-app-region: no-drag` (drag-region test).
- **i18n:** the repo has no framework; strings live as constants beside the component. Strings: `Home`,
  `Attached`, `Not found`, `Locate…`, `Remove`, `+ Add folder…`, `Make home`, `Reveal in Explorer`,
  `Copy path`, `Copied path`, `Remove from session`, `Attach to session`, `Copy into <x>/`, `Cancel`,
  `in <project>`, `Removed <x> from session`, `Undo`, `Folder not found`, `No session`,
  `Start a session to see its folders here.`, `Search timed out. Try again.`, the §2.6 and D16 toasts.
  Counts use `countLabel` (`1 folder` / `2 folders`, results, files, unsaved files). Names and paths
  render `dir="auto"`, ellipsised with the full path as title; bars tolerate +30 % label length (the tag
  and actions never wrap under the name).

## 13. Decisions Needed

- **D1 [high]** Files tree, Search in files and quick open show the session's folders; the tree **no
  longer follows `cd`**, and Search no longer uses the live cwd. Pick: drop cwd-following; no
  auto-attach. Reversible, but a shipped behavior changes for every session (`cwd.e2e` updated).
- **D18 [high]** The locked process rule names `--warn` / `--bad`, which don't exist. Pick: map them to
  `--amber` / `--danger` with the existing warn-banner recipe (§11). No new tokens are added.
- **D2 [normal]** One windowed `role="tree"` per folder, stacked in one scroller; selection per folder;
  drag/clipboard pane-wide; bars not sticky. The alternative (one forest tree with bar pseudo-rows) was
  rejected because bars would have to be treeitems and their buttons couldn't stay tabbable.
- **D3 [normal]** The bar chevron collapses the section and all its subfolders (replaces "Collapse all").
- **D4 [normal]** A folder equal to, inside or containing a session folder can't be attached (drop: not
  offered; picker: mf-model's `duplicate`/`overlaps`).
- **D5 [normal]** "Outside every root" means outside **this session's** folders, not `writeRoots()`.
- **D6 [normal]** No new host messages: Add folder uses mf-new-session's `folder:pick` (+ `__pickDirHook`);
  Locate uses mf-live-edits' `folder:locate`. The two sibling specs name different picker test seams
  (`__pickDirHook` vs an `app.evaluate` dialog stub), so the plan should settle on one. mf-live-edits also
  validates Locate by exact duplicates only, while mf-model's addRoot rejects overlaps too.
- **D7 [normal]** The OS-drop seam `window.__conduitOsDrop` is installed only in e2e mode (`about.e2e`).
- **D8 [normal]** Compiler options follow the active session's home via a cached-tsconfig options root;
  attached tsconfigs are ignored; extraLibs aren't purged on remove.
- **D9 [normal]** Remove has no confirm; the Undo toast re-adds at the end (order isn't restored).
- **D10 [normal]** A missing home in Files is the warn box with `Locate…` only.
- **D11 [normal]** Search sends one `contentSearch` per folder under one `requestId`; caps apply per
  folder (the total can be K× today's cap).
- **D12 [normal]** With no active session the pane shows `No session` (aligned with mf-changes).
- **D13 [normal]** Git dots are keyed by absolute path from `repoChanges` (else today's `changes` against
  their own git root); rows under no known repo get no dot.
- **D14 [normal]** §2.1 claims come from source inspection at `524474d`, not runtime; the builder
  re-confirms them with the listed e2es before changing behavior.
- **D15 [normal]** Basename collisions are disambiguated with ` — <parent segment>`.
- **D16 [normal]** Removing a folder with dirty tabs under it is refused until they're saved or closed
  (no data-loss path). Clean tabs from a removed folder stay open.
- **D17 [normal]** Mixed drop + `Attach to session`: eligible folders attach and everything else copies;
  failed attaches are reported and not copied.
