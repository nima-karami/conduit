Fresh-context architecture critique of docs/plans/2026-11-18-mcp-full-screen.plan.md (reviewer did not see the design backstory). Advisory; the conductor's responses are in the plan's "Settled decisions" and "Decisions Needed".

**Verdict: REVISE.** The container approach is sound and has precedent in `.board`, but two specified behaviours are not backed by the plan (agent-focused deep links, focus restore into an `inert` tree). Several contracts and one slice ordering also have holes that should be fixed before coding.

## Blockers
1. **Agent focus has no producer or consumer (dim 4).** Spec §5/§9 say the session dialog and native-impact notice land on "Agents with that agent open". The retarget table (`app.tsx` 5878, 6079) calls `openSettingsAt('mcp', undefined, { mcpTab: 'agents' })`; `opts` is `{ releaseNotes?, mcpTab? }` and `McpSectionProps` has no `focusedAgent`. The call site at `webview/app.tsx:6079` has `target.id` but cannot pass it. Direction: add one optional `agentId` (or `AssignmentPoint`) to the target; have `PermissionsAssignments` open that drawer on mount like the existing `exceptionSeed` effect at `permissions-assignments.tsx:249-301`; or cut the requirement from the spec explicitly.
2. **Focus restore into an `inert` workbench (dim 6).** `SettingsPage` saves `document.activeElement` on mount and restores it on unmount while `<div className="workbench" inert={settingsOpen}>` (`app.tsx:5881`). The common openers (footer Settings button `app.tsx:5594`, a focused terminal) are inside the inert subtree. `onClose` flips `settingsOpen` and unmounts in the same commit; a layout-effect cleanup can run before React removes `inert`, and `focus()` on an inert element is a no-op. jsdom does not enforce `inert`, so the planned unit test passes while the real app loses focus to `<body>`. Direction: restore focus in a post-commit effect in `app.tsx` after `inert` clears, falling back to the active terminal; add an e2e assertion for focus after Back.

## Should-fix
3. **Edit/review/delete steps are not covered by the Esc ladder (dim 6).** Spec order is "drawer/editor → release notes → Settings". The plan registers only the two drawers. Review and delete pages register nothing, so Esc there closes all of Settings and discards staged work. Direction: one rule (Esc steps back one level, including review and delete) through a single `onEscape` owned by the Roles/Agents state machine.
4. **Drawers as overlay entries are a semantic mismatch (dim 3).** `src/overlay-stack.ts:24-37`: a `'modal'` push dismisses every open popover; `modalDepth` also counts drawers, so real dialogs opened over Settings (delete confirm, session dialog at z `--layer-modal`) shift z-index per open drawer. Pull-based alternative: `SettingsPage`'s single `onEscape` asks a "nested level" callback (as release-notes does at `settings-modal.tsx:168`). One stack entry, obvious ordering.
5. **`key={settingsSeq}` remount (dim 6).** Any repeated `openSettingsAt` while open (palette `cmd:activity`, RefusalChip, native notice, add-exception) destroys the Roles/Agents editor and review state, filters, scroll and the open drawer; staged unapplied edits are lost silently. Direction: no remount; make the target a prop-driven value applied in an effect.
6. **Activity data sources are unassigned (dim 4).** `center-pane.tsx:435-441` passes `getActivity`, `getActivityRow`, `allowOnce`, `machines` (from `remoteRows`, `app.tsx:2298`) into `PermissionsActivity`; `app.tsx:5444-5457` supplies the first three from `mcp.*`. `McpSectionProps`/`SettingsPageProps` list only scope, machines and `onAddActivityException`. Say whether `McpSection` calls `useConduitMcp()` itself; confirm `sessions`/`machines` are derived once.
7. **Slice 2 breaks the build between tasks (dim 6).** T2.3 deletes the `permissions-activity` doc kind while `openActivity` (`app.tsx:1080-1091`) still dispatches it until T2.5; with per-task commits `tsc` fails mid-slice. Fold the `openActivity` retarget into T2.3 or order T2.5 first.
8. **Spec/plan drift on `inert` scope (dim 1).** Plan overrides §10 with `inert` on `.workbench` only; spec §4/AC still say "workspace behind is `inert`". Name which chrome stays interactive; update the spec.
9. **Re-homed code stays large; seam only partly justified (dim 2/5).** `permissions-roles.tsx` is ~460 lines of `Editing`/`Review`/`Deletion`/`Profiles` state. New files `role-list`, `role-drawer`, `agents-list`, `agent-drawer`, `role-summary`; `PermissionsAgentDrawer` takes `children` and `onEditChanges`/`onResetAll`, so the real logic stays in `permissions-assignments.tsx`. Each list/drawer pair has one consumer. Merge into owners unless files exceed the repo's size norms.

## Nits
10. `mcp-tabs.ts` is a 2-line file; put `MCP_TABS`/`McpTabId` in `mcp-section.tsx`.
11. `permissions-strings.ts` (`PERM_STR`) adds a second MCP string home next to `conduit-mcp-strings.ts` (`MCP_STR`), which T5.1 also edits.
12. `GroupState`/`groupState` serve one pill; confirm importers beyond tests (fallow). Check `groupSummary`'s other consumers before deleting.
13. "missing-home banner copy" (`src/contracts/native-launch.ts:44`) is a copy change, not a data flow; check main-process consumers vs "renderer-only".
14. Fixed-position geometry copies `.board` (`styles.css:9837`, z 40) but ignores in-flow banners (`.server-banner`, `NativeImpactNotice`, `PermissionStoreNotice` at `app.tsx:5866-5880`); the page covers them without shrinking. Say whether intended.
15. The entry-point table is otherwise accurate; `openSettingsAt` callers outside `app.tsx` and `settings-modal.tsx` do not exist.

**Summary:** the full-screen page structure is the right size of change and matches the `.board` precedent. Fix the missing agent-focus path, the inert-focus-restore hole, the Esc and remount semantics, and the unassigned Activity data sources before building, and cut the speculative file splits.
