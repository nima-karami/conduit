# S0 Windows measurements: tray helper (2026-11-04)

Machine: Windows 11 Pro 22621, one 5120x1440 display, rustc/cargo 1.99.1 (MSVC), Node at `C:\Program Files\nodejs`, hc 0.1.17.
Probe kit: `%TEMP%\claude-scratch\tray-probe\` (deleted after the run). hc runs used an isolated core, `HC_SESSION=tray-s0-1976927242` (core pid 29444, stopped at the end), with `HC_TERMINAL_SOCKET`, `HC_TERMINAL_ID` and `HC_SCOPE` unset. Launch: `hc run --bg --no-parent --name <n> --cwd <kit> node drive.mjs <t> <log> ...`.

## Headline

- **T2 launch flags (F4): `CREATE_UNICODE_ENVIRONMENT | CREATE_BREAKAWAY_FROM_JOB`** with a `CreateEnvironmentBlock` env. A plain `CreateProcessW` child dies when the helper's parent Node exits. `ShellExecuteExW` dies too. With breakaway the child survives the drive exiting, its hc terminal finishing, and `hc server stop`.
- **T4: exe 209,408 B (204.5 KiB)**, about 10% of the 2 MB budget. **Working set 8,589,312 B (8.19 MiB): over the 6 MB budget.** Private bytes are 1,638,400 B (1.56 MiB) and private working set is 1,126,400 B (1.07 MiB). The extra is shared system-DLL pages: 27 modules, including shell32, windows.storage, combase and MSCTF. A `hold`-mode probe with no window already has a 5.65 MiB working set. Dropping serde_json can't fix this, because the whole exe is 204 KiB. Lead call: re-state the budget as private working set ≤ 2 MB (measured 1.07 MiB).
- **No STOP condition hit.** T1, T3 and T5 all passed.
- **New findings for C1 / G1:**
  1. The release exe imports **`VCRUNTIME140.dll`**. A clean machine (S9 Windows Sandbox) may not have it. Fix: build with `-C target-feature=+crt-static` in `native/tray/.cargo/config.toml`. Measured with that flag: 306,688 B (299.5 KiB), no VCRUNTIME, working set 8.31 MiB.
  2. The plan's windows-sys feature list is short two features. `WNDCLASSW`/`RegisterClassW` need `Win32_Graphics_Gdi`, and `SHELLEXECUTEINFOW`/`ShellExecuteExW` need `Win32_System_Registry`.
  3. The **first `NIM_ADD` from a never-seen exe path** returns `{added:true}`, but an immediate `Shell_NotifyIconGetRect` returns **E_FAIL (0x80004005)**. That happened on the first run from the kit path and the first run from the swap path. It returns S_OK on every later run, and on the first run by 8 s. If the T6 fallback ("2 s re-add poll on GetRect failure") is adopted, it must not treat an E_FAIL right after the add as "icon lost".
  4. New icons land in the **overflow flyout**. The S_OK rect `[17,1591,57,1631]` is below the 1440-px screen, so the icon isn't promoted onto the taskbar (that is T9's subject).
  5. Job mechanics: libuv puts every non-detached child in its own job with `KILL_ON_JOB_CLOSE | BREAKAWAY_OK | SILENT_BREAKAWAY_OK | DIE_ON_UNHANDLED_EXCEPTION` (`0x3C00`). That job is what kills the helper when its parent Node dies (T7), and it's why its children die without breakaway. Silent breakaway did work when the parent chain held no outer job (a WMI-launched drive). Under hc it didn't: the child stayed in the job and died.
  6. libuv stdio pipe names are predictable: `\\.\pipe\uv\<counter>-<parentpid>`, and stdin's counter is `18446744073709551615`. They still can't be opened (T3), because each is a single connected instance.

## Manual steps for the user (one sitting, about 10 min)

Prep: rebuild the probe kit (the S0 `tray-probe` crate, which the lead can recreate) or use the G1 `conduit-tray.exe` with a test mode. Copy it to `%TEMP%\claude-scratch\swap\conduit-tray.exe`, and keep a second build with different bytes and a bumped VERSIONINFO next to it as `conduit-tray.new.exe`.

**T1 eyeball + T6 (Explorer restart):**
1. In a PowerShell window: `cd $env:TEMP\claude-scratch\swap; $env:PROBE_LOG="$PWD\t6.log"; node -e "require('child_process').spawn('.\\conduit-tray.exe',['icon'],{stdio:['pipe','ignore','ignore']});setInterval(()=>{},1e9)"`. The probe has a windows subsystem and exits on stdin EOF, so Node holds its stdin open. Events go to `t6.log`.
2. Open the `^` overflow flyout and confirm the default-application icon with tooltip "tray-probe (Conduit S0)". **This is the T1 eyeball.**
3. Note Explorer's PID: `(Get-Process explorer).Id`. Run `Stop-Process -Id <thatPid>`. Explorer relaunches on its own; if it doesn't within 5 s, run `explorer.exe`.
4. Within 10 s, `Get-Content t6.log` should show `{"readd":true,"ok":true,...}` followed by a `getRect` line, and the icon should be back in the flyout.
5. Pass: the design holds. Fail (no `readd`, or `ok:false`): add the 2 s re-add poll on GetRect failure in `model`. Per finding 3, that poll must tolerate E_FAIL right after a first add.
6. Press Ctrl+C in the Node window. The probe gets EOF, deletes the icon and exits.

**T9 (show-on-taskbar persistence across a binary swap):**
1. Start the probe from `%TEMP%\claude-scratch\swap\conduit-tray.exe` as in T6 step 1.
2. Settings › Personalization › Taskbar › Other system tray icons: turn ON "tray-probe" (it may appear under the exe's FileDescription or file name). Confirm the icon moves onto the taskbar.
3. Record the key: `Get-ChildItem 'HKCU:\Control Panel\NotifyIconSettings' | ForEach-Object { $p = Get-ItemProperty $_.PSPath; if ($p.ExecutablePath -like '*claude-scratch\swap\conduit-tray.exe') { $_.PSChildName; $p | Select-Object ExecutablePath,IsPromoted } }`. Expect `IsPromoted = 1`.
4. Quit the probe (Ctrl+C in the Node window).
5. Swap: `Rename-Item conduit-tray.exe conduit-tray.exe.old; Copy-Item conduit-tray.new.exe conduit-tray.exe.new; Rename-Item conduit-tray.exe.new conduit-tray.exe; Remove-Item conduit-tray.exe.old`.
6. Start the probe again (step 1). Re-run the step 3 query.
7. Pass: the same key name is reused, `IsPromoted` is still 1, and the icon is on the taskbar, not in the flyout.
8. Fail: repeat steps 1-7 with `icon --guid`, which uses the fixed GUID `6f1e2d3c-4b5a-4978-8a9b-0c1d2e3f4a5b` with the same path. If that passes, add `guidItem` to the contract. If it fails, ship and release-note it.
9. Cleanup: turn the toggle off, quit the probe, delete `%TEMP%\claude-scratch\swap`.
