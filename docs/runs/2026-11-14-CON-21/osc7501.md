# REQ-D9 — which CLIs report OSC 7501 `blocked` at their own prompts

Measured 2026-11-14 on Linux (this machine), by running each CLI inside an isolated `conduit-hc`
core (`build/vendor/hc/conduit-hc` 0.1.16, own `HC_SESSION=reqd9` and `XDG_STATE_HOME` in the
session scratchpad, so the user's Conduit core was never touched). We forced a prompt, polled
`hc get --json <t>` every 4 s (`reported`, `status`), answered or cancelled the prompt, and polled again.
hc decodes OSC 7501 itself, and Conduit maps hc's `status` record unchanged (`server/runtime/runtime.ts:146-168`).
So `status` here is exactly what `ServerAttention` receives.

## Results

| CLI (version) | Prompt forced | Reported while prompting | After the prompt cleared | Verdict |
|---|---|---|---|---|
| Claude Code 2.1.325 | Bash permission (`--permission-mode default`, "run rm measured.txt") | `{state:'blocked', kind:'permission', app:'claude-code', msg:'approve Bash: rm measured.txt'}` | Esc → `{state:'idle'}` | **MEASURED: emits `blocked`/`permission`** |
| Claude Code 2.1.325 | AskUserQuestion ("red or blue?") | `{state:'blocked', kind:'question', app:'claude-code', msg:'answer: Do you prefer red or blue? (Red · Blue)'}` | Esc → `{state:'idle'}` | **MEASURED: emits `blocked`/`question`** |
| Claude Code 2.1.325 | Workspace-trust dialog at start | `reported:false`, `status:null` (no report yet) | — | **MEASURED: NOT reported.** The trust dialog comes before Claude Code starts reporting |
| Claude Code 2.1.325 | normal turn | `working` → `done` | — | reports turns (context) |
| OpenCode 2.2.7 | bash permission (project `opencode.json` `permission.bash: "ask"`) | `{state:'blocked', kind:'permission', app:'opencode', msg:'Permission needs input', title:'Listing /etc/ssh directory'}` | Reject → `{state:'idle'}` | **MEASURED: emits `blocked`/`permission`** |
| OpenCode 2.2.7 | default config (no ask rule) | no prompt appeared (bash ran directly); `working` → `idle` | — | reports turns (context) |
| OpenCode 2.2.7 | a question prompt | not forced | — | **NOT MEASURED** (`kind:'question'` unknown for OpenCode) |
| Codex | — | not installed here | — | **ASSUMED / unmeasured** |
| Kiro | — | not installed here | — | **ASSUMED / unmeasured** |
| Cursor agent | — | not installed here | — | **ASSUMED / unmeasured** |

Notes:
- `OPENCODE_CONFIG_CONTENT='{"permission":{"bash":"ask"}}'` did **not** produce a prompt. The project
  `opencode.json` did.
- hc also carries `msg` and `title`. Conduit's `mapStatus` drops them, and attend doesn't need them,
  because Conduit writes its own words (spec §4.1 anti-spoofing).

## Consequence for CON-21 `attend`

- `attend` is built on OSC 7501 `blocked` only, and generically: any program that reports `blocked`
  raises it, whatever its name. That is measured for Claude Code (permission, question) and OpenCode
  (permission).
- **Not built:** screen-pattern detection of prompts (REQ-D9 option "both"). It isn't measured, so
  it isn't built, per the lead's brief. The existing `stuck` screen verdict keeps its current chip behaviour.
- Known gap: Claude Code's start-up trust dialog, and every prompt of Codex, Kiro and Cursor, raise no `attend`.
