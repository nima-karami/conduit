# Learnings — interactive-plan run 2026-09-19

- [autonomous-build-loop] `.autoloop/` held the previous run's live ledger (review-mode, 2026-09-05) with no prev- folder; archived it as `prev-2026-09-05-review-mode` before writing this run's files. The skill should say: archive on kickoff.
- [implementation-plan] Parallel groups were cut on file disjointness only; T1.4 consumes `PlanBlock` from T1.2 in another group, so the "parallel" pair had a Consumes edge. The skill's group rule should also require no cross-group Consumes. Ran T1.4 in a second wave instead.
- [architecture-critic] Six real blockers on a plan that passed the planning self-review (baseline accumulation, one ack for two writes, unpinned splice base, size-blind layout, watcher never armed, empty first baseline). Worth its cost; keep 2b on for anything with a sync model.
- [build-and-verify] Bash heredocs in this environment collapse `\` to `\` and silently corrupted a regex and a win32 test path; the first "red" was against corrupted bytes. Executor briefs now say: write source with Write/Edit, never a heredoc.
- [implementation-plan] Adding a member to a `Record<Union, …>`-keyed map's union type breaks the map at a file the task did not own (`FILE_FOR` in electron/conduit-fs.ts). A plan that widens a discriminated union must list every `Record<Union,…>` site as a file to modify. Executor chose the right fix (`Exclude<>` for the non-singleton kind) and reported it as a deviation.
- [memory] The node_modules junction trick for worktrees is incompatible with any `npm install` in the worktree: npm's reify "Removing non-directory node_modules" replaces the junction with a real partial install (no Electron binary, because install scripts are gated by npm's allow-scripts). Fix that worked: `npm ci` in the worktree then `node node_modules/electron/install.js`. Give a worktree a real install when a slice adds deps.
- [build-and-verify] Executors' destructive-command attempts (`Remove-Item -Recurse node_modules`) are denied by the permission classifier; workspace repair is the session's job, not the executor's. Brief executors to report, not repair.
- [autonomous-build-loop] Two Opus executors died mid-task on a 429 session limit (reset 4pm). One had written stub files. Re-dispatch must tell the new executor about partial files from the interrupted attempt so it neither duplicates nor trusts them. The ledger should carry a 'partial_files' note per interrupted task.
- [implementation-plan] The plan's file map listed `.claude/skills/conduit-plan/SKILL.md` as a file to modify, but `.claude/` is gitignored and absent from every worktree — the only copy is the installed one in the main checkout. A file map must not list untracked paths; the installed copy refreshes when the human re-installs from the Skills panel.
- [feature-spec] Spec §3 listed `%%` comments as "supported" in the Mermaid subset. Measured: the parser drops them and the serializer never re-emits them, so a structural edit deletes them. "Supported" needs to distinguish preserved from accepted-and-discarded.
- [none] Reading the consumer caught a loop bug no test would: `buildPlanHandoff` filters on `status === 'open' && !sentAt` with no author check, so an agent reply left `open` gets pasted back at the agent on the next Send. Skill now requires replies to be written `resolved`.
- [build-and-verify] Two "green but broken" defects in one slice, both invisible to DOM-count assertions: a ProseMirror node view with a contentDOM never gets the contenteditable=false stamp (clicking a code fence typed into the prose instead), and ReactFlow's fitView prop runs once at init so a canvas mounted in a portal sat at min zoom outside its own viewport. Both were found only by driving the real app. Assert containment/focus target, never just element counts.
- [none] Backticks inside a double-quoted git commit message in Bash get command-substituted and silently drop the code span. Use a heredoc with a quoted delimiter for any commit message containing backticks.
- [instruction-file] Two independent executors flagged that this session's ambient "auto mode" directive (make file edits through Bash: sed, heredocs) directly contradicts a measured hazard in this environment: Bash heredocs collapse `\` and eat backticks, which silently corrupted a regex, a win32 test path and a commit message in this run. Source edits must use Write/Edit here. The directive should carve out source editing, or the hazard should be stated beside it.
- [code-review] Three parallel fix lanes on disjoint file sets worked, but a defect found by lane A lived in lane B's file and arrived after B had started — it needed a fourth follow-up lane. When review findings are split into lanes, the lane boundary should be announced to every lane so a cross-lane finding is routed rather than dropped.
- [runtime-qa] The highest-severity defect of the run (Send pasting into the wrong project's agent) was only reachable with TWO projects open. Single-project QA would never have seen it. A QA brief for anything session-bound must specify a multi-context setup.
- [runtime-qa] A defect survived two QA rounds because each drove one half of it: round 2 drove "Keep mine" before the read-only reconcile existed, round 3 drove read-only without a conflict. When a fix lands between QA rounds, the next round must re-drive the paths the FIX could have broken, not only the defect it was meant to fix. The review caught it by reading the prop, not the behaviour.
- [autonomous-build-loop] Blocker counts converged 6 -> 2 -> 1, and the last one was a regression introduced by the previous round's own fix. A fix round is itself a change that needs review; the loop should treat "review the fix" as non-optional rather than as an optimisation to skip when the count looks small.
