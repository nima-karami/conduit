# Learnings — editor-parity batch 2026-09-28
- [feature-spec] Spec agents that probed the running app caught the user's premise being false (Files highlight does not follow focus) — probe-before-spec paid off; keep asking spec agents to measure current behaviour. 
- [implementation-plan] auto-save Slice 1: a claim-measurement slice with a blanket "any false → stop" rule halted the run on two false verdicts (C5 partly, C11) that nothing in the build depends on. Next time, list for each claim which task depends on it, so a false verdict stops only the dependent work (spec D8 already said "drop the part that depends on it").
- [CLAUDE.md] Explorer tree paths are joined with `/` (`file-tree.ts` `joinPath`) while doc ids use `canonicalPath` (all `\`). Any renderer compare between a tree path and a doc path (`onFileRenamed`, `dropDocsFor`) must canonicalise both sides. Today a rename leaves the dirty tab open on the deleted path. Also: harness `openSession` forward-slashes the root, so an e2e can't reproduce the native-root shape unless it posts `openRepo` itself.
- [CLAUDE.md] CodeViewer used to recreate the Monaco editor whenever doc.content changed, and every save changes it, so focus went to <body> after each Ctrl+S. auto-save removed doc.content from the editor effect's deps (content now reseeds the model in place through fileSaves.attach). Anything re-keyed on doc.content in CodeViewer brings that bug back. Only an e2e that kept typing after a save caught it.
- [implementation-plan] Planner optimised for "existing tests untouched" and picked an asymmetric state model (group 1 legacy fields + group 2 overlay); the critic counted ~19 representation-only branches and a silent data-loss consumer. Tell planners that preserving test *expectations* matters, not test *accessors*.
- [autonomous-build-loop] Phase 2b earned its keep on split-editor: the structural call was caught before any code.
- [instruction-file] (tree-chevrons, 2026-09-28) A hidden e2e window does not advance CSS transitions: a computed `transform` read 300ms after a toggle still returned the pre-toggle matrix, so AC4 reported "open" chevrons that were closed. Read settled transforms under `emulateMedia({ reducedMotion: 'reduce' })` and test the transition's duration separately; worth a CLAUDE.md line next to the hidden-window rAF note.
- [build-and-verify] (tree-chevrons) Playwright treats an empty spacer span as hidden, so `waitForSelector` on a layout-only element needs `state: 'attached'` — same trap as `.termpane` in the smoke-flakiness memory; a generic "structural/empty elements: wait attached" line in the executor brief would save a run.
- [none] (tree-chevrons) A three-theme, one-launch-per-theme scenario ran 143s against the runner's 210s per-scenario guard; extending it (more themes/ACs) should split per theme rather than grow the one file.
- [code-review] A forced-colors assertion on computed `color` is vacuous in Chromium; assert SVG stroke/fill vs currentColor.
- [runtime-qa] tree-chevrons QA: in a hidden (CONDUIT_E2E) window, computed `background-color` read after hover returns the pre-transition value (CSS transitions don't advance); judge hover/press state from a screenshot (which forces a frame) or emulate reduced motion first. Cost one false FAIL line.
- [feature-spec] (nav-keybindings) "Old chord is inert" ACs must enumerate EVERY command bound to that chord in the target context, not just the one being rebound: Monaco binds F12 to `goToNextReference` inside a references peek (weight 90 < revealDefinition's 100), so removing Definition's F12 surfaces it — AC-5b "F12 inert in the peek" was unpassable as written, and the fixture's next reference happened to BE the definition, so the first run looked like a removal failure. Grep monaco-editor/esm for `KeyCode.F12` (primary AND secondary) when speccing.
- [implementation-plan] (nav-keybindings) A plan that has a UI component import a Monaco-coupled module must check who else imports that component's parent: `settings-modal.tsx` is imported by a node/jsdom unit test (files-drop-claim), and pulling `monaco-editor` into its static graph crashed it (`document.queryCommandSupported`). Worked around with a lazy `import()`; a planner should state the module-graph consequence of each new import edge.
- [build-and-verify] (nav-keybindings) A hidden e2e window does not repaint on a live theme swap via `updateSettings` — three "theme" screenshots came out identical. Seed `settings.json` in a fresh userDataDir per theme (as test/e2e/visual/shoot.mjs does) for any per-theme visual check.
- [feature-spec] "Monaco resolves by physical key" was an unmeasured spec claim that became a unit test asserting the wrong result; spec agents must mark library-behaviour claims ASSUMED and planners must turn them into a source check or spike.
- [code-review] Reviewer found 3 data-integrity blockers in auto-save that a green gate + passing 157s e2e missed; lifecycle audits (every removal path, seed-vs-edit state) are where to look.
- [runtime-qa] auto-save QA: in Conduit the terminal is a centre tab (session tab = `.tabbar .tab` without role=tab) and a second, hidden `.termpane` exists — target `.termpane .xterm >> visible=true`, or clicks time out at 30 s.
- [runtime-qa] Hidden harness window: `BrowserWindow.blur()` produced 0 renderer `blur` events (re-confirmed 2026-09-28) — window-blur ACs stay needs-human-smoke.
- [implementation-plan] (changes-active-highlight) Adding a REQUIRED prop to a component (ChangesViewProps/FilesViewProps/FolderSectionProps) broke 6 unit tests that render it with literal prop objects — none in the file map. Planners should grep `test/unit` for `createElement(<Component>` and list those files whenever a contract adds a required prop.
- [build-and-verify] (changes-active-highlight) The spec's "tree double-click opens don't reveal" did NOT reproduce on an uppercase-drive temp root; it reproduced only when the session root was opened as `c:/…` (canonicalPath upper-cases doc paths, roots keep their spelling). A probe that uses the harness's default path spelling can report a defect fixed that isn't — vary the root's drive-letter case when measuring path-matching bugs.
- [runtime-qa] (changes-active-highlight) Asserting `.filerow--selected` from the DOM in a windowed tree is only valid while the selected row is mounted; a tab activation that scrolls the tree made a correct build look like it cleared the selection. Keep both states within one viewport or read React state.
- [build-and-verify] (auto-save, review round) Moving state out of a component (save ownership) means auditing every place the old owner was torn down, not only the one the plan names. Session removal closed tabs through its own path and skipped the new store's teardown (review B1). Grep for every way the owned thing ends (close, session close, rename, window close) before calling the move done.
- [code-review] Re-review of a fix round found the B2 fix turned the close path into a write — fixes to state machines need re-checking against every caller, and each 'fixed' finding needs a test that can fail.
- [feature-spec] (nav-keybindings review) "Record the key Monaco fires on" was specced as `e.code` from a source read of `USLayoutResolvedKeybinding`; the actual input is `e.keyCode` (`keyboardEvent.js` `extractKeyCode`). When a spec claims what a library resolves on, cite the function that READS the DOM event, not the one that maps the result.
- [build-and-verify] (nav-keybindings review) "Which rule wins" questions left as "the build states the winner" produced a measurement of ONE registration order (already-open editor) and missed the other (editor opened after the rebind, where the result flips). For order-dependent behaviour, measure both orders, or remove the dependence, before reporting a winner.
- [build-and-verify] (nav-keybindings review) Runtime-proof checks that "focus the last editor" (`focusEditor`) can land on a hidden diff tab's still-connected editor and report a false FAIL; pick the editor by model path.
- [code-review] (auto-save, re-review) A fix that changes what a state means (B2 made seed-only buffers `dirty`) must be checked against every consumer of that state, not only the one the finding named. `closeDoc`'s auto request ignored `edited`, so the B2 fix opened a new silent rewrite. When a finding widens a state, list its readers before closing the finding.
- [runtime-qa] (changes-active-highlight QA) Before reporting a focus/keyboard criterion as failed, run the same probe on the merge-base build: Ctrl+Tab focus loss looked like a feature regression and was identical on main. [none: product defect is in the QA report]
- [runtime-qa] Quick-open (Ctrl+P) opens PREVIEW tabs that replace each other; a driver needing two tabs must pin (double-click the tab) or open from the tree.
- [code-review] (changes-active-highlight) Turning a pin that is set once into derived state ("pinned while focused") quietly made it permanent, and since pins widen the virtual window contiguously it mounted 86/86 rows. No e2e covered it because no step read the mount count. When a render-time value's lifetime changes from event-driven to derived, re-check every consumer that assumed it was short-lived.
- [architecture-critic] Quit-guard critic caught an unquittable-app deadlock (single confirm slot overwritten without settling) and a durability regression (flush deferred behind async prompt) — host lifecycle changes always get 2b.
- [instruction-file] (file-integrity) Explorer tree paths are `joinPath` = `/`-joined, tab/doc paths are canonicalPath (`\`); any compare between the two must go through `pathBelow`/`renamedPath` (src/canonical-path.ts). Rename AND delete both silently no-op'd on this for months; a spec (auto-save C11) even documented "rename discards edits" for a branch that was never reached. Worth a CLAUDE.md line next to the canonicalPath note.
- [build-and-verify] (file-integrity) In this harness's Bash tool, heredocs collapse `\` to `\` — a node-via-heredoc edit of a TS file with Windows-path literals silently wrote `'C:\p\k.ts'`. Use the Edit tool for any text containing backslashes.
- [runtime-qa] (file-integrity) mf-live-edits "E3: nothing pasted while busy" fails on base de36575 too (built + run alone); it is pre-existing, not a file-integrity regression.
- [instruction-file] (file-integrity r2) Conduit turns Monaco's TS semantic markers OFF (`monaco-setup.ts` noSemanticValidation), so an e2e that waits on `getModelMarkers` for "Cannot find module" waits forever on a correct build. Ask the worker directly: `(await monaco.typescript.getTypeScriptWorker())(uri).getSemanticDiagnostics(uri)`.
- [instruction-file] (file-integrity r2) Monaco's `addExtraLib` returns a no-op handle when the content is unchanged, and a handle only removes the version it added. Anything that must later REMOVE an extraLib (rename/delete) has to keep the handle of the first add and skip identical re-adds, or the dispose silently removes nothing.
- [runtime-qa] (file-integrity r2) goto-index fails "deep source file … got 0" at 25c543c as well (built + run alone, 3 runs). The scenario checks for code-viewer.tsx as soon as more than 400 libs are loaded, while the index is still streaming. Treat it as pre-existing / flaky, not an index regression.
- [build-and-verify] (file-integrity r3) The e2e helper `modelValueAt(page, '/q.ts')` matches by suffix, so it also matches `/qdir/q.ts` and returns whichever model comes first. That produced a false FAIL on a correct build. When two open files share a basename, look models up by their exact URI.
- [implementation-plan] (split-editor) A plan can lock two things that contradict each other. Spec §9 made the Terminal button `role="tab"`, and E14/I7 says the existing e2e suites pass unchanged, but 25 e2e files select `.tabbar [role="tab"]` to mean "doc tabs". So 4 of the 5 regress suites went red. Before locking an ARIA/role change on a shared element, grep `test/e2e` for selectors on that role and list the files that would have to change.
- [build-and-verify] (split-editor) A value cached in React state and resynced from other state in a passive `useEffect` is stale for one committed frame. Nothing noticed while every consumer read the same cache. A new consumer that reads the source directly (the per-group strip reads `layouts`) exposed it: nav-history's Back was judged against the old `null` and a real-input e2e caught it. When a slice adds a reader of the source next to readers of the cache, resync in `useLayoutEffect` or derive the value.
- [runtime-qa] (split-editor) A click inside a `<webview>` guest produces no host `focusin` and no `focus` on the `<webview>` element, only a window `blur`, with `document.activeElement === <webview>`. The plan's pre-agreed fallback, which bound the element's `focus` event, would never have fired. Measure guest focus with a real click before specifying which event carries it.
- [implementation-plan] (dirty-quit-guard S1) The A1 probe as planned ("second app.quit() → app exits") cannot pass on a fresh harness profile: the profile starts with a running session, so today's `onWindowClose` guard sends `confirmQuit` and blocks the close forever. A control run (single quit, no preventDefault) timed out identically. Any probe of quit/close lifecycle must auto-answer `quitDecision` in the renderer AND run a no-intervention control first, or it reports a false negative.
- [implementation-plan] (dirty-quit-guard S2) Plan contracts named a field from an older plan (`autoEligible:false`) that had since been renamed (`AttachOpts.writable`). Planners should grep the current source for every field a contract cites; the executor caught it only because the doc comment matched.
- [build-and-verify] (dirty-quit-guard S2) Executors told "do not commit, the session commits per task" worked cleanly for 4 concurrent file-disjoint groups in one worktree: pathspec commits (`git commit -- <files>`) let each task land as its own commit while siblings were still writing, with no index races.
- [feature-spec] (split-editor review round) "Every user activation lands focus in the activated view" collided twice with E14 "existing e2e unchanged": nav-history-lifecycle clicks the Terminal button and then presses Alt+←, and review-mode-pane ×-closes to the Terminal and then presses Ctrl+Shift+R. xterm swallows app keys, so both broke. A focus-policy AC must list each pointer landing on a key-owning surface (terminal, webview) separately. Two session rulings were needed: a pointer onto the Terminal keeps focus where it was, and a keyboard landing focuses it.
- [instruction-file] (split-editor QA) The global `* { scrollbar-color }` rule makes Chromium ignore every `::-webkit-scrollbar` rule in styles.css. The `.tabbar` "thin overlay" scrollbar had been a 15px classic bar, lifting tabs 7.5px on overflow (on main too). Any scrollbar styling has to use the standard properties (`scrollbar-width`/`scrollbar-color`). Worth a CLAUDE.md gotcha.
- [feature-spec] (split-editor re-review) "Land focus in the activated view" made the Terminal a focus trap. xterm owns every key except the reserved set, so after Ctrl+Tab onto it the next Ctrl+Tab went to the shell. Any spec that moves focus INTO a key-owning surface (a terminal, a webview guest) must also say which app chords escape it (VS Code `commandsToSkipShell`). A real-guest measurement showed a focused `<webview>` swallows Ctrl+Tab and there is no forward path, so web tabs deliberately get no focus target.
- [build-and-verify] (split-editor re-review) Playwright's `page.keyboard` and the host `webContents.sendInputEvent` deliver keys to the HOST document even while a `<webview>` guest has focus. A test that "types into the guest" that way passes over a guest that really swallows the key. Send guest keys through the guest's own `webContents.sendInputEvent`.
