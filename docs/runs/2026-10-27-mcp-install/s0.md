## D1 — installed key survives a running interactive Claude

| Question | Result | How |
|---|---|---|
| Key survives a live **authenticated** turn + `/exit` | **NOT_MEASURED** | Scratch `CLAUDE_CONFIG_DIR` is not logged in; no API key; credentials deliberately not copied |
| Key survives a running (unauthenticated) interactive Claude | **MEASURED: survives** | Started interactive `claude`, waited 9 s (onboarding screen), wrote `mcpServers.conduit` by hand with the T2.3 algorithm (read → set → temp + rename), drove onboarding to the login screen, Ctrl+C ×2, killed the PTY. `mtime` never changed after our write; the key was intact afterwards |
| Claude merges rather than overwrites `.claude.json` | **MEASURED: merges** | `claude mcp list` and `claude -p` both rewrote the scratch file (migrations, `pluginUsage`, `changelogLastFetched`) and kept a hand-written `mcpServers.conduit` |

Caveat: Claude's write path while a turn runs (history, project stats) was not exercised.

## D9 — Codex installed table + per-launch `-c`

Scratch `config.toml` held the §3.4 table (`env = {ELECTRON_RUN_AS_NODE, S0_LOG, TABLE_ONLY}`,
`env_vars = ["CONDUIT_SESSION_TOKEN","CONDUIT_MCP_ENDPOINT"]`, `default_tools_approval_mode="auto"`).
`codex exec` ran with the exact `-c` set `codexArgs` builds (`src/mcp-launch.ts:41-59`), with
`CONDUIT_SESSION_TOKEN`/`CONDUIT_MCP_ENDPOINT` set in the parent env.

| Question | Result | How |
|---|---|---|
| Table parses | **MEASURED: yes** | `codex mcp list`/`mcp get conduit` show it, `default_tools_approval_mode: auto` |
| Starts with `-c` overrides | **MEASURED: yes** | Server spawned and got `initialize` + `tools/list` before the (expected) 401 on the model call |
| `command`, `args` | **`-c` wins** | Server argv was the `-c` args (`codex-flag --endpoint ep-flag`) |
| `env` (inline table) | **merged key by key** | `-c env={ELECTRON_RUN_AS_NODE='1'}` kept the table's `S0_LOG`/`TABLE_ONLY` (log landed at the table's `S0_LOG` path) |
| `env_vars` (array) | **`-c` replaces** | Only `CONDUIT_SESSION_TOKEN` reached the server; the table's `CONDUIT_MCP_ENDPOINT` did not (per-launch passes the endpoint as `--endpoint`, so nothing is lost) |

## Incidental

- Claude 2.1.312 sends a `server/discover` request (`_meta` protocol `2026-07-28`) before
  `initialize`; on a non-error empty result it still proceeds to `initialize`. The fallback shim
  answers unknown methods with `-32601`, which a client treats as "not supported".

## Decisions

- **`CURSOR_CLIENT_NAMES = ['Cursor']`** (T1.5). Measured via `agent mcp list`; interactive sessions
  not measured. Exact match, as `clientKindOf` specifies.
- **Claude approval pattern: none.** The project-approval prompt is already blocking via
  `/Esc to cancel/` (T3.2 makes no change).
- **D1: direct edit with the mtime guard holds** (T2.3 unchanged). Running Claude never rewrote the
  file after our write and Claude merges its own writes; the authenticated-turn case is
  NOT_MEASURED, so per §14 the default stands. Re-check in S6 QA with a logged-in session.
- Claude dedupe: keep per-launch injection unchanged (one `conduit`, per-launch wins).
- Codex: table as specified. `-c` wins for `command`/`args`/`env_vars`; `env` merges, so installed
  `env` keys ride along in Conduit launches — harmless for the §3.4 entry (`ELECTRON_RUN_AS_NODE` only).
- OpenCode: default holds — `$XDG_CONFIG_HOME/opencode/opencode.json` else
  `~/.config/opencode/opencode.json` (also on Windows), project file `<root>/opencode.json`.
