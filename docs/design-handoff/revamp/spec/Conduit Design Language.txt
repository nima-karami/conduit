You asked for Aero in light and dark plus Neon, so this is the missing one. Built by substituting token values into 5a/5b/5c without touching a single element, spacing value or radius — the diff between light and dark is entirely colour. Where that was not possible, the notes say so, and those exceptions are exactly the tokens the handoff has to define per theme.

Figtree + IBM Plex Mono · ground #131419 · panel #1b1d24 · raise #23252e · accent #8b95f0, violet gradient on progress · window radius 12, panel 20, card 15, control 13 · shadows go black (0 1px 3px rgba(0,0,0,.45))
This frame is 5a’s DOM with a different palette substituted and nothing else touched — which is the actual argument that Aero is a theme, not a second design. Every value that changed is a colour; every radius, gap and shadow geometry is shared.
Two things do not survive a mechanical inversion. Translucent panels go muddy over a dark ground, so panel becomes opaque #1b1d24. And the light version’s trick — dark terminal inside light chrome — inverts: here the terminal is the darkest surface (#0d0e12), still reading as an object because it is below the panels rather than above them.
The accent lightens from #4a56c8 to #8b95f0. The same indigo at light-mode value fails contrast on a dark panel, so accent is one of the tokens that genuinely needs a per-theme value rather than an alpha.
Shadows flip from ink-alpha to black and deepen. On dark grounds a 7%-ink shadow is invisible, which is why the current app reads flat (§7.1) — it has no elevation tokens at all.

Figtree + IBM Plex Mono · #eceff4 ground · #4a56c8 accent, violet gradient reserved for progress · real assets/icon.png as the window mark · window radius 12, panel 20, card 15, control 13 · shadow 0 1px 3px · 1px inset window hairline
The 12px window padding and 11px gutters are the whole idea: panels float, so the terminal reads as an object rather than the room. Costs 23px of usable width against a flush layout — and it only reads correctly if the Electron window is itself rounded (12px here, with a 1px hairline), so the panels have a soft edge to float inside rather than a hard box.
Exactly one shadow level (0 1px 3px) plus a deeper one under the terminal. More levels and it stops reading as calm.
Attention is a warm card wash, not a spine — on a light ground a 2px bar is too quiet, but a tinted card is unmissable.
Cost: the airiness spends about one session card of list height versus the current build.

Chakra Petch (display) + JetBrains Mono (data) · #07060d ground · #00f0ff busy / #ff2d9b attention · real assets/icon.png, notched and magenta-glowed to match · radius 0 · 14px corner notch on filled surfaces and on cards (diagonal drawn explicitly) · glow 0 0 14px
Colour is the status system: cyan means working, magenta means it wants you, and nothing else on screen is saturated. The loudest answer to §7.3 we have drawn.
The notch only cuts filled surfaces; on a bordered card the diagonal is drawn as its own 1px element, because clip-path removes the border along the cut. Bordered chrome (inactive nav, the alert chip) stays square.
Segmented progress (8 blocks) rather than a bar — reads as instrumentation and survives the zero-radius rule.
File icons drop to the minimal monochrome pack; the colored pack hues (#3178c6, #cbcb41) actively fight this palette.
Honest risk: scanline and glow are charming for about a week. Both are one variable away from zero, which is how I would ship it — theatre on a slider.
