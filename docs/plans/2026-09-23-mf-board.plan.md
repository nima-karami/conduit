# mf-board — implementation plan

**Spec:** `docs/specs/archive/2026-09-23-mf-board.md`  **Tier:** FULL

Tier reason: a committed-schema field (`BoardCard.ticket`), a rewritten card surface with a new
component file, a public prefill builder consumed by the app, deleted exports, and a new e2e — across
`src/`, `webview/` and `test/e2e/`.

Built **last** (after mf-model, mf-changes, mf-new-session, mf-files, mf-sidebar, mf-review,
mf-live-edits). Conductor rulings in `.autoloop/locked.md` (L1, L3, L7, L11, L12) and
`.autoloop/blockers.md` (mf-board D1, D8) override the spec where they differ; each override is
listed under Spec staleness.

## Goal

A board card lists every session linked to it (dot, name, agent), jumps to any of them, and starts
another session with the same project and folders via mf-new-session's dialog; cards round-trip an
externally written, read-only `ticket` and show it in a header row.

## Architecture

Everything new is derived in the renderer from data it already has: `state.sessions` (this window's,
via `useSnooze`), `state.projects`, `state.agents`, and the board document. The pure derivations go
in `src/board-linkage.ts` (which already holds the card's session/proposal derivations) and a
one-function `src/agent-label.ts`. That module holds the one agent-label rule, and the sidebar and
the board both call it (spec D11). Presentational card parts live in a new
`webview/components/board-card-links.tsx`. `BoardView`/`Card` wire them in, and `app.tsx` turns a
card into a `NewSessionPrefill` with one pure call. No host message, no host code and no
persisted-session change. The only on-disk change is that `restoreBoard` keeps `ticket`.

## Data flow

```
host postState ─► state.sessions (this window) ─► useSnooze ─► sessions ─┐
                  state.agents, state.projects ─────────────────────────┤
                                                                         ▼
app.tsx ── <BoardView home={active?.home} sessions agents …> ── per card:
             linkedSessionsForCard(sessions, card.id, home)   (cardId match AND folderKey(home) ∈ {s.home} ∪ s.roots)
               └► <LinkedSessions> rows: linkedRowState / linkedRowName / linkedRowLabel / agentLabelFor
                    click|Enter|Space ─► onActivateSession(id) ─► setActiveId + setCenterView('editor')
             <TicketHeader ticket={card.ticket}>      (read-only; parsed by restoreBoard)
             [+ Start session] or menu "Start session for this card"
               └► onStartSessionForCard(card, pillEl) ─► app: cardSessionPrefill(card, {sessions, active, projects, agents})
                     ─► setNewSession(prefill)  ─► mf-new-session dialog (seedNewSession, missing roots pass through — L11)
                     ─► Start: openRepo {path: home, agentId, roots, projectId, cardId, requestId}  (mf-new-session / mf-model)
                     ─► Cancel/Esc: focus pillEl (if still connected)
board.json ─► readBoardArtifact ─► restoreBoard (keeps a validated ticket) ─► BoardView
BoardView edit ─► updateBoard ─► host writeBoardArtifactFile ─► serializeBoardArtifact (ticket survives: cards are spread)
```

## Settled decisions — do not re-litigate

- Spec D1–D13 as written, except where the Spec staleness rows below record an override.
- **blockers.md mf-board D1 (conductor-accepted):** optional read-only
  `BoardCard.ticket {key?, source?, status?}`, preserved on save, with no in-app writer.
- **blockers.md mf-board D8 + L11:** the prefill is mf-new-session's `NewSessionPrefill`. Missing
  prefilled roots are **passed through** to the dialog, which shows them as `Not found`. No filtering
  happens here.
- **L7:** the board is the active session's `home` board. A link counts on `home` **or** an attached
  root (spec D13), which doesn't change how `.conduit/` resolves.
- **L1:** `home` is never in `roots`, so `linkedSessionsForCard` doesn't dedupe.
- Rows follow host list order (D10). This window's sessions only (D5). No new setting.
- `.bcard__badge`, `sessionsForCard`, `badgeStateForCard` and `CardBadge` are deleted (D4, AC6).

## Spec staleness

- **§3.2 "compared through the existing `normalizeRoot`"**: mf-model introduced `folderKey`
  (`normalizeRoot` plus UNC case folding) as the single folder-key rule, and `sessionHasFolderKey`
  over it. This plan uses those. A second comparison rule would contradict L11's "one folder
  validator".
- **§3.3 `NewSessionPrefill` with required fields**: mf-new-session's type has every field optional
  (`projectId` `undefined` means derive, `null` means standalone). The builder always sets `home`,
  `roots`, `projectId` (`string | null`, never `undefined`), `cardId` and `cardTitle`, so the dialog
  never derives on a board prefill.
- **§7 tokens `--text-muted` / `--muted`**: neither exists in `webview/styles.css` (0 uses measured).
  The muted name uses `--text-dim` and the agent label uses `--text-faint`.
- **§7 "the existing tag and pill classes"**: there is no generic tag or pill class. Only
  component-scoped ones exist, such as `.proposal__tag` and `.bcard__badge`. New `.bcard__*` rules
  are written in the same shape.
- **§7 "hovered row gets a `--accent` 6% background; `+ Start session` on hover gets a 9% tint"**:
  `test/unit/state-vocabulary.test.ts` ("paints hover only from the state tokens") rejects a hover
  `background` that isn't a `--state-*` token unless it is allowlisted for a *status meaning*. An
  accent hover on a link row carries no status, so allowlisting it would weaken the gate. Instead:
  - rows join the **quiet** ladder (`--state-hover-bg` / `--state-press-bg`);
  - the pill's accent tint is its **rest** fill, `color-mix(in srgb, var(--accent) 9%, transparent)`,
    and it joins the **field** ladder (hover changes the edge, not the fill).

  Recorded as Decisions Needed #1.
- **§7 "contrast … checked in `npm run shots`"**: shots write PNGs and measure nothing. Contrast is
  asserted by a unit test on the theme tokens (T2.6), as the diff-token suites do. Measured with
  `test/unit/theme-color.ts` maths against `--raise` (the `.bcard` fill), accent text on an accent
  wash:

  | wash | aero | aero-dark | neon |
  |---|---|---|---|
  | 9% | 5.36 | **4.83** | 11.66 |
  | 12% | 5.12 | 4.60 | 10.94 |
  | 15% (`--accent-soft`) | 4.91 | **4.32 ✗** | 10.09 |

  So the status pill and the Start pill use 9%, and `--accent-soft` must not be used.
- **§7 "Rows and the pill are at least 24px tall" / "a truncated part gets `title`"**: jsdom has no
  layout, so "truncated" can't be detected in a unit test. Every ticket part, row name and agent
  label gets `title` set to its full value unconditionally, which is a superset of the rule.
- **§9 e2e "dragged … with the real mouse"**: *(Superseded by mf-board QA: `page.mouse` does drive
  native HTML5 drag in this build; the e2e now runs a mouse drag first.)* Originally: Playwright's mouse can't drive HTML5 drag and drop in
  this harness. `test/e2e/terminal-drop.e2e.mjs:4-9` measured this, and
  `test/e2e/sidebar-dnd.e2e.mjs:64-69` still marks mouse drags NEEDS-HUMAN-SMOKE. The e2e uses the
  one-shared-`DataTransfer` technique mf-sidebar uses (`dragstart` dispatched **on the pill**, which
  bubbles to `.bcard`, then `dragover`/`drop` on the Planning `.bcol`, then `dragend`). That proves
  the pill doesn't swallow the drag or break the card's drag wiring. Whether Chromium starts a
  native drag from a `<button>` inside a `draggable` ancestor is a runtime-QA item (Decisions
  Needed #2).
- **§9 Background "Given settings autoSwitchSession = true"**: it is the default (`src/settings.ts`
  `autoSwitchSession`). `runScenario` uses a fresh profile, so the scenario asserts the default
  holds instead of seeding it.
- **§2 row "`openRepo {path, agentId, cardId?}` … `mgr.create(agent.id, p, undefined, cardId)`"**:
  superseded by mf-model (`mgr.create(agent.id, p, { cardId, roots, projectId })`). This plan
  touches no host code.

## Global constraints

- Gate: `npm run verify` (format-check, lint, fallow dead-code, duplication, both typechecks,
  tests, security). Never disable, narrow or allowlist a check to pass. **This plan's executor does
  not run `npm run build`, e2e or `npm run verify` while another agent is running PTY e2e on the
  machine.** Per task, run the single unit file (`npx vitest run test/unit/<file>`). The gate and
  the e2e run in the conductor's integration step.
- Naming: files are `kebab-case.ts(x)`; functions are `camelCase` verbs or nouns matching siblings
  (`linkedSessionsForCard` next to `proposedFlags`); CSS is BEM under the owning block (`.bcard__*`,
  modifiers `--x`); React components are `PascalCase`, exported only when another module imports
  them.
- Comments: *why* only (CLAUDE.md hard rule). Link the spec (`// spec 2026-09-23-mf-board §3.2`)
  rather than restating it. Update the stale doc comments you touch: the `BoardView` props, the
  `Card` props and the `CardEdit.fields` doc.
- No `process.platform` branches in `src/`. Unit tests use explicit `C:\\Src\\A` vs `c:/src/a/`
  strings (CI runs on Linux).
- Tokens: `--accent`, `--text`, `--text-dim`, `--text-faint`, `--border-2`, `--font-mono`,
  `--r-round`, `--state-*`. No hex. A new interactive class joins the vocabulary section at the foot
  of `webview/styles.css`, never above it.
- Renderer-safe `src/` only: `src/board-linkage.ts` and `src/agent-label.ts` import no `node:*`
  module.
- Invariant (ADR 0002, `src/types.ts` `cardId` doc): `board.json` never gains a session id, a path
  or any machine-local datum. The linked list is derived and never stored.

## Contracts

### `src/board.ts`

```ts
/** Read-only tracker reference written by an external tool. Conduit never writes it (spec §3.5). */
export interface BoardTicket { key?: string; source?: string; status?: string }
export interface BoardCard {
  // …existing fields unchanged…
  ticket?: BoardTicket;
}
```

Module-private: `const TICKET_CAPS = { key: 40, source: 24, status: 32 } as const` and
`function restoreTicket(raw: unknown): BoardTicket | undefined`. A sub-field is kept only when it is
a `string` whose `.trim()` is non-empty. It is stored trimmed, then cut to the cap by
`Array.from(v).slice(0, cap).join('')`. The result is `undefined` when no sub-field survives or when
`raw` isn't a non-null, non-array object.

`restoreBoard` adds `...(ticket ? { ticket } : {})` to the card it builds. `duplicateCard` stays as
is: it builds the copy field by field, so `ticket` is already not copied. AC4 pins that.
`updateCard`/`moveCard` already spread `...c`, so `ticket` survives edits and moves.

### `src/conduit-proposal.ts`

`cardEditedFields` (private) pushes `'ticket'` when `!ticketEqual(a.ticket, b.ticket)`.
`ticketEqual` is private and compares `key`, `source` and `status` with `===`, treating an absent
object as `{}`. The `CardEdit.fields` doc becomes: "Which fields differ (`title`, `notes`, `links`,
`ticket`) — drives the review summary." `diffBoard`'s doc gets "title/notes/links/ticket".

### `src/board-linkage.ts`

```ts
import type { BoardCard } from './board';
import type { NewSessionPrefill } from './new-session-seed';
import type { Project, Session } from './types';

export type LinkedRowState = 'running' | 'stopped';

/** Sessions linked to `cardId` on the board at `boardHome`: s.cardId === cardId AND
 *  sessionHasFolderKey(s, folderKey(boardHome)). Input order. boardHome undefined/'' → []. */
export function linkedSessionsForCard(
  sessions: readonly Session[],
  cardId: string,
  boardHome: string | undefined,
): Session[];

/** running → 'running'; exited | stale → 'stopped'. */
export function linkedRowState(s: Pick<Session, 'status'>): LinkedRowState;

/** The linked session with the greatest lastActiveAt; first wins a tie; undefined for []. */
export function lastLinkedSession(linked: readonly Session[]): Session | undefined;

/** s.name.trim() || 'Untitled session'. */
export function linkedRowName(s: Pick<Session, 'name'>): string;

/** `${linkedRowName(s)}, ${agentLabel}, running` | `…, not running` (spec §7 a11y template). */
export function linkedRowLabel(s: Pick<Session, 'name' | 'status'>, agentLabel: string): string;

export interface CardPrefillContext {
  sessions: readonly Session[];
  active: Session | undefined;
  projects: readonly Project[];
}

/** The New session prefill for a card (spec §3.3). null when there is no board home (no active
 *  session). Source = lastLinkedSession(linkedSessionsForCard(sessions, card.id, active.home))
 *  ?? active. home/roots = source's (roots copied, missing ones kept — L11); projectId =
 *  projectForNewSession(source, projects); agentId = the LAST SESSION's agentId, passed raw —
 *  seedNewSession's registeredAgentId (D20 aliases) decides; omitted for the active fallback. */
export function cardSessionPrefill(
  card: Pick<BoardCard, 'id' | 'title'>,
  ctx: CardPrefillContext,
): NewSessionPrefill | null;
// returned shape: { home, roots, projectId: string | null, cardId: card.id, cardTitle: card.title, agentId? }
```

Deleted: `BadgeStatus`, `CardBadge`, `sessionsForCard`, `badgeStateForCard` (and the file-header
comment's "(N2)" line is reworded to name linked rows). `proposedFlags`, `proposedAdditionsIn`,
`ProposedChange` and `ProposedFlag` are unchanged.

### `webview/app.tsx`

- `newSessionReturnFocus = useRef<HTMLElement | null>(null)`.
- `<BoardView home={active?.home} sessions={sessions} agents={agents} onStartSessionForCard={startSessionForCard} …/>`.
- `startSessionForCard = useCallback((card, returnFocus) => { const p = cardSessionPrefill(card, { sessions, active, projects: state?.projects ?? [], agents }); if (!p) return; newSessionReturnFocus.current = returnFocus; setNewSession(p); }, [...])`.

  when it is `isConnected`, then null the ref.

### Invariants and validation

- The only trust boundary crossed is `board.json` / `board.proposed.json` → `restoreBoard`. `ticket`
  is validated there and nowhere else, since everything downstream holds a `BoardData`. React
  renders ticket text as a text node, never as HTML.
- `LinkedSessions` never writes the board. Closing a session changes only `sessions`, so the only
  write path is still `apply()` → `updateBoard`.

## Deviation rule

If a task's assumption turns out wrong (an upstream export has another name or signature, the
`BoardView` prop is still `projectPath`, the state-vocabulary test rejects a rule), that task
**stops** and fixing the misaligned piece becomes the work. Never a shim, a second copy, a special
case, a widened type, a fallback, or an allowlist entry patched in place of its semantic source.
The report leads with the fix that keeps the locked decision.
