A post-response guard cannot undo prior UI effects. Test/report stopped subsequent dispatches and uncertain outcome, never physical first-step rollback. No renderer or new cancellation/ack protocol in this scoped correction.
- Local host captures per-call committedOverrides:OneUseOverride[] and ownerAllowed:boolean. Initial control commit stores only successful AskCommit.held; answered commit stores its held input plus successfully committed result.overrides, deduplicated defensively. Never retain a failed commit's proposed token. ownerAllowed becomes true only after successful commitAnswered in the actual allowed-answer continuation; an initial Allow is not human consent. stillCurrent resolves currentLocalDecision(committedOverrides), requires success and current decision Allow OR actual ownerAllowed, and refuses if current decision.overrideIds contains any token not already in committedOverrides. Thus already-consumed authority remains usable for this call while newly minted one-use authority is not used without a new durable commit. Preserve existing held/IO/rollback behavior.
- Remote host captures actual ownerAllowed per call, set only after successful owner outcome/current commit before run. stillCurrent uses freshRemotePolicy with current identity/master/conditions/original signal and ownerAllowed. Extend private freshness phase explicitly: pending/pre-run keeps original ask deadline; running ignores only the already-satisfied ask-wait deadline and still respects original signal/tool budget. Never skip preflight/first-execution deadline. No unasked Allow→Ask bypass. Remote principals have no one-use override support.
- closeWhenDone is not an agent call: bind an explicit lifecycle guard !stopped && !closing.deleted, without borrowing an agent profile or inferring permission. Existing configured automatic close behavior/unsaved guard preserved. All other production context constructors are local and remote agent calls above; fixtures get explicit true default only as external authority test dependency.
- Existing remote multi-target aggregate-rule mismatch m2 remains accepted follow-up; do not weaken tuple comparison or invent a reach ordering to hide it. Exact per-target execution modeling is separate.
