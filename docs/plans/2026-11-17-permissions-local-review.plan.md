# Exact local native permission review

The Permissions modal and Settings edit the existing local policy. Keep their authority in the policy service. A review message describes the candidate under the same CAS token. Saving still validates the edit and reconstructs the same candidate in one synchronous path. Remote review proof, receiver policy and runtime CLI arguments use their existing mechanisms.

## Contract

In `src/conduit-mcp/policy-types.ts`, define the local `LocalPolicyEdit` union with operations `{ kind:'assignment'; point:AssignmentPoint; assignment:Assignment|null }`, `{ kind:'profile'; profile:Profile }`, and `{ kind:'delete-profile'; profileId:ProfileId; replacement:ProfileId }`. Define `LocalPolicyReviewResult = { ok:true; requiresNativeReview:false } | { ok:true; requiresNativeReview:true; digest:string } | { ok:false; error:PolicyEditError }`. The review reply is scoped to the initiating local owner window and contains no file data, native arguments or raw input.

The policy service uses one candidate builder for review and all three existing save methods. Preserve full-CAS entry points and existing errors/saving behavior. For a validated native projection change, produce SHA-256 over a versioned tuple of the exact current edit token, validated current profiles/assignments, and validated candidate profiles/assignments. Use stable canonical JSON for the normalized edits the owner actually acts on. The input must distinguish ordinary candidate differences even when their native effect is equal. Exclude unrelated grants, override usage, last-good warning, and standalone mirror revision. Treat profile and assignment order deliberately per existing policy canonicalization, without widening the identity of semantically distinct candidates.

Replace local `nativeConsent?: boolean` with `nativeReview?: string` on the shared local method signatures and only their three existing renderer envelopes. Save recomputes the digest against the current token and actual candidate. A mismatched, missing, or malformed digest cannot authorize a native projection change. An unrelated non-native save needs no native review token. An old boolean is never consent. Tokens are not persisted and never substitute for current editToken. Duplicate review requests and repeat applying a previously changed candidate cannot affect a new current token.

Add authenticated correlated request `mcp:reviewLocalPolicy` with requestId, expectedToken and edit; reply `mcp:reviewLocalPolicyResult` with requestId and LocalPolicyReviewResult. Check only trusted owner session senders and bounded known DTO fields before owner preview. Use existing assignment/profile validators and only the enum union, no remote machine parameter. Forward via existing Electron/bridge flow; `useConduitMcp.reviewLocalPolicy(edit, expectedToken)` returns typed reply or null. Actual renderer holds candidate with that editToken and shows the native changes before confirmation. If an external edit invalidates the token, refresh the displayed diff and request owner review again. This producer does not replace remaining legacy editor entry points, which retire with their last real caller.

## Accepted architecture refinements

Retain the order of behavior-relevant arrays, including exceptions, profiles and assignments. Use the same existing normalizer for unordered pins in both paths. Canonicalize object keys recursively after existing normalization, without changing actual save semantics or dropping validated behavior fields. Test reversed exception order as a different candidate and harmless object key/pin order as equivalent. The local C2 renderer is trusted to display and receive human confirmation. The digest binds the displayed candidate to its save; it is unkeyed, and does not authenticate a person or grant authority itself.

Global/profile commands require a nonzero authenticated ready app window. Session assignment commands additionally require the actual currently owning window and an existing local session, for both review and save. Unavailable or not-owned session replies contain no candidate information. Use an explicit bounded edit validation step shared by both incoming routes. Accept only current discriminants and known assignment/profile fields (including pins and native modes), arrays of known rules/scopes, and limits consistent with existing stored policy cap. Preserve existing supported values and fixtures. Do not hash or transmit raw unbounded nested values or allow arbitrary extra data on new messages.
