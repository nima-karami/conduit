# Local permission persistence — implementation plan

**Spec:** docs/specs/2026-11-14-policy-and-permissions.md. **Tier:** FULL. Lead instruction 2026-11-17: failed writes reach UI, no silent retries, concurrent edits refused. Architecture decisions: .autoloop/evidence/persistence-design-review.md. Separate commit from Activity query; local-only new full editors in this slice.

## Architecture
Dedicated bounded synchronous PolicyIo at existing service owner, reusing atomicWriteFileSync. Local human saves are rare; serial JS transactions avoid async interleaving and preserve remotePolicy.edit's synchronous callback. No generic transaction framework or second engine. Primary store write precedes successful publication; backup warning distinct. No automatic retry of failed human intent.

## Locked contracts
- New src/conduit-mcp/policy-file-fs.ts exports PolicyIo {read():string|null; writeSync(text:string):true} and createPolicyIo(file:string):PolicyIo. Adapter verifies encoded candidate <=1MiB then mkdir+atomicWriteFileSync, returning literal true. Throws on failure; service catches into typed outcome/error state. Existing async RequestsIo remains for requests/remote mirror persistence.
- PolicyServiceDeps policyIo,lastGoodIo,grantsIo become PolicyIo. All production adapters and typed fixtures use it. No async writer coercion, wrapper returning true before a Promise finishes, or swallowed Promise.
- Human mutations prepare defensive candidate without modifying live file/store, validate complete candidate, sync-write primary, publish only on success. Builtin profile immutable. Only success bumps portable rev/notifies listeners/rechecks tools. Backup copied after primary: failure is backupWarning, successful primary remains committed.
- Local policy/grants candidate max1MiB, portable256KiB existing unchanged. Oversized readable existing files are retained in memory; editing reports explicit oversized-store error and never truncates. Human can reduce data with deliberate editor operation; current store is not overwritten by a failed candidate.
- PolicyUiState adds editToken:string, saveError:string|null, backupWarning:string|null. editToken newly generated by deps.newId on service start and every profile/assignment change (including legacy/session-end/remote apply). Do not reuse portable rev as local session edit identity.
- saveAssignment(point:AssignmentPoint, assignment:Assignment|null, expectedToken:string):PolicyEditResult; saveProfile(profile:Profile,expectedToken:string):PolicyEditResult; deleteProfile(profileId:ProfileId,replacement:ProfileId,expectedToken:string):PolicyEditResult. PolicyEditResult={ok:true}|{ok:false;error:'conflict'|'invalid-value'|'unknown-profile'|'read-only'|'save-failed'|'too-large'|'not-found'}. expectedToken checked before any mutation; stale edit never overwrites a newer deny. Existing legacy setters keep signatures but use durable candidate write path.
- saveProfile validates custom p-* id, name1..80 printable, all TOOL_NAMES rules, no invalid condition values via existing validators; profile references must resolve. Full assignment validation reuses existing parser guards including scope/path limits, pinned normalization. No renderer trust.
- deleteProfile rewrites all its assignments to chosen existing replacement atomically; preserves exceptions and onScreenOnly; rejects builtin/self replacement/missing id. Save failure leaves profile/usages unchanged.
- New protocol mcp:saveAssignment {requestId,point,assignment,expectedToken}, mcp:saveProfile {requestId,profile,expectedToken}, mcp:deleteProfile {requestId,profileId,replacement,expectedToken}; reply mcp:policyEditResult {requestId:number,result:PolicyEditResult}. Host rejects malformed values and unknown local sessions. These new routes are local only; no machine field is accepted. Remote full editors require a separately detailed owner token/durability slice; existing remote editor remains on its current APIs meanwhile.
- Hook new saveAssignment/saveProfile/deleteProfile/retryPolicy methods return Promise<PolicyEditResult|null> directly. Null means host timeout/unavailable; caller displays explicit uncertain-save error and refreshes snapshot before retry. Existing boolean legacy methods retain boolean returns. Service legacy mutation result unions and protocol mcp:toolPolicyResult must explicitly include save-failed/too-large (and existing domain errors); this is a real new error contract, not coercion into old errors.

- revokeGrant(id:string):PolicyEditResult reports not-found or persistence failure directly; conservative in-memory revocation remains on failed save. Remote revocation maps persistence failure to policy_unavailable.
- GrantBatchResult={ok:true;grants:Grant[]}|{ok:false;error:PolicyEditError}. ControlCall.grant propagates exact batch errors; save-failed/too-large/read-only reach the owner answer, never inferred from global state.
- CallFlow.answerPermission returns Promise<PermissionAnswerResult> settled after re-decision, grant persistence and commitAnswered, before runNow. Cancellation/disposal clears receipts; legacy answer stays boolean.
- createGrants(choice,p,tool,targets,requestId):GrantBatchResult validates every target, clones store, creates all, persists single grants candidate, publishes all-or-none. Existing createGrant delegates single target. Host grantsFor uses batch, never per-target loop. An answer failure never leaves partial new grants.
- Human widening operations (grant create/one-use grant) must durably save before success. One-use consumption durably writes removal before executing; failure refuses call and keeps it consumed in memory conservatively. Security tightening (revoke/session end/expiry) remains effective in memory on failed write and reports saveError. No automatic failure retry timer.
- retrySave():PolicyEditResult writes ONLY current conservative memory snapshot, not a failed human draft. Protocol mcp:policyRetry and hook retryPolicy; button label 'Retry saving current rules'. UI retains a failed human draft separately; its Retry sends the captured expectedToken again, conflict forces reload/review.
- Remote draft durability/full edits are out of this local persistence commit, but remain in assigned scope as next slice. Stable owner token belongs to RemotePolicy Entry; never use token from its freshly created temporary PolicyService for a selected UI snapshot. No machine full-edit routes are exposed until that slice. Existing remote no-write projection adapter migrates mechanically to PolicyIo only; no claim of remote durability is made.
