## Goal
A controller acknowledges only durably stored remote edits, rejects stale human intent, and exposes full portable profile/assignment editing for the approved UI.

## Settled decisions
Receiver enforces policy and portable full-doc baseRev CAS. Controller owns draft intent and local edit identity. Session assignments/scopes never travel. Keep the existing engine and no fourth capability. Do not change native modes or apply new UI design here. Prior synchronous local owner contracts, typed save failures and one-use handling remain intact. Security review of each correction is before final merge, not an extra permission gate between authorized slices.

## Architecture and contracts
Use the existing RemotePolicy Entry as controller's authority. Durable synchronous bounded draft write before publishing any owner edit or starting a push, reusing PolicyIo after local slice. Requests IO remains async for request lifecycle; no global RequestsIo rewrite. Portable policy network stays full-doc CAS by receiving machine's baseRev.

- Extend createPolicyIo(file, options?:{maxBytes:number}) for explicit per-owner cap; default local policy/grants cap1MiB remains enforced by their service too. Remote pending-copy aggregate cap16MiB; validate encoded candidate before filesystem IO. Existing larger/corrupt/newer files remain untouched/read-only with visible error; never truncate to fit. Existing per-machine portable256KiB/64profiles/256assignments/64exceptions/path limits unchanged.
- Export REMOTE_POLICY_DRAFTS_MAX_BYTES = 16 * 1024 * 1024 from remote-policy.ts, consumed by owner candidate/load checks and host createPolicyIo options. Reject a loaded text above this aggregate bound before parsing as read-only/preserved, not merely its next write. createPolicyIo read itself still returns whole text; no claim of bounded read allocation.
- RemotePolicyDeps.draftsIo:PolicyIo. persist(candidateDrafts):PolicyEditResult is synchronous and writes complete candidate before mutation. No auto retry after failure. Read failure/corruption produces owner storeError and writable=false; old edit() must refuse rather than silently succeed/push.
- Entry gains editToken:string from newId at creation/load. Stable over repeated ui calls, grant-only/status-only/link down updates. Refresh whenever effective editable doc OR conflict revision/document changes, successful owner edit/discard/reapply, peer replacement or connection gone; opaque token prevents restart ABA. Never expose temporary PolicyService token as Entry version.
- uiOf projection overrides policy.editToken with Entry token and policy.saveError/readOnly with actual controller store facts. Temporary service is only validation/projection with a no-write IO; no durable claim from it. Conflict copy is read-only and shares owner entry identity for explicit reapply.
- Existing edit(machine,op) becomes durably synchronous, refuses no-copy/busy/read-only/save-failed/too-large. It prepares temporary service, applies semantic legacy op, validates full portable result, writes candidate draft map, then publishes, refreshes token, notifies, starts send if connected. Host legacy booleans now reflect actual controller save outcome.
- Add RemotePolicyEdit discriminated union in src/conduit-mcp/ui-types.ts: assignment{point:RemotePolicyPoint,assignment:Assignment|null}; profile{profile:Profile}; delete-profile{profileId:ProfileId,replacement:ProfileId}. No session assignment or session exception scope may be projected away; reject before op/full-doc validation.
- editFull(machine:string,expectedToken:string,edit:RemotePolicyEdit):PolicyEditResult. Compare Entry token first, then translate to temporary svc's own token when invoking its typed local editor. Validate complete resulting RemotePolicyDoc before storing. Add legitimate remote errors no-copy/busy to PolicyEditResult union. No generic error coercion.
- New renderer command mcp:remoteEdit {requestId,machine,expectedToken,edit}, reply typed mcp:policyEditResult. Hook remoteEdit(...):Promise<PolicyEditResult|null>. Host validates machine/exact operation and rejects all unsupported local-only points/scopes. Electron forwards command through mcp.fromRenderer.
- Acknowledged discard/reapply: add requestId and expectedToken to mcp:remotePolicy; actions discard/reapply/retry-save. Hook returns Promise<PolicyEditResult|null>. Existing Settings callbacks supply selected Entry token and await result; null timeout is shown inline even without owner snapshot, other errors shown inline plus owner snapshot, new full editor will await. Discard returns after durable local deletion without pushing; Reapply returns after durable local rebasing and queues a push; do not await up-to30s network in10s renderer request. Pushing/waiting/conflict/applied remain actual network status.
- discard deletes pending draft only after durable write; failure keeps prior draft/token. reapply rebases to conflict.rev only after durable write, then queues send. Concurrent/stale action is refused, never overwrites newer rules.
- send snapshots submitted draft; success promotes known submitted doc+ackrev into mirror before dropping draft so visible profile never briefly reverts to old mirror. Persist draft cleanup; if cleanup write fails, remote apply remains truthfully applied, current memory is conservative canonical state, saveError explains stale local pending copy. Explicit retry-save writes current draft map, never resends rejected intent. Restarted old disk draft must hit receiver CAS/conflict before any overwrite; test no duplicate widening.
- Every send completion is bound to its captured submitted draft and Entry/link lifetime; stale completion cannot clear/rebase a later draft or newer conflict.
- Network push rejection must become visible refused status/error (no unhandled Promise). Confirm peer result and source contracts, do not swallow thrown errors as success. A newer known mirror must not be replaced by older same-link data; reset freshness on explicit reconnect so authoritative lower-rev recovery remains visible/conflicted rather than hidden indefinitely.
- Existing missing Electron mcp:remotePolicy forwarding is fixed with new acknowledged route. Source settings Discard/Reapply path must be exercised in real Electron.
