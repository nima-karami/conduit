# mf-model — implementation plan

**Spec:** `docs/specs/2026-09-23-mf-model.md`  **Tier:** FULL

Tier reason: host model, persistence format, migration, ~12 new protocol messages, launch args,
watcher and health subsystems across `src/`, `electron/` and three renderer files; a new public
contract seven sibling items consume.

## Goal

A session has a `home` plus attached `roots` and an optional `projectId`; the host owns, validates,
persists (sessions.json v2 + projects.json v1), publishes and acts on them (repos, write roots,
watcher, `--add-dir`, missing-folder detection), while a single-folder session behaves as today.

## Architecture

The model stays in `SessionManager` (sessions) plus a new `ProjectStore` (projects); both emit into
the existing persist + `postState` path. Every renderer payload is validated by one async
orchestrator, `createSessionOps` (`src/session-ops.ts`), which probes the folder, re-reads the
session after every await, then calls a synchronous, already-validated `SessionManager` mutation.
Everything that decides something is pure and lives in `src/` with fs/path/timers injected
(migration, folder keys, validation, repo merge, launch args, health scheduling); `electron/main.ts`
only wires message cases and side effects. Startup migration is a pure `buildStartupModel` whose
output the host executes (backups → projects.json → sessions.json v2) before the first `state`.

## Settled decisions — do not re-litigate

- L1–L10 of `.autoloop/locked.md` are the frame. mf-model §13 D1–D16 are accepted as picked, with
  the conductor's rulings: **D3 extended migration trigger accepted** (migrate whenever the
  sessions blob is v1; deterministic `p-<sha1(folderKey)[:12]>` ids); **D16 additions accepted**.
- **D6 is the single source of truth for win32 metacharacters:** a root containing any of
  `" % & | < > ^ !` is *skipped* for `--add-dir` when the command does not end in `.exe`; the skipped
  list is returned by `launchArgsFor`/`buildLaunchSpec` as `skippedAddDirRoots` so mf-new-session's
  preview can disable Start. mf-new-session's whole-launch BatBadBut refusal is not built here.
- **Conductor override of D5 (from mf-live-edits D11):** a `homeMissing` session never spawns.
  `buildLaunchSpec` returns a typed refusal `{ ok: false, reason: 'home-missing' }`; cwd resolves
  live cwd if it exists → home if it exists → refuse. `os.homedir()` is no longer a session
  fallback. `term:start` on refusal spawns nothing and writes one dim line; the centre/card UI is
  mf-live-edits'.
- **Conductor ruling:** the reconnect poll covers a missing **home** (`homeMissing`) as well as
  `missingRoots` (mf-live-edits D20 depends on it).
- Sidebar keeps grouping by `home` (D1). `state.groups`, `ProjectGroupDTO`, `ProjectGroup` and both
  `groupByProject` helpers are deleted (D2).
- `buildLaunchSpec` is the one function `term:start` spawns from (mf-new-session D15); its `roots`
  input is already filtered to present roots by the caller.
- Stored `home`/`roots` keep the caller's spelling (`path.resolve`d for roots); every comparison
  uses `folderKey`.

### `src/folder-validation.ts` (renderer-safe; fs injected)
```ts
export type SessionOpReason =
  | 'unknown-session' | 'invalid-path' | 'not-found' | 'not-a-directory' | 'filesystem-root'
  | 'duplicate' | 'overlaps' | 'is-home' | 'not-attached' | 'unknown-project' | 'too-many';
export const MAX_ROOTS = 32;
// module-private: MAX_FOLDER_PATH = 4096
export interface DroppedRoot { path: string; reason: SessionOpReason }
export interface FolderProbeDeps {
  path: { isAbsolute(p: string): boolean; resolve(...p: string[]): string; parse(p: string): { root: string } };
  kind: (p: string) => Promise<'dir' | 'not-dir' | 'missing'>;   // host: fs.promises.stat
  realPathLeaf: (p: string) => string;                           // host: src/path-guard.ts realPathLeaf
}
export interface ProbedFolder { stored: string; keys: string[] }  // keys = unique [folderKey(stored), folderKey(realPathLeaf(stored))]
export async function probeFolder(
  raw: unknown, deps: FolderProbeDeps,
): Promise<ProbedFolder | { reason: 'invalid-path' | 'not-found' | 'not-a-directory' | 'filesystem-root' }>;
/** Keys vs existing folder keys: equal → 'duplicate'; isAncestorOf either way → 'overlaps'. */
export function placementConflict(candidate: readonly string[], existing: readonly string[]): 'duplicate' | 'overlaps' | null;
```
`invalid-path`: non-string, length 0 or > 4096, contains `\0`, or not `isAbsolute`.
`filesystem-root`: `parse(x).root === x` for `stored` or its realpath (after `kind` says `'dir'`).

### `src/session-ops.ts` (host-only)
```ts
export type SessionOpResult = { ok: true } | { ok: false; reason: SessionOpReason };
export interface SessionOpsDeps {
  mgr: Pick<SessionManager, 'get' | 'addRoot' | 'removeRoot' | 'replaceRoot' | 'setHome' | 'setProject'>;
  projects: Pick<ProjectStore, 'has'>;
  probe: (raw: unknown) => ReturnType<typeof probeFolder>;
  onFoldersChanged: (sessionId: string, change: { homeChanged: boolean }) => void;
}
export interface SessionOps {
  addRoot(sessionId: unknown, path: unknown): Promise<SessionOpResult>;
  removeRoot(sessionId: unknown, path: unknown): SessionOpResult;
  replaceRoot(sessionId: unknown, oldPath: unknown, newPath: unknown): Promise<SessionOpResult>;
  setHome(sessionId: unknown, path: unknown, keepOldHome: boolean): Promise<SessionOpResult>;
  setProject(sessionId: unknown, projectId: unknown): SessionOpResult;
  resolveInitialRoots(home: string, roots: unknown): Promise<{ roots: string[]; dropped: DroppedRoot[] }>;
}
export function createSessionOps(deps: SessionOpsDeps): SessionOps;
```
Invariant for every async op: after the probe resolves, re-`get` the session (`unknown-session` if
gone) and recompute existing keys from the **current** `home`/`roots` before `placementConflict`
and the `MAX_ROOTS` check. Existing keys: `addRoot` → home + roots; `replaceRoot` → home + roots
minus old; `setHome` swap (path's key ∈ roots) → no probe, no conflict check; `setHome` new path →
home (omitted when `keepOldHome === false`) + roots; `too-many` when the op would make
`roots.length > 32`. `removeRoot`: non-string → `invalid-path`; key = home's → `is-home`; not in
roots → `not-attached`. `setProject`: `null` clears; string not in store → `unknown-project`;
any other type → `{ok:false, reason:'unknown-project'}`, logged.
`resolveInitialRoots`: non-array → `{roots: [], dropped: []}`; each entry probed then checked
against home + already-accepted entries; home's key → `is-home`; failures go to `dropped`.
`onFoldersChanged` fires once after each successful mutating op (not for `setProject`).

## Deviation rule

If a task's assumption turns out wrong — the piece it builds on is misaligned, a locked signature
doesn't fit reality — that task **stops** and fixing the misaligned piece becomes the work. Never a
shim, second copy, special case, widened type, alias field, fallback, or an override patched in
place of its semantic source. The report leads with the fix that keeps the locked decision.

## Decisions Needed

- [high] **`openRepo:result.droppedRoots` shape.** mf-model: `{ path, reason }[]` (always
  present); mf-new-session §3.2: `string[]` plus `error?`. Default taken: mf-model's shape;
  mf-new-session reads `droppedRoots.map((d) => d.path)` for its toast. mf-new-session may add
  `error` (unknown agent) additively in its own item.
- [high] **Missing prefilled roots in `openRepo`.** mf-new-session D17 expects a non-existent root
  to be kept and marked `missingRoots`; mf-model §3.3 validates `stat` → `not-found` → dropped.
  Default taken: mf-model (dropped, reported in `droppedRoots` with `reason: 'not-found'`), so
  invariant I2's realpath check always ran on every stored root. Reversing it means
  `resolveInitialRoots` accepting `not-found` entries lexically.
- [normal] **Unknown `projectId` in `openRepo`** → standalone (mf-model §2.2), not an error as
  mf-new-session §3.2 suggests. Default: mf-model.
- [normal] **Health re-check on every watcher fire for the watched session** (async, deduped per
  key) is how "an event after which the watched folder no longer exists" is detected. Cost: ≤ one
  stat per folder per debounce window under activity, zero when idle (idle-fs-quiet).
- [normal] **projects.json flush is dirty-gated** in `flushStateSync`, unlike sessions.json, so a
  run that never touched projects never rewrites an unreadable file.
- [normal] **Live cwd missing but home present now launches in home**, not `os.homedir()` — a
  consequence of the conductor's home-missing ruling (mf-live-edits AC-6). Visible to single-folder
  users only when their cd'd-into directory was deleted.
- [normal] **`repoRoot` ships with no renderer caller** (mf-changes/mf-review add them). Slice 8 is
  last so it can be dropped to the consuming item if the review prefers "no producer before a
  caller"; the e2e is its only caller here.
- [normal] **D7 unmeasured:** repeated `--add-dir` accumulating in real claude is assumed; the e2e
  proves argv only. One manual check with the real CLI recommended.
