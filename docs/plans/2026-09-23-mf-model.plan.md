## Goal

A session has a `home` plus attached `roots` and an optional `projectId`; the host owns, validates,
persists (sessions.json stays `version: 1` with a `projectPath` mirror; projects.json v1),
publishes and acts on them (repos, write roots, watcher, `--add-dir`, missing-folder detection),
while a single-folder session behaves as today.

## Architecture

The model stays in `SessionManager` (sessions) plus a new `ProjectStore` (projects); both emit into
the existing persist + `postState` path. Every renderer payload is validated by one async
orchestrator, `createSessionOps` (`src/session-ops.ts`), which probes the folder, re-reads the
session after every await, then calls a synchronous, already-validated `SessionManager` mutation.
The whole folder lifecycle — watched set, health checks, reconnect revalidation, repo rescans, plan
reconcile — lives in ONE host module, `SessionFolderRuntime` (`electron/session-folder-runtime.ts`),
with a handful of entry points and a single `onFoldersChanged(sessionId)` hook for later items
(L12 S1); `main.ts` keeps only message cases. Decisions are pure and live in `src/` with
fs/path/timers injected. Startup is a pure `buildStartupModel` the host executes.

## Settled decisions — do not re-litigate

- L1–L12 of `.autoloop/locked.md` are the frame; mf-model §13 as revised in the spec.
- **On-disk format (L12 S13):** sessions.json keeps `version: 1`. `serializeSessions` writes `home`
  **and** `projectPath` (= home) so an older build loads every session; the `Session` type has no
  `projectPath` (L1). The parser prefers `home`, falls back to `projectPath`. **Migration trigger =
  any entry lacking `home`**; its `projectId` is the deterministic `p-<sha1(folderKey)[:12]>`, so it
  joins its folder's existing project. No sessions future-version or downgrade backup machinery.
- **B1:** a missing-but-valid root in `openRepo.roots` is kept (lexical checks only) and seeded into
  `missingRoots` at create. A missing home refuses the session: `openRepo:result {error:'home-missing'}`;
  also `'unknown-agent'` and `'invalid-path'`. A returning root re-runs the full validator before its
  mark clears; if it now fails, it stays excluded and the reason is logged once.
- **B2:** projects.json is `absent` only on `ENOENT`. Any other read error (`unreadable`) or a future
  version keeps session `projectId`s and **blocks projects.json writes** for the run; project
  mutations retry the read first and are refused with `store-unavailable` while blocked.
- **B3:** exactly one `fsChanged` per watcher fire: `{root, folders}`; the renderer does one Changes
  refresh per message.
- **S7:** no `launchedRoots`/`skippedAddDirRoots`/`setLaunchRecord` on the session; `buildLaunchSpec`
  returns `skippedAddDirRoots`.
- **S8:** no `session:replaceRoot` wire message and no `keepOldHome` field; `replaceRoot` and
  `setHome(…, keepOldHome)` are host APIs on `SessionOps` for mf-files' `session:locateFolder` (L11).
- **S9:** `repoRoot` only on `git:history`, `git:refs`, `git:switch`; rangeDiff/resolveRange are mf-review's.
- **S10:** one metacharacter policy: on win32 a root containing `" % & | < > ^ !` is skipped for
  `--add-dir` (and reported) only when the **resolved** command ends in `.cmd`/`.bat`; `.exe` and
  posix unaffected.
- **S11:** `collapsedProjects` path → id coerce is owned by mf-sidebar (hand-off; not built here).
- **Enclosing repos (conductor, supersedes spec D8):** for each present folder whose downward scan
  finds no repo rooted at the folder itself, the host asks git for the enclosing repo
  (`rev-parse --show-toplevel` through `runGit`/`runGitBin`, `GIT_OPTIONAL_LOCKS=0`, via the existing
  30 s memo `repoTopLevel` in `electron/main.ts:784`, `GIT_TIMEOUT.metadata`) and lists it tagged by
  the folder it encloses (`home` for home, `attached` for an attached folder), deduped with the
  downward results. A home inside `repo/packages/foo` keeps showing that repo's changes.
- Missing home never spawns; `buildLaunchSpec` returns `{ok:false, reason:'home-missing'}`; cwd =
  live cwd if it exists → home if it exists → refuse. The poll covers a missing home.
- Sidebar keeps grouping by `home` (D1). `state.groups` et al. deleted (D2, Slice 1).
- `buildLaunchSpec` is the one function `term:start` spawns from and `launch:preview` reuses.

### `src/session-migration.ts` (host-only)
```ts
export interface StartupBackup { from: 'sessions.json' | 'projects.json'; to: string; overwrite: boolean }
export interface StartupModel {
  sessions: Session[];          // [] when input.sessions is null
  projects: Project[];
  projectsWritable: boolean;    // false for 'unreadable' | 'future'
  backups: StartupBackup[];
  writeProjects: boolean;       // projectsWritable && the list differs from what was loaded
  writeSessions: boolean;       // legacyIds non-empty
  warnings: string[];
}
export function buildStartupModel(input: { sessions: SessionsParse | null; projects: ProjectsLoad }): StartupModel;
// module-private: projectIdForKey(key) = 'p-' + sha1(key).hex.slice(0, 12)
// module-private: projectNameForHome(home) = a drive root (C:, C:\ or C:/) → home; else sessionNameFromPath(home)
```
Rules, in order:
1. `cleanIds = projects.kind ∈ {absent, ok}`; `projectsWritable = projects.kind ∈ {absent, ok, corrupt}`;
   loaded list = `ok` → its projects, else `[]`.
2. Each **legacy** session (id in `legacyIds`): `pid = projectIdForKey(folderKey(home))`; if the list
   lacks `pid` and `projectsWritable`, append `{id: pid, name: projectNameForHome(home), order: max+1}`
   (first-seen order); the session gets `projectId = pid` in every case (unwritable → dangling,
   reads standalone this run).
3. Each non-legacy session whose `projectId` is not in the list: when `cleanIds` and
   `projectId === projectIdForKey(folderKey(home))` → recreate that project as in step 2
   (**deterministic-id recovery**: covers a crash between the two writes and a run whose projects
   write was blocked); when `cleanIds` otherwise → delete the field; when not `cleanIds` → keep.
4. Backups: legacy ids present → `{from: 'sessions.json', to: 'sessions.pre-mf.bak.json', overwrite: false}`;
   `corrupt` → `{from: 'projects.json', to: 'projects.corrupt.json', overwrite: true}` + warning;
   `unreadable`/`future` → warning only.

### `src/folder-validation.ts` (renderer-safe; fs injected)
```ts
export type SessionOpReason =
  | 'unknown-session' | 'invalid-path' | 'not-found' | 'not-a-directory' | 'filesystem-root'
  | 'duplicate' | 'overlaps' | 'is-home' | 'not-attached' | 'unknown-project' | 'too-many';
export interface DroppedRoot { path: string; reason: SessionOpReason }
export const MAX_ROOTS = 32;
export interface FolderProbeDeps {
  path: { isAbsolute(p: string): boolean; resolve(...p: string[]): string; parse(p: string): { root: string } };
  kind: (p: string) => Promise<'dir' | 'not-dir' | 'missing'>;   // host: fs.promises.stat
  realpath: (p: string) => Promise<string>;                      // host: fs.promises.realpath (async; S12)
}
export type ProbedFolder =
  | { status: 'present'; stored: string; key: string; realKey: string }
  | { status: 'missing'; stored: string; key: string };          // lexical checks only; never realpath'd
export async function probeFolder(
  raw: unknown, deps: FolderProbeDeps,
): Promise<ProbedFolder | { reason: 'invalid-path' | 'not-a-directory' | 'filesystem-root' }>;
/** Candidate keys vs existing keys: equal → 'duplicate'; isAncestorOf either way → 'overlaps'. */
export function placementConflict(candidate: readonly string[], existing: readonly string[]): 'duplicate' | 'overlaps' | null;
/** Keys of a session's folders: each folder's lexical key plus its cached realpath key if known (S5). */
export function folderKeysOf(folders: readonly string[], realKeys: ReadonlyMap<string, string>): string[];
// module-private: MAX_FOLDER_PATH = 4096
```
`invalid-path`: non-string, length 0 or > 4096, contains `\0`, not `isAbsolute`. `filesystem-root`:
`parse(x).root === x` for `stored` (lexical, both statuses) or `realKey`'s source realpath (present).
`not-found` stays a `SessionOpReason` (used by `addRoot`, which requires presence) but `probeFolder`
reports absence as `status: 'missing'`, letting each caller choose.

### `src/session-ops.ts` (host-only)
```ts
export type SessionOpResult = { ok: true } | { ok: false; reason: SessionOpReason };
export interface SessionOpsDeps {
  mgr: Pick<SessionManager, 'get' | 'addRoot' | 'removeRoot' | 'replaceRoot' | 'setHome' | 'setProject'>;
  projects: Pick<ProjectStore, 'has'>;
  probe: (raw: unknown) => ReturnType<typeof probeFolder>;
  realKeys: Map<string, string>;   // host-owned lexical key → realpath key; ops write it on every present probe
  onFoldersChanged: (sessionId: string, change: { homeChanged: boolean }) => void;
}
export interface SessionOps {
  addRoot(sessionId: unknown, path: unknown): Promise<SessionOpResult>;            // requires present: missing → 'not-found'
  removeRoot(sessionId: unknown, path: unknown): SessionOpResult;
  setHome(sessionId: unknown, path: unknown, keepOldHome?: boolean): Promise<SessionOpResult>; // wire always omits keepOldHome (true)
  replaceRoot(sessionId: string, oldPath: string, newPath: string): Promise<SessionOpResult>;  // host API for mf-files Locate (L11)
  setProject(sessionId: unknown, projectId: unknown): SessionOpResult;
  resolveInitialRoots(home: string, roots: unknown): Promise<{ roots: string[]; missing: string[]; dropped: DroppedRoot[] }>;
  revalidate(sessionId: string, root: string): Promise<SessionOpReason | null>;   // Slice 6: full probe for a returning root
}
export function createSessionOps(deps: SessionOpsDeps): SessionOps;
```
Every async op: after the probe, re-`get` the session (`unknown-session` if gone) and compute
existing keys from the **current** folders via `folderKeysOf(…, realKeys)` before
`placementConflict` and the `MAX_ROOTS` check. Candidate keys = `[key, realKey?]`. Existing sets:
`addRoot` → home + roots; `replaceRoot` → home + roots minus old (old must be in roots:
`not-attached`), result at the same index; `setHome` swap (path's key ∈ roots) → no probe, no
conflict; `setHome` new path → must be present (`not-found`), existing = home (omitted when
`keepOldHome === false`) + roots; `too-many` when roots would exceed 32. `removeRoot`: non-string →
`invalid-path`; home's key → `is-home`; absent → `not-attached`. It leaves `realKeys` alone: that is a host-wide path cache another session may still resolve through, and a re-add re-probes it (code review F3).
`setProject`: `null` clears; unknown string → `unknown-project`; other type → `unknown-project`,
logged. `resolveInitialRoots`: non-array → all empty; entries in order, each probed; `missing`
entries checked lexically against home + accepted; present ones with real keys; home's key →
`is-home`; failures → `dropped`. `revalidate`: probe `root`; `missing` → `'not-found'`; else
conflict against the session's other folders (excluding `root`) → reason or `null`, writing
`realKeys` on success. `onFoldersChanged` fires once per successful mutating op.

### `electron/project-watcher.ts`
```ts
type WatchFn = (dir: string, opts: { recursive: true }, cb: (event: string, filename: string | Buffer | null) => void) => fs.FSWatcher;
export interface FsFire { root: string; folders: string[] }
export class ProjectWatcher {
  constructor(onFire: (fire: FsFire) => void, opts?: {
    debounceMs?: number; log?: (m: string) => void;
    onSuspect?: (folders: string[]) => void;   // a watch errored (then unregistered) or reported a null filename
    watch?: WatchFn;
  });
  setFolders(folders: readonly string[]): void;   // replaces watch(root)
  stop(): void;
}
```
Registered folders deduped by key (first spelling wins); a folder under another shares its
ancestor's recursive watch; same set → no-op; dropped ancestors' watches closed. On each event:
`abs = watchRoot + '/' + filename`; the containing registered folders are computed **on arrival**;
`shouldIgnoreWatchPath` is evaluated on the path **relative to the deepest** containing folder; if
not ignored, their indexes go into a per-window `Set<number>` (bounded by the folder count — no path
strings retained). A null/empty filename marks every folder of that watch and calls `onSuspect`.
On fire: ONE `onFire({ root, folders })`, `folders` = touched folders in registration order, `root =
folders[0]`. Parity: one registered folder → one watch, one fire per window, `{root: p, folders: [p]}`.

### `src/folder-health.ts`
```ts
export type FolderState = 'present' | 'missing' | 'unknown';   // unknown = could not be issued within the timeout (cap saturated)
export interface FolderHealthReport { sessionId: string; homeKey: string; states: Map<string, FolderState> } // keyed by folderKey
export interface FolderHealthDeps {
  isDir: (p: string) => Promise<boolean>;
  get: (id: string) => Session | undefined;
  sessions: () => readonly Session[];
  apply: (r: FolderHealthReport, bounded: Bounded) => Promise<void>; // awaited; `bounded` runs apply's own fs work (revalidate, realpath) in the stat slots under one 3 s window, `undefined` = not done in time (code review F4)
  timeoutMs?: number;     // 3000
  pollMs?: number;        // 5000
  maxInFlight?: number;   // 2 (S3)
}
export class FolderHealth {
  constructor(deps: FolderHealthDeps);
  check(sessionId: string, only?: readonly string[]): Promise<void>;   // home + roots, or just `only`
  pending(sessionId: string): Promise<void> | undefined;
  dispose(): void;
}
export function applyHealthReport(
  s: Pick<Session, 'home' | 'roots' | 'missingRoots' | 'homeMissing'>,
  r: FolderHealthReport,
  rejected: ReadonlySet<string>,   // keys of returning roots whose revalidation failed
): { homeKey: string; missingRoots: string[]; homeMissing: boolean };
```
One `isDir` per key in flight (shared); at most `maxInFlight` outstanding across all keys, others
queue; the 3 s timeout starts at **issue** (timeout ⇒ `missing`); a folder still queued when its
check's own 3 s window closes ⇒ `unknown` (keeps its previous state). A key whose stat is unsettled
past its timeout is not re-issued by the poll. Poll interval exists iff any session has
`homeMissing` or `missingRoots`; a tick checks only those folders. `applyHealthReport`: `present` →
cleared unless the key is in `rejected`; `missing` → marked; `unknown` → unchanged; home only when
`r.homeKey === folderKey(s.home)`.

## Deviation rule

If a task's assumption turns out wrong — the piece it builds on is misaligned, a locked signature
doesn't fit reality — that task **stops** and fixing the misaligned piece becomes the work. Never a
shim, second copy, special case, widened type, alias field, fallback, or an override patched in
place of its semantic source. The report leads with the fix that keeps the locked decision.
