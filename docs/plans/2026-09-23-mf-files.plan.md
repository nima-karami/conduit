# mf-files — implementation plan

**Spec:** `docs/specs/2026-09-23-mf-files.md`  **Tier:** FULL

Tier reason: this touches the Files tab, the Search pane, quick open, the TS index and the explorer
drop path. It adds one new host handler (`session:locateFolder`, L11) and a new renderer test seam,
and splits the 1.9k-line `right-pane.tsx` FilesView into per-folder sections.

Build order is serial (`.autoloop/tasks.yaml`): mf-model, then mf-changes, then mf-new-session, then
**mf-files**, then mf-sidebar, mf-review, mf-live-edits and mf-board. Anchors like `right-pane.tsx:1395`
are from main `524474d`, which is the code before the three upstream items land. After they land,
look up functions **by name**, not by line.

## Goal

The Files tab renders one bar and one tree per session folder (home first, then the attached
folders), plus a `+ Add folder…` button. Each bar has a `···` menu, and a missing folder shows a
warning box with Locate/Remove. An OS folder dropped on the tree can be attached instead of copied.
Search in files groups results by folder, quick-open rows carry folder tags, and the TS index covers
every folder, with compiler options taken from home. None of these surfaces follow the terminal's
`cd` any more.

## Architecture

The renderer holds no folder list of its own. `sessionSections(active)`, a pure function in
`src/session-sections.ts`, turns `home`/`roots`/`missingRoots`/`homeMissing` into ordered section
models, and every surface derives from it:

- The Files tab, via `FilesView` (moved out of `right-pane.tsx` into `webview/components/files-view.tsx`):
  - FilesView owns the **pane-wide** state: drag set, clipboard, conflict prompt, the `committing`
    lock, the drop menu and the shared scroller.
  - Each present folder is a `FolderSection` (`webview/components/folder-section.tsx`). It owns the
    **per-folder** tree state: nodes, selection, roving focus, drafts, reveal and its window over the
    shared scroller.
- Search, quick open and indexing, through `presentFolders`.

Folder edits go through one renderer module, `webview/folder-actions.ts`, which sends mf-model's L3
messages and this item's `session:locateFolder` via mf-new-session's `requestHost`. Locate is
host-side: `src/folder-locate.ts` picks through the one `FolderPicker` seam and replaces the folder in
place with mf-model's `SessionOps.replaceRoot` / `setHome(…, false)`.

## Settled decisions — do not re-litigate

- `.autoloop/locked.md` L1–L12 are the frame. Spec §13 D1–D18 are taken as picked, except where L11
  or L12 override them (see Spec staleness).
- **L11: one picker seam.** Add folder uses `folder:pick` + `__pickDirHook` (mf-new-session). Locate
  uses the same `FolderPicker` instance on the host. There is no `__folderPickerQueue` and no
  `app.evaluate` dialog stub.
- **L11: one Locate handler.** `session:locateFolder` is **built here**, and mf-live-edits' centre
  pane consumes it. Validation is mf-model's single validator, reached through `SessionOps`:
  duplicates and overlaps are both rejected, excluding the folder being replaced. Home locate drops
  the old path, via `keepOldHome = false`. Re-picking the folder's own path after it has returned is
  a no-op success.
- **L12 B3.** `fsChanged {root, folders}` fires once per watcher fire. This item adds **no**
  `refreshChanges` call; the per-section tree refresh and the index top-up iterate `msg.folders`.
- **L12 S1.** This item adds no host folder-lifecycle site. Every edit goes through `SessionOps`,
  whose ops call `onFoldersChanged`.
- **D1.** Files, Search and quick open cover the session's folders only; the tree never re-roots on
  `cd`. D18: tokens are `--accent`/`--accent-soft`/`--amber`/`--danger`, with no hex values.
- **D2.** One `role="tree"` per section, all stacked in one scroller (`.right__scroll--files`).
  Bars are not sticky.
- **D3.** The bar chevron collapses the section and all its subfolders.
- **D9.** Remove has no confirm and offers an Undo toast.
- **D16.** Remove is refused while that folder has dirty tabs.
- **D17.** In a mixed drop, eligible folders attach and everything else copies.
- Every per-folder map is keyed by `folderKey` (mf-model), never by the raw path. This covers the
  tree cache, collapsed set, search replies, quick-open corpus and indexed roots.

## Global constraints

- **Gate:** `npm run verify`. Never weaken, narrow, skip or defer a check, and read its exit code
  directly (never through `| tail`). Per task, run `npx vitest run <file>`. `npm run typecheck` runs
  both tsconfigs.
- **Renderer-safe** (no runtime `node:*`, no `process`): `src/session-sections.ts`,
  `src/os-drop.ts`, `src/folder-search.ts`, `src/quick-open-folders.ts`, `src/folder-locate.ts`.
  `src/folder-locate.ts` is imported only by the host, but it stays dependency-injected and pure.
- **Unit tests are platform-neutral.** They never read `process.platform`, native `path` or
  `path.basename`, because CI is ubuntu. Paths are strings with explicit separators, and every keyed
  test includes one `C:\` vs `c:/` casing case.
- **Every export has a production importer** by the end of its slice (fallow). Test-only helpers
  stay module-private and are tested through their public caller.
- **Naming.** Files are kebab-case and components PascalCase. Unit tests are
  `test/unit/<module>.test.ts`. E2e tests are `test/e2e/<name>.e2e.mjs` on `test/e2e/harness.mjs`
  (`runScenario`, `launchApp`, `closeApp`, `openSession`, `tapBridge`, `assert`). They run hidden
  and serially with `node test/e2e/run-smoke.mjs <name>`, but **the builder does not run
  `npm run build`/e2e while another agent holds the PTY suite**. The e2e runs are listed per slice
  for the integrator.
- **Comments explain WHY only.** Point at the spec section (`// see mf-files spec §2.7`) rather than
  restating it.
- **User copy** is verbatim from spec §2/§10 or as pinned here. It lives in an `STR` const in the
  module that renders it. Counts use `countNoun(n, one, many)` (`src/menu-selection.ts:27`, which
  includes the number).
- **CSS:**
  - Tokens only.
  - Reuse `.iconbtn`, `.btn`, `.btn--primary`, `.ctxmenu__item--danger`, the `.files__bar` family and
    `.palette__badge[data-tone]`.
  - New interactive classes join the rows of the interaction-state vocabulary section in
    `webview/styles.css` where `.iconbtn` sits. `test/unit/state-vocabulary.test.ts` stays unmodified
    and green.
  - `@media (forced-colors: active)`: the tags get `1px solid CanvasText`.
- **Rows and focus:**
  - Virtualized rows stay direct keyed children (`flatMap`, never `[row, extra]`).
  - A wheel handler that must `preventDefault` binds natively (none planned).
- **Overlays** use `ContextMenu`/`Popover` only; no new layer.

### `src/folder-locate.ts` (pure, deps injected; host is the only importer)
```ts
import type { Session } from './types';
import type { SessionOpResult } from './session-ops';   // type-only
import type { LocateReason } from './protocol';
export interface LocateDeps {
  get: (sessionId: string) => Session | undefined;
  pick: (defaultPath: string | undefined) => Promise<string | null>;
  isDir: (p: string) => Promise<boolean>;
  dirname: (p: string) => string;                    // host: path.dirname
  ops: {
    setHome: (sessionId: string, path: string, keepOldHome: boolean) => Promise<SessionOpResult>;
    replaceRoot: (sessionId: string, oldPath: string, newPath: string) => Promise<SessionOpResult>;
  };
}
export type LocateOutcome = { ok: true; path: string } | { ok: false; reason: LocateReason };
export function locateFolder(sessionId: unknown, path: unknown, deps: LocateDeps): Promise<LocateOutcome>;
// module-private: nearestExistingAncestor(p, deps) — walk dirname until isDir or dirname(p) === p (→ undefined)
```
The steps, in order:

1. A non-string `sessionId`, or a session that `get` does not find, returns `unknown-session`.
2. A non-string `path` returns `invalid-path`.
3. The target is resolved by folder key: `folderKey(path) === folderKey(home)` means home.
   Otherwise the target is the attached root with that key, and the stored spelling is used as
   `oldPath`. No match returns `not-attached`.
4. `pick(await nearestExistingAncestor(path))` runs. A `null` result returns `cancelled`.
5. For home, `ops.setHome(id, picked, false)` runs. For an attached root,
   `ops.replaceRoot(id, oldPath, picked)` runs.
6. A result of `{ok: true}` returns `{ok: true, path: picked}`. Otherwise the reason is returned
   unchanged.

### `webview/tree-window.ts`
```ts
export interface SectionWindowInput extends FixedWindowInput { sectionTop: number }  // section's first-row offset in the scroller content
/** Window of one section against the shared scroller. A section whose rows are entirely outside
 *  [scrollTop − overscan·rowHeight, scrollTop + viewportHeight + overscan·rowHeight] mounts only its pins. */
export function computeSectionWindow(input: SectionWindowInput): FixedWindowResult;
```
If the section is fully off-screen, the result is `startIndex = endIndex = 0` (plus pins, handled
the same way `computeFixedWindow` handles them), with `padTop + padBottom = totalHeight`. Otherwise
it calls `computeFixedWindow` with `scrollTop = max(0, scrollTop − sectionTop)` and
`viewportHeight = min(viewportHeight, scrollTop + viewportHeight − sectionTop)` when the section
starts below the top.

```ts
import type { requestHost } from './host-request';
import type { PushToastInput } from './toast-store';
export type FolderActionOutcome =
  | { kind: 'added'; key: string; name: string }
  | { kind: 'located'; key: string; name: string }
  | { kind: 'removed'; key: string; name: string }
  | { kind: 'none' };

  sessionId: string;
  request: typeof requestHost;
  post: (m: WebviewToHost) => void;
  toast: (t: PushToastInput) => void;
  dirtyPaths: () => ReadonlySet<string>;      // app: getDirtySnapshot (webview/dirty-store.ts)
}
export interface FolderActions {
  add(): Promise<FolderActionOutcome>;
  remove(section: FolderSectionModel): Promise<FolderActionOutcome>;
  makeHome(section: FolderSectionModel): Promise<void>;
  locate(section: FolderSectionModel): Promise<FolderActionOutcome>;
  attach(paths: readonly string[]): Promise<{ attached: string[]; failed: string[] }>;   // Slice 4
}
export function createFolderActions(deps: FolderActionsDeps): FolderActions;
// module-private: PICK_TIMEOUT_MS = 30 * 60_000; OP_TIMEOUT_MS = 15_000
```
Rules. `<name>` is `section.label`, or `repoBaseName(path)` for a path that isn't a section yet:

- **add:**
  - It sends `folder:pick`, then waits for `folder:picked`.
  - A `null` or timed-out pick returns `none` and shows nothing.
  - Otherwise it sends `session:addRoot {sessionId, path, requestId}` and waits for
    `session:opResult`.
  - On `ok`, it returns `added` with `key = folderKey(path)`.
  - On failure (or a `null` reply) it shows an error toast from the §2.6 table:
    `duplicate` → `<name> is already in this session.`, `overlaps` →
    `<name> overlaps a folder already in this session.`, anything else → `Couldn't add <name>.`
- **remove:**
  - Let `n` = the number of dirty paths equal to or inside `section.path` (`isAncestorOf`, compared
    by `folderKey`).
  - If `n > 0`, it shows an error toast `Save or close ${countNoun(n, 'unsaved file', 'unsaved files')} in <name> first.`,
    posts nothing and returns `none`.
  - Otherwise it sends `session:removeRoot` and waits. On `ok`, it shows an info toast
    `Removed <name> from session`.
  - That toast carries `action: {label: 'Undo', run}` unless `section.missing`. `run` posts
    `session:addRoot` with the **captured** `sessionId` and `path` and awaits the reply. A
    `duplicate` reply is silent; any other failure uses the add table.
  - On failure it shows `Couldn't remove <name>.`
- **makeHome:** sends `session:setHome`. On failure it shows `Couldn't make <name> home.`
- **locate:**
  - It sends `session:locateFolder {sessionId, path: section.path, requestId}` with
    `PICK_TIMEOUT_MS`.
  - `ok` returns `located` with `key = folderKey(result.path)`. `cancelled` or `null` returns
    `none` and shows nothing.
  - Failures toast `duplicate` → `<picked name> is already in this session.`, `overlaps` → the
    overlaps copy for the picked name, anything else → `Couldn't locate <name>.` (the picked name
    comes from `result.path` when present, else `section.label`).
- **attach:** runs `session:addRoot` for each path, serially, collecting `attached` and `failed`.
  It shows no toast (the caller composes one).

## Deviation rule

If a task's assumption turns out wrong, that task **stops**, and fixing the misaligned piece becomes
the work. This covers an upstream export that is missing or shaped differently, a locked signature
that doesn't fit, or a reply that arrives in another shape.

The fix is never a shim, a second copy, a special case, a widened type, a fallback, or an override
patched in over the semantic source. In particular:

- no second folder-conflict rule (drop eligibility goes through `findFolderConflict`);
- no renderer-side Locate replacement;
- no second picker seam;
- no per-folder `refreshChanges`;
- no folder list held in renderer state.

The report leads with the fix that keeps the locked decision.
