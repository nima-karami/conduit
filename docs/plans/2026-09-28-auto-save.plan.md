# Auto-save — implementation plan

**Spec:** `docs/specs/2026-09-28-auto-save.md`  **Tier:** FULL

## Goal

VS Code `files.autoSave` parity (`off` / `afterDelay` / `onFocusChange` / `onWindowChange`) for every
`CodeViewer` host. Auto-saves never overwrite a file that changed on disk. Save ownership moves out of
the editor into a per-path store backed by the Monaco model.

## Architecture

Four layers, each with one owner:

1. **Host precondition** (`src/file-service.ts` `writeFile` + `electron/main.ts` IPC). An optional
   `expected` is compared against an uncapped utf8 read of the target *after* the existing
   `validateWrite` / read-grant checks. A mismatch writes nothing and returns `conflict`.
2. **Pure policy** (`webview/auto-save-policy.ts`). The §2.3 state machine as a reducer, plus the
   §2.2 trigger matrix. No timers, React, Monaco or bridge.
3. **Per-path save store** (`webview/file-save-controller.ts`, factory `createFileSaves(deps)`).
   Every dependency is injected, so it unit-tests with a fake model and fake timers. It owns the
   baseline, the model content subscription, timers, the single-flight write chain, the
   `save-registry` entry and the published status. `webview/file-saves.ts` is the singleton that
   wires the real deps (Monaco model, bridge `writeFile`, `notifySaved`, toasts).
4. **Glue**. `CodeViewer` attaches on mount, forwards editor-blur and view-leave triggers, and
   renders the conflict/failure banner from the status. `app.tsx` pushes settings into the store,
   forwards window blur, disposes the store on tab close, and does save-on-close. `doc-tabs` shows the
   conflict marker.

The store lives in a module, not in `CodeViewer`, so it survives the editor being recreated on every
save (C8) and tab unmount (C9). Its baseline is no longer assigned during render
(`code-viewer.tsx:137`), and that removes the spec §2.2 "flush sees a stale baseline" hazard at the
structural level. **Split-editor compatibility:** the store is keyed by path, and every group
showing a path shares its one Monaco model, so a second `CodeViewer` on the same path calls the
idempotent `attach` and shares the same entry, timer and status. Nothing here assumes a single mount.

## Data flow

```
Settings modal ─update()─▶ AppSettings{autoSave, autoSaveDelay} ─(App effect)─▶ fileSaves.configure({mode, delayMs})

CodeViewer mount ─ attach(path,{diskContent, autoEligible}) ─▶ store entry (created once per open tab)
                                                                 ├─ subscribes model.onDidChangeContent (model outlives editor)
                                                                 ├─ registerSave(path, entry)  ◀── Ctrl+S / Save All / closeDoc / tab dot
                                                                 └─ reconciles model with disk (seed ≠ edit)
model edit ─▶ updateDirty(path, baseline, value)  +  autoSaveStep({edit}) ─effects─▶ arm/clear timer
triggers:  timer | CodeViewer onDidBlurEditorWidget | CodeViewer unmount (keyed on doc.path) | window 'blur' (App → flushAll)
           ─▶ autoSaveStep({trigger}) ─ {save, kind:'auto'} ─▶ single-flight chain
chain ─ bridge.writeFile(path, buffer, {expected: baseline}) ─IPC─▶ main.ts parseWriteOptions ─▶ file-service.writeFile
            validateWrite / grant (unchanged) ─▶ uncapped read ─ equal ─▶ atomic temp+rename ─▶ {ok:true}
                                                              ├ differs ─▶ {ok:false, conflict:'changed'}
                                                              └ ENOENT  ─▶ {ok:false, conflict:'deleted'}
result ─▶ autoSaveStep({writeDone}) ─▶ status map ─(useSyncExternalStore)─▶ CodeViewer banner, doc-tabs marker
ok ─▶ baseline = written; notifySaved (app files map) + refreshIndexedFile
```

State lives in the renderer (per window, in memory) and on disk. The only thing that crosses IPC is
the extra `writeFile` argument and the extra `conflict` field in the result.

## Settled decisions — do not re-litigate

- **D1 (locked by conductor):** the precondition applies to auto-save and save-on-close writes only
  (`kind: 'auto'`). Manual Ctrl+S / Save All / tab-dot saves (`kind: 'manual'`) stay unconditional,
  but they **refuse while the path is in `conflict`**. Only the banner's Overwrite (`kind: 'force'`)
  writes over a conflict.
- **D11 (locked by conductor):** save ownership moves to the model-backed per-path store and stays
  registered while the tab is open, mounted or not. This also fixes Save All and close→Save for
  dirty background tabs in every mode, `off` included.
- **D3 (locked by conductor):** there is no guaranteed pre-quit save. Window blur plus the existing
  best-effort `beforeunload` save-all are all that run. See Spec staleness S1 on the quit guard.
- **D8 (locked by conductor):** Slice 1 measures C2–C11 in the real built app before anything is
  built on them. Any claim that measures false stops the run with a report.
- D2: with auto-save on, close-dirty saves silently with `kind:'auto'` and falls back to the
  existing Save/Discard/Cancel prompt, prefixed with the reason.
- D4: the dirty dot shows during the delay window.
- D5: `onFocusChange` also saves on window blur.
- D6: delay range is 100–60000 ms, default 1000.
- D7: truncated (> 2 MB) and binary docs are never auto-saved. Manual save is unchanged. The
  truncation hazard is not fixed here.
- D9: the controls live in Settings → Appearance → "Editor & code".
- D10: an auto-save failure toasts only on the first failure of a streak per path. The banner always
  shows.
- Plan decision P1: `AutoSaveMode`, the delay bounds and the persisted-value parse live in
  `src/settings.ts`, because `src/` can't import `webview/` and the host parses settings. The spec's
  `parseAutoSave` / `clampAutoSaveDelay` are therefore **not** added to `auto-save-policy.ts`, where
  they would duplicate the settings parse.
- Plan decision P2: reducer effects are a tagged union
  (`{type:'save', kind}` | `arm` | `clear` | `reportFailure`), not a string union. `save` needs a
  kind, and the spec's `showConflict` is dropped because the published status already drives the
  banner and the tab marker.
- Plan decision P3: streak throttling (D10) applies to `auto` writes only. A manual save failure
  still toasts every time, as it does today.
- Plan decision P4: the store's `dispose(path)` runs exactly where `clearDirty(path)` runs today
  (`forceCloseDoc`, `webview/app.tsx:1646`), so the store and the dirty flag share one lifecycle.
- Plan decision P5: the model→disk reseed (`code-viewer.tsx:172-182`, value only) moves into
  `attach`. A reseed is tagged so the content listener counts it as a seed and never as a user edit
  (C10 eligibility). The language fix (`setModelLanguage`) stays in `CodeViewer`.

## Spec staleness

- **S1: the conductor's D3 note says "the existing quit guard keeps prompting for anything still
  dirty."** Measured statically: `src/quit-guard.ts:1-30` decides from running **sessions** only, and
  `confirmQuit` (`webview/app.tsx:503-526`) carries `msg.running`, a session count. No quit guard
  exists for dirty files, and that matches spec C5. This plan adds none, because it would be the
  spec's v1 "guaranteed pre-quit flush". Slice 1 measures C5 in the built app. Logged as Decisions
  Needed #1.
- **S2: spec §4, "Rename/move of an open dirty file: flush the old path before `dropDocsFor`."**
  `onFileRenamed` (`webview/app.tsx:2557-2567`) is the explorer's `onRenamed` callback
  (`webview/components/right-pane.tsx:235`). It runs **after** the host has already renamed the
  file, so an `auto` flush to the old path always gets `conflict:'deleted'`, and writing without the
  precondition would recreate the old file. The flush as specified can never succeed. This plan
  makes **no change to rename** (the pre-existing C11 loss stays, as D11 already accepted). Slice 1
  confirms the ordering while measuring C11. Logged as Decisions Needed #2.

## Contracts

### Host write precondition — `src/path-guard.ts`, `src/file-service.ts`, `electron/main.ts`, `electron/preload.ts`, `webview/bridge.ts`

```ts
// src/path-guard.ts (beside WriteResult)
export type WriteConflict = 'changed' | 'deleted';
export type WriteResult =
  | { ok: true; path: string }
  | { ok: false; error: string; conflict?: WriteConflict };
export interface WriteOptions {
  /** Content the renderer last knew to be on disk; present ⇒ compare-before-write. */
  expected?: string;
}

// src/file-service.ts
export async function writeFile(
  absPath: string,
  content: string,
  roots: readonly string[],
  grants?: GrantStore,
  opts?: WriteOptions,
): Promise<WriteResult>;
/** IPC trust boundary: undefined → {}; a plain object whose `expected` is absent or a string →
 *  {expected?}; anything else (null, array, non-string expected, extra keys ignored) → null. */
export function parseWriteOptions(raw: unknown): WriteOptions | null;
```

Invariants:

- The `validateWrite` → grant fallback → directory refusal order is untouched, and the compare runs
  only **after** `target` is resolved. A rejected path returns the verdict it returns today, whether
  or not `expected` is set.
- With `expected`, the host reads with `fs.promises.readFile(target)` (no cap, no binary sniff) and
  decodes with `.toString('utf8')`, the same decode as `readFile` at `src/file-service.ts:108`.
  - `ENOENT` → `{ ok:false, conflict:'deleted', error:'The file was deleted on disk.' }`
  - Any other read error → `{ ok:false, error: <message> }`, with no `conflict`.
  - A decoded value `!== expected` → `{ ok:false, conflict:'changed', error:'The file changed on disk.' }`
  - Equal → the existing temp+rename write.
- Without `expected`, behaviour is byte-for-byte today's, including the grant branch recreating a
  deleted granted file.
- IPC: `ipcMain.handle('writeFile', async (_e, p: string, content: string, rawOpts?: unknown) => …)`.
  `parseWriteOptions(rawOpts) === null` returns `{ ok:false, error:'Invalid write options.' }` and
  writes nothing. The try/catch stays.
- Preload: `writeFile(path: string, content: string, opts?: WriteOptions): Promise<WriteResult>`
  passes `opts` as the third invoke arg. Bridge interface (`webview/bridge.ts:63`) and
  `export function writeFile(path: string, content: string, opts?: WriteOptions): Promise<WriteResult>`
  keep the browser-preview fallback.

### Policy — `webview/auto-save-policy.ts`

```ts
import type { AutoSaveMode } from '../src/settings';
import type { WriteConflict } from '../src/path-guard';

export type AutoSavePhase = 'clean' | 'dirty' | 'saving' | 'failed' | 'conflict';
export type AutoSaveTrigger = 'timer' | 'editorBlur' | 'viewLeave' | 'windowBlur';
export type SaveKind = 'auto' | 'manual' | 'force';

export interface AutoSaveState {
  phase: AutoSavePhase;
  /** A user edit made the buffer dirty since attach / the last successful save (C10). */
  edited: boolean;
  /** Trailing request raised while `saving`; strongest wins: force > manual > auto. */
  pending: SaveKind | null;
  conflict: WriteConflict | null;
  /** A failure was already reported since the last success (D10). */
  failStreak: boolean;
}
export const INITIAL_AUTO_SAVE_STATE: AutoSaveState; // clean, false, null, null, false

export type AutoSaveEvent =
  | { type: 'edit'; dirty: boolean }
  | { type: 'trigger'; trigger: AutoSaveTrigger }
  | { type: 'request'; kind: SaveKind } // explicit call: Ctrl+S, Save All, close (auto), Overwrite (force)
  | { type: 'writeDone'; outcome: 'ok'; dirty: boolean }
  | { type: 'writeDone'; outcome: 'failed'; kind: SaveKind }
  | { type: 'writeDone'; outcome: 'conflict'; conflict: WriteConflict }
  | { type: 'reset' }
  | { type: 'modeChanged' };

export type AutoSaveEffect =
  | { type: 'save'; kind: SaveKind }
  | { type: 'arm' }
  | { type: 'clear' }
  | { type: 'reportFailure' };

/** §2.2 matrix: does `trigger` save in `mode`? */
export function triggerSaves(mode: AutoSaveMode, trigger: AutoSaveTrigger): boolean;
export function autoSaveStep(
  state: AutoSaveState,
  event: AutoSaveEvent,
  mode: AutoSaveMode,
): { state: AutoSaveState; effects: AutoSaveEffect[] };
```

Transition table (every row is a unit test):

| Phase | Event | Next state | Effects |
|---|---|---|---|
| clean/dirty/failed | `edit{dirty:true}` | phase `dirty` (failed stays `failed`), `edited:true` | `arm` iff mode `afterDelay` |
| clean/dirty/failed | `edit{dirty:false}` | `clean`, `edited:false` | `clear` |
| saving | `edit{dirty:true}` | unchanged, `edited:true` | `arm` iff `afterDelay` |
| saving | `edit{dirty:false}` | unchanged | — |
| conflict | `edit{*}` | unchanged | — |
| dirty/failed, `edited` | `trigger t`, `triggerSaves(mode,t)` | `saving` | `clear`, `save auto` |
| dirty/failed, `!edited` | `trigger` | unchanged | — |
| saving | `trigger t`, `triggerSaves` | `pending = max(pending,'auto')` | — |
| clean/conflict | `trigger` | unchanged | — |
| clean | `request` | unchanged | — (caller resolves true) |
| dirty/failed | `request k` | `saving` | `clear`, `save k` |
| saving | `request k` | `pending = max(pending,k)` | — |
| conflict | `request manual` or `request auto` | unchanged | — (caller resolves false) |
| conflict | `request force` | `saving`, `conflict:null` | `save force` |
| saving | `writeDone ok dirty:false` | `clean`, `edited:false`, `pending:null`, `failStreak:false` | — |
| saving | `writeDone ok dirty:true`, `pending p` | `saving`, `pending:null`, `failStreak:false` | `save p` |
| saving | `writeDone ok dirty:true`, no pending | `dirty`, `failStreak:false` | — |
| saving | `writeDone failed k` | `failed`, `pending:null`, `failStreak:true` | `reportFailure` iff `k!=='auto' \|\| !failStreak` |
| saving | `writeDone conflict c` | `conflict`, `conflict:c`, `pending:null` | `clear` |
| any | `reset` | `INITIAL_AUTO_SAVE_STATE` | `clear` |
| any | `modeChanged` | unchanged | `clear` |

`triggerSaves` matrix: `off` → never. `afterDelay` → timer, viewLeave, windowBlur. `onFocusChange` →
editorBlur, viewLeave, windowBlur. `onWindowChange` → windowBlur.

### Store — `webview/file-save-controller.ts`

```ts
import type { AutoSaveMode } from '../src/settings';
import type { WriteConflict, WriteOptions, WriteResult } from '../src/path-guard';
import type { AutoSavePhase, AutoSaveTrigger, SaveKind } from './auto-save-policy';
import type { SaveEntry } from './save-registry';

export interface SaveModel {
  getValue(): string;
  setValue(value: string): void;
  onDidChangeContent(cb: () => void): { dispose(): void };
}
export interface FileSaveDeps {
  getModel(path: string): SaveModel | null;
  write(path: string, content: string, opts?: WriteOptions): Promise<WriteResult>;
  canWrite: boolean;
  isMarkedDirty(path: string): boolean;                 // getDirtySnapshot().has
  setDirty(path: string, baseline: string, buffer: string): void; // updateDirty
  clearDirty(path: string): void;
  register(path: string, entry: SaveEntry): () => void; // registerSave
  onSaved(path: string, content: string): void;         // notifySaved + refreshIndexedFile
  requestRead(path: string): void;                      // post({type:'readFile', path})
  toast(message: string): void;                         // pushToast({variant:'error'})
  setTimer(cb: () => void, ms: number): unknown;
  clearTimer(handle: unknown): void;
}
export interface AttachOpts {
  diskContent: string;
  /** false for a truncated doc (D7); binary docs never attach. */
  autoEligible: boolean;
}
export interface FileSaveStatus {
  phase: AutoSavePhase;
  conflict: WriteConflict | null;
  /** Last write failure reason; cleared when a write starts. */
  error: string | null;
}
export interface FileSaves {
  configure(cfg: { mode: AutoSaveMode; delayMs: number }): void;
  attach(path: string, opts: AttachOpts): void;
  dispose(path: string): void;
  save(path: string, kind: SaveKind): Promise<boolean>;
  trigger(path: string, trigger: AutoSaveTrigger): void;
  flushAll(trigger: 'windowBlur'): Promise<void>;
  reload(path: string): void;
  revert(path: string): void;
  getStatus(path: string): FileSaveStatus | undefined;
  getStatusSnapshot(): ReadonlyMap<string, FileSaveStatus>;
  subscribe(cb: () => void): () => void;
}
export function createFileSaves(deps: FileSaveDeps): FileSaves;
```

Behaviour:

- **attach** is idempotent per path.
  - First call: create the entry, subscribe `model.onDidChangeContent` (kept until `dispose`), and
    `deps.register(path, { save: (o) => save(path, o?.kind ?? 'manual'), revert: () => revert(path) })`.
  - Every call: if `!deps.isMarkedDirty(path)` and `model.getValue() !== diskContent`, then
    `setValue(diskContent)` under a `seeding` flag. Then set `baseline = diskContent` and
    `autoEligible`, and finish with `deps.setDirty(path, baseline, model.getValue())` (a seed, not an
    edit).
  - No model → no-op.
- **Content listener:** `deps.setDirty(...)`. When not seeding, it also steps `{edit, dirty}`.
- **save(path, kind)** returns `Promise<boolean>`.
  - Unknown path → `true`.
  - Every call steps `{type:'request', kind}` (never a trigger; `request` ignores mode and `edited`). A write chain already in flight → the step only raises `pending`; await the chain and return
    its final result. There is only ever one chain per path (E1).
  - Clean → `true`.
  - `conflict` with `manual` → `false`.
  - `!deps.canWrite` → for `auto`, return `false` silently. For `manual`/`force`, record error
    `'Saving is unavailable in the browser preview.'`, toast it, and return `false`.
  - A `save` effect writes `model.getValue()`, passing `{ expected: baseline }` iff `kind==='auto'`,
    and sets status `error:null`.
  - On `ok`: `baseline = written`, `deps.setDirty`, `deps.onSaved`, then step
    `writeDone ok dirty: model.getValue()!==baseline`. A trailing `save` effect chains inside the
    same promise.
  - On `conflict` / other failure: step `writeDone` accordingly, and set status `error` to
    `res.error`.
  - A write that resolves after `dispose` is ignored entirely.
- **trigger** is a no-op for an unknown path, an entry with `!autoEligible`, or `!deps.canWrite`.
  Otherwise it steps `{trigger}` and runs the effects.
- **Effects:**
  - `arm` → `clearTimer` then `setTimer(() => trigger(path,'timer'), delayMs)`, using the delay
    current at arm time.
  - `clear` → `clearTimer`.
  - `reportFailure` → `deps.toast(AUTO_SAVE_COPY.saveFailed(name, error))`, except inside
    `flushAll`, where failures are collected instead.
- **flushAll('windowBlur')** runs `trigger` on every entry and awaits the chains. If ≥2 collected
  failures: toast `AUTO_SAVE_COPY.saveFailedMany(n)` once. If exactly 1: toast the per-file message.
- **configure:** a changed mode steps `modeChanged` on every entry (clearing timers). A changed delay
  only affects the next `arm`.
- **reload(path):** `deps.clearDirty(path)`, step `reset`, publish, then `deps.requestRead(path)`.
  The order matters: clear first, then read (spec §2.3).
- **revert(path):** `model.setValue(baseline)`. The listener recomputes dirty and steps `edit`.
- **dispose(path):** clear the timer, dispose the content subscription, unregister the save entry,
  delete the status, and notify.
- **Status publication:** the snapshot map is replaced (new identity) only when some path's
  `{phase, conflict, error}` actually changes. Each status object is immutable, so
  `useSyncExternalStore` stays stable.

## Deviation rule

If a task's assumption turns out wrong (the piece it builds on is misaligned, or a locked signature
doesn't fit reality), that task **stops** and fixing the misaligned piece becomes the work. Never a
shim, a second copy, a special case, a widened type, a fallback, or an override patched in place of
its semantic source. The report leads with the fix that keeps the locked decision. A Slice 1 claim
that measures false is a stop for the whole run (D8), not a local adaptation.

## Decisions Needed

- [high] #1: **There is no dirty-file quit guard (S1).** The conductor's D3 note assumes one keeps
  prompting. Measured: `src/quit-guard.ts` counts sessions only. Quitting with a dirty buffer, with
  no window blur first, still loses it. Default taken: none is added (it is the spec's v1 pre-quit
  flush). If a prompt is wanted, it is a host→renderer "dirty count" round-trip on the
  `confirmQuit` shape: a separate item.
- [normal] #2: **Rename flush (S2) is structurally impossible as specified.** The rename has already
  happened when `onFileRenamed` runs. Default taken: no rename change (C11 loss stays). A real fix
  would write the buffer to the **new** path with `expected: baseline` before reopening. That is
  cheap, but it is a new store API and outside D11's accepted scope.
- [normal] #3: P3. A manual save failure still toasts every time; only auto failures are
  streak-throttled. Default: as today for manual.
- [normal] #4: the `beforeunload` save-all stays `manual` kind (today's behaviour), so an
  unload-time save can overwrite an unseen agent change on a path that is not already in
  `conflict`. Default: unchanged (D1 keeps manual-kind writes unconditional). Switching it to
  `auto` is a one-line change if wanted.
