# mf-review — implementation plan

**Spec:** `docs/specs/2026-09-23-mf-review.md`  **Tier:** FULL

Tier reason: the spec is FULL, it adds wire fields (`repoRoot` on `git:resolveRange` / `git:rangeDiff`),
it re-keys every per-file identity inside Review across roughly 20 files, and it runs parallel executors.

## Goal

Review gets a leading `All repos ▼` chip. With All repos selected, Review lists every repo's working
tree grouped by repo, in both the cards and the navigator, with a reviewed count per repo. Commits
and compares are always about exactly one repo. A single-repo session is byte-for-byte today's
Review.

## Architecture

- **Repo scope rides `ReviewSource.repoRoot`.** There is no separate state. A pure resolver,
  `resolveReviewRepo`, turns `(source, reviewRepos, fallbackRoot)` into a root, or `null` for All
  repos. ReviewView and CenterPane both call it.
- **ReviewView's input is per-repo.** In place of `changes` + `changesRoot`, it takes
  `reviewRepos: RepoInfo[]` (the chip set, in display order) and
  `repoChanges: RepoChanges[] | undefined`.
- **One file type everywhere.** Every file inside Review is a `ReviewFile` (`ChangeDTO & { repoRoot }`),
  keyed by its absolute path (K1). That holds in every mode, on one code path.
- **Group headers are window items.** They are fixed-height items in the existing index-based
  windowing (`webview/review-window.ts`). An `itemOfFile` map keeps the cursor, anchors and
  `scrollToFile` file-indexed.
- **The host resolves the added `repoRoot` fields itself.** One helper accepts either a detected repo
  or the session's live-cwd repo (the terminal link rule). mf-changes wrote that rule inline for
  `git:commitDiff`; this plan extracts it and reuses it.
- **Reused from mf-changes, not rebuilt here:** `runGitFanOut`, `GitActionIntent.repoRoots`,
  `buildBulkMenuItems`/`BulkScope`, the repo-tag styling and `HunkActionHost.rootFor`.

## Settled decisions — do not re-litigate

- `.autoloop/locked.md` L1–L12 set the frame. The spec's §13 D1–D11 are accepted as picked.
  `.autoloop/blockers.md` accepts D9: notes and marks are written inside attached repos, and only on
  an explicit note or mark there.
- **L11 binds both surfaces.**
  - In All repos, `Stage all` and `Unstage all` fan out.
  - In All repos, `Discard all changes…`, `Stash changes` and `Pop stash` are disabled, each with a
    title explaining why. They are available per repo (when narrowed, and in a single-repo session).
  - Review keeps its own titles: action bar `Pick one repo to discard its changes`; navigator kebab
    `Pick one repo first`.
- **L12 S9:** `repoRoot` on `git:rangeDiff` / `git:resolveRange` is built here.
  **mf-changes Decisions Needed [high]:** `GitActionIntent.repoRoots` and `runGitFanOut` are built by
  mf-changes. This plan only consumes them.
- **K1:** internal file key = `joinPath(repoRoot, path)`.
  **K2:** stores and formats are unchanged.
  **K3:** `viewKey = sourceKey + '\0' + (resolved ?? '*')`, and marks keep the bare `sourceKey`.
- **Chip visibility:** visible iff `reviewRepos.length >= 2`. Global entry points open All repos:
  `Mod+Shift+R`, the palette, the Changes `Review` button and note-glyph clicks.
- **Handoff:** single repo or narrowed → byte-identical. All repos → grouped under `## <name>`,
  with paths from home (§3.3 / D5).
- **Tokens:** `--accent`, `--amber`, `--success`, `--danger`, `--text-dim`, `--border`, `--r-ctl`.
  Tag pills reuse mf-changes' `.repo-head__tag--home|--nested|--attached` classes as they are. No hex.

## Spec staleness

- **§11 tokens.** `--warn`, `--ok` and `--text-muted` do not exist in `webview/styles.css` `:root`
  (measured). The plan uses `--amber` (Nested), `--success` (a complete group count) and
  `--text-dim` (muted and Attached).
- **§2.1 S1 "stamped the first time the chip becomes visible".** Sources are never persisted
  (`webview/docs.ts:545-560`). After this change every builder stamps `repoRoot` (Slice 3), so an
  unstamped commit or range source can only be a pre-existing in-memory one. `resolveReviewRepo`
  resolves a commit or range without `repoRoot` to `fallbackRoot`, with no mutation. The observable
  result is the same.
- **§2.1 global entry "the session card".** mf-sidebar deletes `openReviewForSession` and the card's
  Review control (`docs/plans/2026-09-23-mf-sidebar.plan.md` T2.1). Nothing is left to change there.
- **§3.1 "Until repoChanges arrives, Review shows today's whole-list loading state".** Today there is
  no working-tree loading state. With `projectData` undefined, Review renders `Nothing to review`
  (`webview/components/review-view.tsx:1941-1947`). This plan keeps today's behaviour and adds no new
  state; only the chip hints read `…`.
- **§3.2 "`CommitPickerMenu` and `CompareDialog`".** `CompareDialog` is a separate module,
  `webview/components/compare-dialog.tsx:363`, rendered by `center-pane.tsx:412-430`.
- **§3.2 "`sourceKey`".** It is an inline const at `review-view.tsx:661-668`. Slice 2 extracts it as
  `reviewSourceKey` so K3 can be unit tested.
- **§2.7 ASSUMED rows.** Planning re-measured all six by source read, and all hold.
  - The only extra finding: `setReviewSource` drops `repoRoot` on commit sources too
    (`webview/app.tsx:694`).
  - The picker's commit rows (`commit-picker-menu.tsx:254,273`) and `buildPinnedSources`
    (`webview/review-picker-rows.ts:37,45,53`) build sources with no root.
  - `rangeDiff`/`resolveRange` resolve only via `gitRoot(session)`: `electron/main.ts:2408-2437` and
    `:2588-2626`.
  - The builder's red-first tests (Slices 2–4) are the runtime proof D7 asks for.

## Global constraints

- **Gate:** `npm run verify`. This pipeline's executors **do not run** `npm run build`, e2e or
  `verify` while another agent runs PTY e2e on this machine. The integrator runs them.
  - Never weaken, skip, narrow or defer a check.
  - Read exit codes directly; never pipe them through `tail`.
- **Unit tests:**
  - `npx vitest run <file>`, red first.
  - Test paths are forward-slash strings; add one `C:/` case where keys fold.
  - Never depend on `process.platform`, because CI runs on ubuntu.
- **Typecheck:** `npm run typecheck` runs both tsconfigs. `src/` never imports from `webview/`
  (measured: no such import exists). The new pure renderer modules therefore live in `webview/`.
- **Naming:**
  - kebab-case files; PascalCase components.
  - Tests in `test/unit/<module>.test.ts`; `renderToStaticMarkup` for component markup tests (the
    `review-scope-control.test.ts` precedent).
  - Strings for new components go in a local `STR` object; plurals go through `src/plural.ts`
    `plural(n, singular, pluralForm?)`.
- **Comments:** WHY only, per CLAUDE.md. Point to this spec's § numbers instead of re-explaining.
- **Fixed code and tests:**
  - `test/unit/review-restore-prepaint.test.ts` source-scans `ReviewView`. Its three markers must
    stay, each exactly once, inside `useLayoutEffect`:
    - `if (scrollRestoredRef.current) return;`
    - `setViewportHeight(el.clientHeight);`
    - `viewportHeight === 0) return;`
  - Virtualized rows stay direct keyed children. Group headers are siblings in the same `.map` over
    window items, never `[header, card]` tuples.
  - `.rcard[data-path]` stays repo-relative, because e2e selectors depend on it.
- **Overlays:** the chip menu is `ContextMenu` (portalled). The Review header is not under `.topbar`,
  so no app-region change is needed.
- **Colours and states:** tokens only. Disabled and locked looks come from the existing
  interaction-state vocabulary.

## Contracts

### `src/protocol.ts` (Slice 1)
```ts
| { type: 'git:rangeDiff'; sessionId: string; base: RefEndpoint; head: RefEndpoint; requestId: number; repoRoot?: string }
| { type: 'git:resolveRange'; sessionId: string; preset: RangePreset; requestId: number; repoRoot?: string }
// results gain an echo:
git:rangeDiffResult    { …today; repoRoot?: string }   // echoed exactly as sent
git:resolveRangeResult { …today; repoRoot?: string }
```
Rules:
- An invalid `repoRoot` runs no git.
- rangeDiff failure → `{ files: [], error: 'unknown repo', key, requestId, repoRoot }`.
- resolveRange failure → `{ error: 'unknown repo', preset, requestId, repoRoot }`.

### `src/active-repo.ts` (Slice 1; renderer-safe, deps injected)
```ts
/** repoRoot undefined → gitRootForSession(s). requestGitRoot hit → that root. A string whose folderKey
 *  equals folderKey(await liveRepo()) → repoRoot (terminal sha links, spec §2.1 D11). Else null. */
export async function resolveRequestRepoRoot(
  s: Pick<Session, 'repos' | 'activeRepoRoot' | 'cwd' | 'home'>,
  repoRoot: unknown,
  liveRepo: () => Promise<string>,   // host: () => sessionGitRoot(session, run); '' = none
): Promise<string | null>;
```
Host handlers `git:commitDiff` (replacing mf-changes' inline check), `git:rangeDiff`,
`git:resolveRange`, `git:history` and `git:refs` all call it as follows:
- Pass `m.root` for commitDiff and `m.repoRoot` for the others.
- `liveRepo` is called lazily, only when `requestGitRoot` misses.
- `null` → that handler's existing failure shape.

### `webview/review-repos.ts` (create, Slice 2; pure, renderer)
```ts
import type { ChangeDTO, RepoChanges } from '../src/protocol';
import type { RepoInfo, RepoTag } from '../src/repo-scan';
import type { ReviewSource } from './docs';
import type { ReviewScope } from './review-scope';

export const NOTES_ARTIFACT_PATH = '.conduit/review-notes.json';   // moved from review-view.tsx:219
export type ReviewFile = ChangeDTO & { repoRoot: string };
export function reviewFileKey(f: Pick<ReviewFile, 'repoRoot' | 'path'>): string;        // joinPath(repoRoot, path) — webview/file-tree.ts
export function cardDomKey(root: string, path: string): string;                          // `${folderKey(root)}\0${path}` — matches data-root/data-path

/** §2.1. working: no repoRoot → reviewRepos.length>=2 ? null : (reviewRepos[0]?.root ?? fallbackRoot ?? null);
 *  a repoRoot matching a reviewRepos root by folderKey → that reviewRepos root; unmatched → same as no repoRoot.
 *  commit/range: repoRoot ?? fallbackRoot ?? null (never checked against reviewRepos). */
export function resolveReviewRepo(source: ReviewSource | undefined, reviewRepos: readonly { root: string }[], fallbackRoot: string | undefined): string | null;
/** True iff source is working with a repoRoot that no reviewRepos root matches (the §4 "repo leaves" trigger). */
export function isStaleWorkingRoot(source: ReviewSource | undefined, reviewRepos: readonly { root: string }[]): boolean;
export function reviewViewKey(sourceKey: string, resolvedRoot: string | null): string;  // `${sourceKey}\0${resolvedRoot ?? '*'}`

/** The working list. root null → every entry in order; else only the folderKey-matching entry ([] if none).
 *  Per repo: first occurrence of a path wins; NOTES_ARTIFACT_PATH dropped. */
export function workingReviewFiles(repos: readonly RepoChanges[], root: string | null): ReviewFile[];
/** Commit/range files tagged with one root; same dedupe + artifact exclusion. */
export function tagReviewFiles<T extends { path: string }>(files: readonly T[], root: string): (T & { repoRoot: string })[];

export interface ReviewGroup { root: string; name: string; tag: RepoTag; sub?: string; branch?: string; files: ReviewFile[]; reviewed: number }
/** Groups in `repos` order; files keep input order; groups with 0 files dropped; reviewed = files whose key ∈ reviewed. */
export function groupReviewFiles(files: readonly ReviewFile[], repos: readonly RepoChanges[], reviewed: ReadonlySet<string>): ReviewGroup[];

/** app.tsx input normaliser. repos undefined or [] → the one-entry synthesis
 *  [{root: fallbackRoot, name: repoBaseName(fallbackRoot), tag: 'home', changes}] when fallbackRoot, else [];
 *  repos non-empty → repoChanges (undefined while it has not arrived). */
export function reviewRepoChangesFor(repos: readonly RepoInfo[] | undefined, repoChanges: readonly RepoChanges[] | undefined, changes: readonly ChangeDTO[], fallbackRoot: string | undefined): RepoChanges[] | undefined;

export interface RepoChipRow { root: string | null; label: string; checked: boolean; hint?: string }
/** [All repos (checked when resolved===null), …one per reviewRepos: label = repoLabel(repo, reviewRepos),
 *  checked = folderKey match, hint = `${plural(n,'file')}` for n>0 in scope | 'clean' | '…' when repoChanges undefined]. */
export function repoChipRows(reviewRepos: readonly RepoInfo[], repoChanges: readonly RepoChanges[] | undefined, resolved: string | null, scope: ReviewScope): RepoChipRow[];
/** Chip text: null → 'All repos'; a reviewRepos root → repoLabel; any other root → repoBaseName(root). */
export function repoChipLabel(reviewRepos: readonly RepoInfo[], resolved: string | null): string;
/** Display path for titles: RepoChanges.sub ?? root. */
export function repoDisplayPath(r: Pick<RepoChanges, 'root' | 'sub'>): string;
```
The scope filter for hints and for `groupReviewFiles` input: `scope === 'staged'` keeps
`c.staged`, `'unstaged'` keeps `!c.staged`. This matches the scoped working list today. The executor
reads the existing scope filter in `review-view.tsx` `allFiles` (`:488-500`) and reuses that
predicate; it does not write a second one.

## Deviation rule

If a task's assumption turns out wrong, that task **stops**, and fixing the misaligned piece becomes
the work. Examples of a wrong assumption:
- an mf-model or mf-changes export is missing or shaped differently;
- a cited line has moved in a way that changes meaning;
- `ReviewSearchFile.path` turns out to be displayed rather than used as a key;
- `repoChanges` is not reachable from RightPane.

Never route around it with a shim, second copy, special case, widened type, alias field, fallback,
or an override patched in place of its semantic source. An e2e that fails is fixed at the selector
or at the product, never by dropping or loosening an assertion. The report leads with the fix that
keeps the locked decision.

## Decisions Needed

- [normal] **Grouped handoff is a separate export.** `buildGroupedHandoffMarkdown` is new, instead of
  an optional `groups` argument on `buildHandoffMarkdown`. This guarantees the single-repo bytes by
  construction: the old function is untouched and its tests are unedited. The spec's intent (§3.3) is
  unchanged.
- [normal] **Handoff path rule is by location, not tag.** A file inside home gets a path relative to
  home; anything else gets an absolute path. This equals §3.3 for home, nested and attached repos,
  and also covers mf-model's enclosing-repo case (a `home` tag rooted above home), where a tag rule
  would emit paths the agent cannot resolve.
- [normal] **Host root resolver extended to history/refs.** `resolveRequestRepoRoot` also replaces
  mf-model's `requestGitRoot` in `git:history`/`git:refs`. Otherwise a commit opened from a terminal
  link on an out-of-set repo (D11) gets a picker that errors with `unknown repo`, where today it
  lists that repo's history. Validation stays equivalent: the root is a detected repo or the
  session's live-cwd repo, never a raw path.
- [normal] **Navigator kebab title.** It reuses mf-changes' `buildBulkMenuItems` with the new
  optional `BulkScope.perRepoTitle` (`Pick one repo first`) rather than a second menu builder.
- [normal] **Repo leaves with one repo left.** The announcement keeps the §4 copy (`… showing all
  repos`) even when the fallback is the single remaining repo. A second string for a transient
  state was judged not worth it.
- [normal] **No working-tree loading state.** Before `repoChanges` arrives, Review renders today's
  empty state (staleness above). A dedicated loading state would be new behaviour the spec
  attributes to "today".
- [normal] **e2e Nested fixture.** Per mf-changes D13, "Nested" is a repo under a non-repo home, so
  the fixture's home is a plain folder holding two repos. The Gherkin's `rmb Home` label therefore
  can't co-exist with a nested repo in the same home. The e2e asserts the tags `RepoChanges` reports
  rather than hard-coding `Home`.
